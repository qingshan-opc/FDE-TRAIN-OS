## 01 · open

**PPT（屏幕）**
- 眉题：01 OPEN · 挂工具表
- 讲解图：harness-anatomy.svg
- 工具描述 = 货架标签
- Agent 选工具 · 只读标签

**口播**
> 同学们好，我是你们的老师404。这节把你的 Skill 挂上 Agent 的工具表。Agent 选工具的时候读什么？不是说明书全文——是货架上的标签，叫工具描述。名称、何时用、输入要求，写清楚它才知道什么时候该伸手。有同学可能会说：404老师，说明书写了二十页，它全读不就懂了？读不全、读不准、还烧上下文——标签就是给「选型」用的短合同。听见了吗？你写 Skill 花了两天，标签写四句，决定 Agent 会不会误选。来，看屏幕，咱们先拆标签三要素——拆完就挂上去测，对吧。

文稿：`video/scripts/narration/01-open.txt`

## 02 · tool-description

**PPT（屏幕）**
- 眉题：02 TOOL DESC · 三要素
- 讲解图：skill-anatomy.svg
- 何时用 · 不用于 · 输入要求
- 示例：weekly-report

**口播**
> 工具描述三要素，缺一项都可能选错。何时用——需要生成本周运营周报时，输入为 KPI 与异常工单数据。不用于——写通用文章、创意写作、对外发送任何内容。输入要求——JSON 格式，缺数据时本工具会拒绝。有同学可能会问：不用于为啥要写？最反直觉，也最重要——它是护栏，防止周报工具被选去写情诗、发朋友圈。听见了吗？何时用是「招徕」，不用于是「拒收」；只写招徕不写拒收，货架再满也会拿错。来，对照屏幕示例 weekly-report，给你自己的 Skill 起草一版标签，挂之前先念一遍，嘛。

文稿：`video/scripts/narration/02-tool-description.txt`

## 03 · three-tasks

**PPT（屏幕）**
- 眉题：03 TASKS · 闭环实测三任务
- 讲解图：agent-loop.svg
- A 该调 · B 不该调 · C 易选错
- 观察 · 记录 · 判定

**口播**
> 挂上去，测三个任务，别只测 happy path。任务 A 该调：「用本周数据生成周报」——期望选中 weekly-report 并调用。任务 B 不该调：「帮我写一句朋友圈文案」——期望不调工具，直接答。任务 C 易选错：「总结一下这周情况」——模糊指令，观察它选什么、会不会误调。有同学可能会说：C 模糊了它瞎选也正常啊。正常，所以要记录——选错正是今天要抓的。听见了吗？三个任务覆盖「该伸手」「别伸手」「容易伸错手」；测完填表，别凭感觉说「好像对了」。任务 B 过但 C 不过，说明「不用于」写得还不够窄，嘛。

文稿：`video/scripts/narration/03-three-tasks.txt`

## 04 · wrong-pick-map

**PPT（屏幕）**
- 眉题：04 WRONG PICK · 选错图谱
- 讲解图：harness-anatomy.svg
- 任务 · Agent选了什么 · 原因 · 描述怎么改
- 选错怪标签 · 不怪 Agent 笨

**口播**
> 选错了别怪 Agent 笨，怪标签写得宽。改描述，再测，直到行为稳定。今天结束前交一张选错图谱：什么措辞下误选或漏选、因为什么、你怎么改的。有同学可能会问：比十次调对更有用吗？有用——十次调对只说明这次行；选错图谱告诉你边界在哪，下次加新工具也不会撞车。听见了吗？图谱和 agent-tool-map.md 一起进 Git，是团队资产，不是私人笔记。来，每一行选错都要有「描述怎么改」，空着「再观察观察」不算过关——改完必须重测同一条任务，对吧。

文稿：`video/scripts/narration/04-wrong-pick-map.txt`

## 05 · desc-length

**PPT（屏幕）**
- 眉题：05 LENGTH · 描述写多长
- 讲解图：skill-anatomy.svg
- 2–4 句 · 长了稀释 · 短了不够
- 三要素各一句 · 最稳

**口播**
> 描述写多长？两到四句最稳；长了关键信息被稀释，短了护栏不够。有同学可能会说：我把说明书摘要贴进去当描述？不行——Agent 选型阶段只需要「何时用、不用于、输入要求」，各一句就够。weekly-report 示例：三要素各一句，加名称，四条结束。听见了吗？标签不是缩写版说明书，是货架价签——顾客扫一眼就要知道该不该拿。写完后大声读一遍：像不像在招徕不该来的活？像就改「不用于」。这是选型阶段最省事的修法；改完回去重跑任务 B 和 C，嘛。

文稿：`video/scripts/narration/05-desc-length.txt`

## 06 · platform-fallback

**PPT（屏幕）**
- 眉题：06 FALLBACK · 平台与输入
- 讲解图：agent-loop.svg
- 无工具表 → Prompt 手动清单
- 今天输入你给 · 第九天编排串拉数

**口播**
> 两个实操问题一并答。平台没有工具表功能？降级玩法：在 Prompt 里手动提供工具清单加描述，让模型先输出选择再执行——选型逻辑不变，只是载体不同。Agent 调用时输入谁准备？今天你在任务里给 JSON 数据；第九天编排会把「拉数据 → 调 Skill」串起来。有同学可能会问：今天要不要让它自己调接口拉数？先别——先把「选对工具、调对 Skill、产出过验收」闭环跑通。听见了吗？先选型、再执行、再验收；数据从哪来，下一层 workflow 再接。降级玩法也要写清三要素，别偷懒只写工具名，对吧。

文稿：`video/scripts/narration/06-platform-fallback.txt`
