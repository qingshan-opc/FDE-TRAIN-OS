# 第 3 节 · 练习

## 知识确认

1. 为什么全面测试前要先冒烟？
2. 实际结果必须由谁提供？
3. 测试证据怎样与用例对应？

## 本地实操

### P1 · 冒烟测试

> @测试，请只给我冒烟测试步骤。依次检查服务启动、健康接口、前端打开和核心查询。每次只给一个操作和预期结果，等我反馈实际结果与证据后再继续。冒烟失败时停止。

### P2 · 核心主流程

> 冒烟通过。请按 test-plan.md 引导我完成一次查询、一次提交、刷新后复查和一条 PRD 核心业务规则。每次只执行一条用例，并把实际结果追加到测试记录。

### P3 · 接口与错误

> 请依次验证一个成功请求、缺少必填项、目标不存在和服务不可用。每次说明期望状态码与页面提示，等我反馈后再继续。

### P4 · 数据与隐私

> 请引导我检查重启持久化、空数据状态、敏感信息是否出现在前端或日志，以及未授权访问的处理。不要制造危险数据，不要修改代码。

### P5 · 汇总结果

> 请把我反馈的每条实际结果写入 test-run.md，包含用例编号、实际结果、证据路径和通过状态。失败项只记录，不修复。

## 提交验证

- 冒烟测试通过或已提交阻塞问题；
- 每条结果来自真实运行；
- 主流程和错误路径均有证据；
- 重启持久化和隐私已检查；
- 失败项没有被测试岗位修改。
