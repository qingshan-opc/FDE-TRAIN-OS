# 第 3 节 · 练习

## 知识确认

1. API 的六个要素是什么？
2. 主键有什么作用？
3. 页面—接口—表对账能发现哪些问题？

## 本地实操

### P1 · 接口菜单

> @后端，方案已确认。请只列 3—5 个接口，每行写“方法、路径、一句话用途、对应页面操作”。不要展开参数和响应，等我回复“确认接口清单”。

### P2 · API 合同

> 接口清单已确认。请生成 API_Spec.md。每个接口写全方法、路径、用途、请求、成功状态码与 JSON 示例、至少一个错误状态码与触发场景。保存后停止。

### P3 · 数据合同

> 请生成 DB_Schema.md，只设计第一版需要的 2—3 张表。写明字段、类型、主键、非空和必要关系，并说明 SQLite 文件位置。保存后停止。

### P4 · 只对账

> 请逐个接口列出读取或写入的“表名.字段名”。字段无来源、无人使用或命名不一致时标为不通过。只列问题，等我确认修正。

### P5 · 完整修正

> 我确认修正方案。请完整重生成 API_Spec.md 和 DB_Schema.md。最后列出页面操作 → 接口 → 数据表的完整链路。

## 提交验证

- `API_Spec.md` 的接口六要素齐全；
- `DB_Schema.md` 每张表有主键；
- 接口与页面操作对应；
- 字段可以追溯；
- 修正后两份合同都是完整最新版。
