# Prompt 工程速查卡（D2 / D5 实战手边卡）

## 最小公式（Day 2 生成页面用）

```
角色 + 背景 + 任务 + 约束
```

- 角色：你是前端工程师（限定它的知识视角）
- 背景：部门 AI 驾驶舱 Week1（让它知道上下文）
- 任务：生成 index.html，五区块（唯一、具体、可数）
- 约束：列字段 / 行数 / 模拟数据值 / 单文件 / 中文标题（逐条可验收）

**检验标准：每条约束都能对应产物上一个可检查的点。**

## 烂 vs 好

| 烂（无法验收） | 好（可对照 Rubric） |
|---------------|--------------------|
| 帮我做个驾驶舱 | 生成单页 index.html：标题「运营驾驶舱」，3 张指标卡（订单量 128 / 转化率 3.2% / 异常工单 7），明细表 4 列 ≥3 行且 1 行异常高亮，单文件可直接打开 |
| 弄好看一点 | 窄屏下指标卡纵向排列；异常行用背景色区分 |
| 顺便加个图表 | 趋势图区用纯 CSS 柱状图，7 个模拟数据点 |

## 迭代纪律（V0.1–V0.4 通用）

1. 不满意 → 先诊断：少了什么 / 错了什么；
2. 定位到 Prompt 里对应的约束（缺失 or 含糊）；
3. 改约束 → 重新生成 → 记一行迭代日志；
4. **不手改产物**——Prompt 才是源码。

## 结构化进阶（Day 5 摘要接口用）

```
角色：你是运营分析助手。
输入：<贴入真实指标 JSON>
任务：写 3 条本月关注 + 1 条行动建议。
约束：
- 每条必须引用输入中的具体数字，禁止编造输入没有的字段；
- 每条 ≤40 字，语气对部门负责人；
- 输出 JSON：{"focus": [...], "action": "..."}；
- 输入为空数组时输出 {"focus": [], "action": "今日暂无数据"}。
```

## 摘要质量三问（验收时自问）

1. 每条结论能指回数据里的哪个数字？（有依据）
2. 建议是不是一个「人明天就能做」的动作？（可执行）
3. 有没有出现输入里根本不存在的字段？（无编造）
