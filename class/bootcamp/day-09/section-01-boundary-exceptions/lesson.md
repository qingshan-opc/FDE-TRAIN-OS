# 第 1 节 · 概念：边界与异常——从能跑到可依赖（15′ · 概念）

> 🎬 视频位（现阶段：口播稿 + 讲解图）
> 「能跑」和「可依赖」之间，隔着一份边界声明和一张异常分类表。

## 教学目标

- 理解边界声明：Skill 明确说「什么输入我不接、接不了时我怎么表现」；
- 背下异常四分类：输入错 / 环境错 / 能力限 / 目标歧——各自处置方式不同；
- 建立「按声明的方式失败」的工程观：失败不可怕，失控地失败才可怕。

### 异常四分类（处置各不相同）

| 分类 | 例子 | Skill 该做的 |
|------|------|-------------|
| 输入错 | 数据为空、字段缺失、格式不对 | 拒绝执行 + 明说缺什么（不编数据补洞） |
| 环境错 | 接口超时、文件打不开 | 重试一次 → 报「环境问题」并停止（不假装成功） |
| 能力限 | 要求超出说明书范围（「顺便翻译成英文」） | 声明超出边界 + 询问是否继续（不擅自扩展） |
| 目标歧 | 指令有两种以上合理解法 | 列出理解选项 + 请求确认（不闷头选一个） |

> 共同原则：**停下来、说清楚、等人来**——对照 Day 5 的「数据不足就说不足」，是同一道防线的工程化。

### 边界声明（加在说明书里）

```markdown
## 边界与异常
- 不接受：输入数据为空 / 缺少 X 字段 / 时间范围跨月
- 输入不足时：停止执行，列出所缺字段，请求补充
- 超范围请求：声明「超出本 Skill 边界」，询问后再继续
- 指令歧义时：列出 ≤3 种理解，请求确认
```

## 🎬 口播稿（约 6 段 · 待审）

> 同学们，第八天第一节。昨天你的 Skill 在乖数据上二连过，恭喜，它能跑了。但能跑和可依赖之间，隔着一份边界声明和一张异常分类表。真实世界的输入不乖：数据是空的、字段缺了、接口超时了，对吧。
> 三个场景：老板要周报，但 KPI 接口返回空数组；异常工单缺了逾期天数字段；老板说把两周数据合并一下——到底是哪两周？这时候你的 Skill 会干嘛？如果答案是不知道，那它只是能跑，还不可依赖，嘛。
> 异常分四类，处置各不同。输入错——数据为空、字段缺失、格式不对：拒绝执行，明说缺什么，不编数据补洞。环境错——接口超时、文件打不开：重试一次，报环境问题并停止，不假装成功。能力限——超出说明书范围：声明超边界，询问后再动。目标歧——指令有两种以上合理解法：列出理解选项，请求确认，对吧。
> 共同原则一句话：停下来、说清楚、等人来。对照你们第五天的数据不足就说不足，是同一道防线的工程化。从今天起，你的 Skill 失败的每一种方式，都是你提前设计好的——这叫按声明的方式失败。失败不可怕，失控地失败才可怕，对吧。
> 边界声明加在说明书里：不接受什么输入；输入不足时停止执行、列出所缺字段；超范围请求声明边界、询问后再继续；指令歧义时列出不超过三种理解、请求确认。让 Skill 拒绝执行，不是显得弱——会拒绝的才可依赖，瞎编的周报比没有周报危害大十倍，嘛。
> 收个尾：边界声明是 Skill 从能跑到可依赖的门票。下一节上刑场——故意喂坏输入，看你的 Skill 怎么死。死法符合声明，才算过关，咱们下午再挂 Agent，对吧。


## 常见懵点

- 「让 Skill 拒绝执行，不是显得它很弱？」→ 相反：会拒绝的才可依赖——瞎编的周报比没有周报危害大十倍；
- 「四类都要写吗？」→ 都写，但可以各一句话；第 2 节的注入测试会逐类验证；
- 「这和三态、降级是什么关系？」→ 同一思想的第三次生长：前端三态（D2-3）、LLM 降级（D5）、Skill 边界（D8）——**体面失败学**。
