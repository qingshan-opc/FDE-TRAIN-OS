# 第 2 节 · 把 Day1 四份文件交给前端

## 本节目标

- 学会切换 `@前端` 并完成正式岗位交接；
- 理解四份输入文件分别解决什么问题；
- 用“五句复述”检查前端是否真的理解；
- 在回复“确认开发”前先拿到前端实施清单。

## 四份输入，不是一份截图

| 文件 | 回答的问题 |
|---|---|
| `PRD.md` | 做什么、给谁用、怎样算合格 |
| `design-spec.md` | 颜色、字号、间距和组件状态怎样统一 |
| `ui-flow.md` | 用户从哪里开始、点击后去哪里 |
| `ui-prototype.html` | 已确认的页面和交互长什么样 |

任何一份缺失，前端都不应该用猜测补齐。它应停止并告诉学员回到产品经理或 UI 补文件。

## 五句复述

开工前只让前端回答五件事：

1. 谁在使用；
2. 第一版有哪些页面或区块；
3. 用户最重要的操作是什么；
4. 必须处理哪些页面状态；
5. 哪些标准决定前端通过。

复述不是浪费时间。它是在代码大量生成前，用一分钟发现理解偏差。

## 前端实施清单

第一次开发固定采用 `frontend/index.html`、`frontend/styles.css`、`frontend/app.js`。清单还要写明页面区块、交互、演示数据位置、四种状态和暂不接入的真实接口。学员确认后才回复“确认开发”。

## 口播稿

同学们好，我是你们的老师404。现在我们开始第二次正式岗位交接。昨天 UI 已经完成三份交付物，加上产品经理的 PRD，今天一共四份文件交给前端。

你先不要说“照这个做个页面”。请切换到 @前端，让它检查四份文件是否存在。PRD 告诉它做什么，设计规范告诉它长什么样，UI 流程告诉它怎么操作，原型让它看到已经确认的结果。缺任何一份，都先回上游补齐。

文件齐全后，让前端只用五句话复述用户、页面、核心操作、数据状态和验收标准。你要对照原文件检查。理解不一致时，只纠正理解，不让它偷偷修改上游文件。

最后让前端给出实施清单。今天为了让小白先跑通流程，我们使用三个文件，不上框架，不装依赖。页面结构、样式、行为分开，双击就能打开。看清清单后，你本人再回复“确认开发”。这一步就是新的人工确认闸。同学们，本节先到这里。
