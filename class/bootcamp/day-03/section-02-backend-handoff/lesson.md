# 第 2 节 · 把前端成果交给后端

## 本节目标

- 切换 `@后端` 并检查输入文件；
- 让后端先复述、再逐题澄清；
- 看懂最小后端方案；
- 亲自把住“确认后端方案”的闸门。

## 后端必须收到什么

| 输入 | 后端从中读取什么 |
|---|---|
| `PRD.md` | 用户、范围、业务规则和验收标准 |
| `frontend-api-needs.md` | 页面要展示和提交哪些字段 |
| `frontend/index.html`、`frontend/app.js` | 请求从哪个动作发出、结果显示在哪里 |
| `frontend-acceptance.md` | 前端当前已经通过哪些检查 |

文件缺失时不要猜，让后端指出缺口并回到责任岗位。

## 先复述，再逐题问

后端先复述核心规则、展示数据、提交数据和四种状态。之后一次只问一个问题：数据从哪里来、核心对象是什么、谁可以访问、有哪些隐私限制、本机是否有 Python 3。每问完一题都等待学员回答。

## 人工确认闸

后端给出 3—5 个接口、2—3 张表、运行方式、健康检查、错误处理和不做项。学员检查后才回复“确认后端方案”。在此之前不能生成正式代码。

## 口播稿

同学们好，我是你们的老师404。现在把 Day2 的成果交给后端。不要只发一句“帮我做后端”，而要让它读取 PRD、前端数据需求、真实前端文件和验收记录。文件齐全后先复述，发现不一致就停下纠正。随后数据来源、核心对象、权限、隐私和 Python 环境一次只问一个，不要让一大串问题把小白淹没。最后看最小方案，确认接口、数据表和运行方式都属于第一版，再由你本人回复“确认后端方案”。同学们，本节先到这里。
