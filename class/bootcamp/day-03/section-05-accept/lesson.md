# 第 5 节 · 前端切真接口：主持第一次完整联调（35′ · 实操+验收）

> 联调不是两个 Agent 互相说完成，而是学员按契约分段验证：接口有数据、前端请求正确、页面显示正确。

## 教学目标

- 学员能用自己的项目解释本节概念，而不是背技术名词；
- 学员能向指定岗位下达一句清楚的任务，并说出验收口径；
- 学员只根据真实文件和运行证据批准交付。

## 讲授要点

- 业务 Mock 必须移除或隔离。
- 完整走提交、SQLite、列表、详情和看板更新。
- 遇到问题先查契约，再判断由前端还是后端修复。

**本节岗位**：@前端工程师 Agent + 学员亲测

**本节产出**：真实数据全链路 V0.8 + 冒烟记录

**本周共同边界**：本周只做桌面 Web 单应用、本地数据库和可验证的数据链路；不做手机端、登录、复杂权限、Docker、生产级高可用，也不接真实 AI。

## 🎬 口播稿（短讲版）

这一节我们只解决一个问题：联调不是两个 Agent 互相说完成，而是学员按契约分段验证：接口有数据、前端请求正确、页面显示正确。

请记住三件事。

「业务 Mock 必须移除或隔离。」

「完整走提交、SQLite、列表、详情和看板更新。」

接下来你们要做的不是听懂就算，而是完成这项真实任务：指挥前端切换真实 API，学员亲手走完整业务流程并记录证据。

AI 可以生成文件、代码和建议，但批准权不能交出去。你要看实际文件、亲手验证，再决定通过还是返工。

同学们，本节先到这里。

## 常见懵点（导师备用）

- “能不能让一个 Agent 一次做完？”→ 可以很快看到结果，但会失去岗位交接、状态变化和验收过程，这正是本课要学的部分。
- “我不懂代码怎么验收？”→ 先按页面、文件、请求响应和数据变化验收；让工程师解释原因，不要求学员先会写代码。
- “Agent 说完成了是不是就算完成？”→ 不算。只有实际文件存在、验证真实执行且学员明确批准，状态才从 REVIEW 进入 APPROVED。
