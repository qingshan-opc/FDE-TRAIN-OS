# 第 3 节 · 数据库设计：表、关系与索引（20′ · 概念）

> 一句话：数据库就是后厨的仓库——表是货架，主键是每件货的标签，索引是仓库门口的检索目录。

## 教学目标

- 用 Excel 类比说清表、行、列：表 = 一张 Sheet，行 = 一条记录，列 = 字段；
- 理解主键（每行的身份证）为什么必须有、为什么不能复用；
- 用「一个部门很多员工」说清一对多关系与外键（指向另一张表主键的列）；
- 理解索引 = 书的目录：查得快但写得慢，不是越多越好；
- 现场为「部门周报助手」搭出 users / reports / metrics 三张表的草稿。

## 讲授要点

### 表、行、列：给程序用的 Excel

| Excel | 数据库 | 周报助手里的例子 |
|-------|--------|------------------|
| 一个 Sheet | 表（table） | `users` 表 |
| 一行 | 一条记录（row） | 张三，平台部，工号 1024 |
| 一列 | 字段（column） | 姓名 / 部门 / 工号 |

差别在：Excel 是给人看的，数据库是给程序按规矩并发读写的。

### 主键：每行的身份证

主键（Primary Key）是每行记录的唯一标识——人话：身份证。
两个同事可以同名，但工号不能同号。身份证三条规矩：唯一、不为空、发了不回收。

### 关系：一对多与外键

一个部门有很多员工，一个员工属于一个部门——这叫「一对多」。
落法：在「多」的那侧加一列指向「一」的主键，这列叫**外键**（人话：行李牌，写着这件货属于哪个货架）。
`reports` 表里放一列 `user_id` 指向 `users` 的主键——谁交的周报，一查便知。

### 索引：书的目录

索引（Index）是数据库为某一列预先排好的「目录」。
没有索引，查「张三的周报」= 全书逐页翻（全表扫描）；有索引 = 先翻目录直达页码。
代价：每插入一条新数据，目录也要更新——**查得快，写得慢**。所以索引只加在「经常被拿来查」的列上，不是越多越好。

### 现场搭三张表（周报助手）

- `users`：id（主键）、name、dept——谁；
- `reports`：id（主键）、user_id（外键→users.id）、week、content、submitted_at——交了什么；索引建议：`user_id + week`（最常被按「某人某周」查）；
- `metrics`：id（主键）、dept、week、submit_rate——汇总指标，驾驶舱卡片直接读它，不用每次现算。

## 🎬 口播稿（约 3 分钟）

【开场抛问】同学们，100 个同事的周报交上来——你打算怎么存？一个巨大的 Excel？今天告诉你，数据库其实你也早就认识。

【类比】一张表，就是一张 Excel 的 Sheet；一行，是一条记录；一列，是一个字段。数据库就是「给程序用的 Excel」——人看的那套你会，程序看的只是更讲规矩。

【主键】第一条规矩：每行必须有一张「身份证」——行话叫「主键」。两个同事可以都叫张伟，但工号绝不能撞号。身份证唯一、不发空、发出去不回收。

【关系】第二条：表和表怎么连？一个部门有很多员工——这叫「一对多」。做法是在多的那侧挂一张「行李牌」，写着它属于哪个货架——行话叫「外键」。周报表里记一列「谁的 id」，谁交的一查便知。

【索引】第三条：索引是「书的目录」。有目录，查得快；但每进一本新书，目录也得跟着改——所以「查得快，写得慢」，不是越多越好，只加在天天被翻的那几页。

【落回项目】你的周报助手，三张表就够开张：users 管人、reports 管周报、metrics 管汇总数字。

【带走的话】记住——设计数据库，就是给数据分货架、发身份证、编目录。

## 常见懵点（导师备用）

- 「为什么不能用姓名当主键？」→ 姓名会重复、会改；身份证式的主键选「人造编号」（自增 id）最稳；
- 「外键是不是另一张表复制过来的数据？」→ 不是复制，是「指针」——只存对方的身份证号，数据仍在对方表里；
- 「索引这么好用，每列都加上？」→ 每加一个索引，写入都多付一笔维护费；读多写少的列才值得加。
