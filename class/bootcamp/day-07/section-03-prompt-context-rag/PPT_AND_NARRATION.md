## 02 · prompt-bad

**PPT（屏幕）**
- 眉题：02 BAD · 坏 Prompt 长啥样
- 例子：「帮我写个摘要」
- 缺：角色 · 材料 · 边界 · 格式

**口播**
> 先看坏 Prompt。最常见一句：「帮我写个摘要。」缺啥？缺角色——你是谁；缺材料——依据什么；缺任务边界——多长、给谁看；缺约束——不许编什么；缺格式——段落还是三条要点。模型只好猜：写成日报？写成朋友圈？写八百字还是八十字？有同学可能会说：它不是挺聪明的吗，应该懂我。不懂。它懂的是「接下一个像真的词」，不是读心。听见了吗？坏 Prompt 的本质是：把猜测空间留给模型——猜测空间越大，幻觉和返工越多，钱和时间都是你的。来，把你昨天写过的一句提示词拿出来，对照缺了哪几项；下一页咱们看好 Prompt 长什么样，对吧。

文稿：`video/scripts/narration/02-prompt-bad.txt`

## 03 · prompt-good

**PPT（屏幕）**
- 眉题：03 好 Prompt · 五要素
- 讲解图：prompt-four-elements.svg
- 角色 · 背景 · 任务 · 约束 · 格式
- 像写接口契约

**口播**
> 好 Prompt 像任务说明书，五要素：角色、背景、任务、约束、输出格式。例：你是部门助理；依据下面这段 JSON；写二百字以内周报摘要；不许编造没出现的人名；用三条要点输出。第一天 PM Agent 提示词就是这类标准件——能改、能验、能迭代。有同学可能会问：是不是越长越好？不是。长而空照样烧 Token；长而清，才值钱。像写接口契约：对方看完不用回来问第二遍。来，对照屏幕五要素，用你昨天的摘要任务在心里套一遍。五要素写全，不等于写长；写清「依据什么、输出长什么样」就够硬，嘛。

## 04 · context

**PPT（屏幕）**
- 眉题：04 CONTEXT · 往窗口装什么
- 讲解图：context-assembly.svg
- 系统提示 + 资料块 + 用户话 + 工具说明
- 给少瞎编 · 给多迷失

**口播**
> 第二个词，Context Engineering。别被英文吓到——就是决定这次调用往窗口里装啥。常见配方：系统 Prompt，加上检索到的文档块，加上用户最新消息，必要再加工具说明。给少了会怎样？模型靠训练记忆瞎编，就是幻觉。给多了会怎样？「迷失在中间」，你写在开头的硬约束被淹没。驾驶舱真问题：该放本周 JSON 和风格说明，还是整份表结构？该放最新用户请求，还是三天闲聊全塞？有同学说「全塞最保险」——不对，桌面就那么大，堆满反而找不到关键那张纸。装填是手艺，不是玄学。记住口诀：少了会编，多了会淹，刚刚好才叫装填。装填之前先列清单：系统规则、真材料、用户原话——三样缺一就补，多了就删，呢。

文稿：`video/scripts/narration/04-context.txt`

## 05 · rag-story

**PPT（屏幕）**
- 眉题：05 RAG · 先当开卷考试
- 闭卷硬背 → 容易编
- 开卷：先翻到相关页再答
- 第五天摘要 ≈ 简化 RAG 思想

**口播**
> 第三个，RAG，检索增强生成。先别背缩写，听故事：闭卷考试靠记忆，容易瞎编；开卷考试先翻到相关页再答，靠谱得多。RAG 就是给模型「开卷」——先从资料库捞相关片段，再让它基于片段生成。企业里的「库」可以是向量库、关键词搜索、Wiki，甚至你们第一周接上的业务数据库。「基于本周数据生成摘要」就是简化版 RAG：先查出真数据，再喂给模型写。有同学可能会问：有了 RAG 还会幻觉吗？会减弱，不会归零——检索错了、拼错了，它仍可能添油加醋，所以还要验收。听见了吗？开卷不是抄书：材料找错页，答案照样歪。下一页把 RAG 拆成五步，跟着数就行，嘛。

文稿：`video/scripts/narration/05-rag-story.txt`

## 06 · rag-steps

**PPT（屏幕）**
- 眉题：06 STEPS · RAG 五步
- 流程：切块 → 嵌入 → 入库 → 检索 → 拼 Prompt 生成
- 检索质量决定上限 · 先想清再选型

**口播**
> RAG 流程五步，跟着屏幕数：一，文档切块；二，嵌成向量；三，存进库；四，用户一问，检索最相关几段；五，拼进 Prompt，再生成。你不必这节就动手搭向量库，但要能讲清「为啥这比闭卷稳」。有同学可能会说：那我是不是该上最贵的向量数据库？先把「查什么、怎么判相关、拼进 Prompt 后还验不验收」想清楚，比品牌重要。RAG 是药，不是神——检索质量决定上限。五步里最容易翻车的是「检索」和「拼接」——这两步决定模型看见的世界，对吧。

文稿：`video/scripts/narration/06-rag-steps.txt`

## 07 · finetune

**PPT（屏幕）**
- 眉题：07 SELECT · 微调还是 Prompt
- 双列：改权重贵慢 · 改话术快便宜
- 默认三板斧：Prompt + RAG + Eval

**口播**
> 最后说选型：Fine-tuning 跟 Prompting。微调改模型权重，像给员工做长期培训——贵、慢、影响持久；Prompting 改你这次给它的话，像每次派工单——快、便宜、随时能改。FDE 默认：九成场景先用 Prompt 加 RAG 加 Eval 三板斧，微调写进「以后再说」。只有需要非常固定的风格或格式、Prompt 怎么写都不稳，才考虑微调。有同学一上来就说「我们要训自己的模型」——先把 Prompt 方案验收过了再说。听见了吗？先会用，再谈训。微调像装修承重墙，Prompt 像换家具——多数时候先换家具，嘛。

文稿：`video/scripts/narration/07-finetune.txt`
