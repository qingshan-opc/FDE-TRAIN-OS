# 第 3 节 · 解剖 PM Agent 提示词：四要素 + 两接口（20′ · 概念）

> 写提示词之前，先得会读——这节把 PM 提示词像 X 光片一样读一遍。

## 教学目标

- 学员能在 PM_Agent_Prompt.md 原文中指认出四要素（角色定位/核心任务/关键输入/关键输出）和两接口（Input Sources / Output Targets）的位置；
- 学员能说明每个要素对 AI 行为的具体影响（不是背名字，是知道改了它会怎样）；
- 学员注意到「首先通过提问深入理解」这一流程设计，为下节实战做预期管理。

## 讲授要点

**为什么先学读（3′）**

- 「会读提示词」比「会写提示词」更基础——像学开车先看懂仪表盘；
- 读懂这份，本周后面四份角色提示词结构相同，全部免检；以后遇到任何新提示词，你都有解剖刀。

**逐段解剖（12′，对照 PM_Agent_Prompt.md 原文）**

| 要素 | 原文位置 | 人话 | 改了它会怎样 |
|------|---------|------|-------------|
| 角色定位 | 「你是一位拥有10年以上经验的资深产品经理专家……」 | 它是谁、多少年功力 | 功力描述决定回答的专业水位——改成「实习生」产出立刻变水 |
| 核心任务 | 「将用户的初期产品构想……转化为专业、完整且可执行的产品规划方案」 | 它的职责边界 | 边界写窄会缺位，写宽会越界（比如替你做了架构师的活） |
| 关键输入 | 「导演指令：用户在聊天界面直接输入的产品初始想法」 | 它从哪读需求 | 这是输入口——你的点子从这里进 |
| 关键输出 | 四份文档：PRD / Roadmap / 用户故事地图 / 指标框架，含保存路径 | 它交付什么、存到哪 | 这是输出口——下游角色从这里接 |
| 协作说明 | 「你的产出将由协调者分发给设计师、后端工程师……」 | 它和谁交接 | 提示词不是孤立的，它在流水线上有上下游 |

合起来就是工具包 README 里说的**四要素 + 两接口**：四要素定能力，两接口（Input Sources / Output Targets）定协作。

**一个藏起来的关键设计（5′）**

- 工作流程第 1 条：「首先通过提问深入理解用户的产品创意」——它不会直接开写，会先反问你；
- 这是好提示词的标志：先澄清、再动笔。烂提示词才会拿到点子就狂写三千字；
- PRD 模板里明确要求包含**目标平台列表**和**验收标准**——这不是巧合，正是第 2 节最小骨架的工业化版本；今天过闸的三要素就从这里来。

## 🎬 口播稿（约 2.5 分钟）

【开场】同学们，工具包里那份 PM 提示词，你下载了——但你真「读」过吗？这节不动手，就把它像 X 光片一样读一遍。

【为什么先学读】写提示词之前，先得会读。就像学开车先看懂仪表盘——「会读」比「会写」更基础。读懂别人的，才写得出自己的。

【四要素】整份提示词摊开，其实是四块。

「角色定位」——它是谁：十年经验的产品经理。这句决定回答的专业水位。

「核心任务」——它干什么：把模糊想法变成可执行的文档。这句是职责边界。

「关键输入」——它从哪读需求：你直接输入的点子。「关键输出」——它交付什么：PRD、路线图，存到哪都写明了。

【两接口】最后看「协作说明」——这是两个接口：输入口接着你，输出口接着下游的设计师和工程师。提示词不孤立，它在流水线上有上下游。

【藏起来的细节】还有个关键设计：它「首先通过提问深入理解」——不直接开写，先反问你。这是好提示词的标志，下节你会亲身体会。

【带走的话】提示词读法就一句：四要素定能力，两接口定协作。

## 常见懵点（导师备用）

- 「这跟我直接说『你现在是产品经理』有什么区别？」→ 一句话只给了角色定位，缺了任务边界、输入输出口径和文档结构约束——AI 会自由发挥，产出不可验收；
- 「四要素记不住怎么办？」→ 不用背名字，记住问题：它是谁？干什么？从哪读？交什么、交给谁？——能答这五个问题就是会读；
- 「为什么输出文档结构要规定得这么细？」→ 结构就是验收的抓手：下游（和你）可以逐项检查缺不缺，自由格式的文档没法机器校验。
