# 第 2 节 · 人工确认与日志（15′ · 概念）

> 🎬 视频位（现阶段：口播稿 + 讲解图）
> 闸不是装个样子。今天讲清楚：确认点怎么设计才不是「点确定大赛」，日志怎么记才查得了案。

## 教学目标

- 掌握确认闸三问：看什么、谁来看、多久看一次；
- 理解「信任分级」：连续通过攒额度，抽看比例随信任上调（D7 信任经济学的兑现）;
- 掌握执行日志三要素：时间、动作、结果——可回放、可追责。

## 讲授要点（15′）

| 时段 | 内容 |
|------|------|
| 0–5′ | 破题：确认点的失败模式——「点确定大赛」（看都不看就批） |
| 5–10′ | 确认闸三问 + 信任分级 |
| 10–15′ | 执行日志三要素 + 事故回放案例 |

### 确认闸三问（设计时必答）

```
① 看什么？→ 确认界面必须给「决策所需的最低信息」：
   不是日志原文，是草稿 + 关键数字 + 风险标红
② 谁来看？→ 有责的那个人（本课=你；真实团队=流程 owner）
③ 多久看一次？→ 信任分级：
   新上线：每次都看 → 连续 10 次过：抽看 1/3 → 稳定期：抽看 + 定期审计
```

### 执行日志三要素（每步一条）

```
2026-07-24 17:02  Skill A 拉数据      ✓ 42 条，3.2s
2026-07-24 17:02  Skill B 生成周报    ✓ weekly-0724.md
2026-07-24 17:03  ◇ 人工确认          ⏸ 等待张三审批
2026-07-24 17:15  ◇ 人工确认          ✓ 张三批准（第 3 段数字已核）
2026-07-24 17:15  Skill C 发送        ✓ 已发部门群
```

为什么值得记：出事故时你要能回答三个问题——**什么时候、谁干的、干成了什么**。日志是唯一的案底。

### 反模式（确认闸形同虚设的三种死法）

- 信息不足：确认界面只有「发送吗？」没有草稿——逼人盲批；
- 频率麻木：一天弹 20 次确认，第 21 次一定盲批——信任分级就是治这个；
- 无痕可追：批了没记录，出事互相甩锅。

## 🎬 口播稿（约 5 段 · 待审）

> 同学们，确认闸最大的敌人不是 AI，是点确定大赛——弹得多了，人看都不看就批。所以闸不能装样子，得按工程设计来做。今天咱们把确认点怎么设计、日志怎么记，一次讲透，对吧。
> 确认闸设计时必答三问。看什么？给决策所需的最低信息——草稿加关键数字加风险标红，不是一坨原始日志。谁来看？有责的那个人，训练营里就是你自己。多久看一次？这个咱们下一节讲信任分级。
> 信任分级呢，新上线每次都看；连续十次通过，改成抽看三分之一；稳定期抽看加定期审计。这就是第七天攒的信任额度兑现的地方——不是偷懒，是风险管理。弹窗太多人会麻木，分级就是治这个，对吧。
> 再说执行日志，每步一条：时间、动作、结果。出事故时它能回答三个问题——什么时候、谁干的、干成了什么。没有日志的团队，出事只能靠回忆和甩锅，咱们可不走那条路，对吧。
> 反模式也记一下：信息不足逼人盲批、一天弹二十次麻木、批了没记录互相甩锅。避开这三条，你的闸才拦得住。同学们带走一句——确认点加日志，等于信任的工程设计，这个得记牢，对吧。


## 常见懵点

- 「每步都确认，AI 还有什么意义？」→ 只有「不可撤回」步骤前有闸；可撤回的自动连跑——比例通常是 5 步 1 闸；
- 「抽看不怕漏掉错的吗？」→ 怕，所以抽看配「定期审计 + 异常告警」；信任分级是风险管理不是偷懒；
- 「日志记在哪？」→ 今天：Markdown 文件进 runs/；真实系统：数据库/日志平台——格式思想不变。
