# 第 3 节 · 按计划执行并留下证据

## 本节目标

- 先执行冒烟测试，再进入全面测试；
- 由学员亲手提供实际结果；
- 验证页面、接口、数据、错误和隐私；
- 把证据按用例编号保存。

## 为什么先冒烟

冒烟测试先看服务能否启动、健康检查是否成功、页面能否打开和核心查询能否执行。如果这里失败，继续跑几十条用例没有价值，应立即提交阻塞问题。

## 每次只执行一条

测试智能体给出一条操作和预期，学员亲手执行，再粘贴实际结果。截图、响应和日志统一保存在 `test-evidence/用例编号/`。智能体不能自己编造“实际通过”。

## 执行范围

1. 查询、提交和刷新主流程；
2. 一条关键业务规则；
3. 成功请求、缺少必填项、目标不存在和服务不可用；
4. 重启持久化、空数据状态和敏感信息检查。

## 口播稿

同学们好，我是你们的老师404。计划确认后才开始执行。第一组先做冒烟测试，检查服务、健康接口、页面和核心查询。通过以后再测试查询、提交、刷新、错误和数据持久化。每次只做一条，智能体先说操作与预期，你亲手运行并反馈实际结果。截图、请求内容和日志按用例编号保存。失败项只记录，不在测试岗位偷偷修改。同学们，本节先到这里。
