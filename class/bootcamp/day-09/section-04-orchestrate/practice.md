# 第 4 节 · 练习：流水线施工与两路径实测（随堂 30′）

## 任务 A · 跑通流水线（5–25′）

把 resources.md 里的编排指令模板改成你自己的流程（A/B/C 换成你第 3 节的三件 Skill），发给 Agent，观察：

| 检查点 | 期望 | 实际 ✓/✗ |
|--------|------|----------|
| A 跑完后 B 自动开始 | 无需你再发指令 | |
| B 产出确认界面 | 草稿 + 关键数字 + 风险标红，三样齐 | |
| 到闸自动停 | 你不说话，它不动 | |
| 日志在追加 | runs/ 下每步一行 | |

任何一项 ✗：先修 Skill（守卫/边界），再修编排指令，把修复原因记进迭代日志。

## 任务 B · 闸口两路径实测（25–33′）

**路径 1 · 批准**：确认界面出来后，回复「发」。观察 C 执行、日志记「批准 + 执行结果」。

**路径 2 · 驳回**：再跑一次流水线，这次回复「驳回：〈编一个具体理由，如第 2 段数字不对〉」。观察：

| 检查点 | 期望 | 实际 ✓/✗ |
|--------|------|----------|
| 流水线打回 B | B 重做草稿，版本号 +1 | |
| 驳回留痕 | 日志记「驳回 + 理由 + 时间」 | |
| 重出确认界面 | 新草稿再次等你批 | |
| 二次批准后放行 | C 执行的是 v2 草稿 | |

## 任务 C · 日志回放自查（33–35′）

合上所有对话，只打开今天的 runs/ 日志，口头复述（或写下来）：

1. 今天流水线跑了几次？
2. 每次各步结果是什么？
3. 哪次被驳回了、理由是什么、后来怎么过的？

三问都能答上来 → 日志合格；答不上来 → 缺哪要素补哪要素，再跑一次验证。

## 完成标志

- 两路径实测表全 ✓；
- runs/ 日志可回放（三问答全）；
- 迭代日志记下今天修过的每一处。
