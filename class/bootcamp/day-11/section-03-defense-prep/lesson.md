# 第 3 节 · 答辩准备（15′ · 实战）

> 🎬 视频位（现阶段：口播稿）
> 8 分钟答辩 = 作品 3′ + 架构 3′ + 迭代故事 2′。好答辩不是讲得多，是砍得狠。

## 教学目标

- 按「3+3+2」结构产出答辩提纲一页纸；
- 作品演示掐表彩排：30 秒演示路径走 3 遍，砍到 3 分钟以内；
- 迭代故事选定：一个「修了三次才修对」的 bug，讲出你的工程判断力。

## 「3+3+2」结构

```
第一段 · 作品演示（3′）：别讲，演。
  驾驶舱全貌 → 唤起 Agent → 流水线跑一步 → 闸上驳回一次 → 批准放行
  原则：观众记住一个「它真的活着」的瞬间，胜过十句功能罗列
第二段 · 架构讲解（3′）：指着全景图讲。
  四层架构 + 三 Skill 编排 + 闸在哪、为什么在那
  弹药：第 2 节十条证据的「一句话说明」
第三段 · 迭代故事（2′）：讲一个 bug。
  现象 → 我怎么定位 → 修错了什么 → 最终怎么修对 → 我学到什么
  原则：讲好一个失败，比讲好十个成功更像工程师
```

## 流程安排（15′）

| 时段 | 内容 |
|------|------|
| 0–3′ | 结构讲解 + 提纲模板 |
| 3–10′ | 写提纲一页纸：三段各列要点 + 每段主打证据 |
| 10–15′ | 作品段彩排：掐表走演示路径，超时就砍 |

## 🎬 口播稿（约 5 段 · 待审）

> 同学们，答辩八分钟，结构 3+3+2。作品三分钟、架构三分钟、迭代故事两分钟。好答辩不是讲得多，是砍得狠——没讲到的放互评问答里说。现在就开始写提纲，别等到上台才想结构，对吧。
> 第一段作品演示，别讲，演。驾驶舱全貌、唤起 Agent、流水线跑一步、闸上驳回一次、再批准放行——让观众记住一个它真的活着的瞬间，胜过十句功能罗列。掐表走三遍，超时就砍，砍到三分钟以内，对吧。
> 第二段架构，指着全景图讲四层、三 Skill 编排、闸在哪、为什么在那。弹药是第二节写好的十条一句话。第三段迭代故事，讲一个修了三次才修对的 bug——现象、定位、修错、修对、学到什么。讲好一个失败，比十个成功更像工程师，对吧。
> 现在写提纲一页纸，三段各列要点和主打证据。提纲只写关键词，别写逐字稿；三段开头第一句话背下来，其余靠证据现场说。紧张忘词？第一句接第二句，证据在手就不慌，咱们靠材料不靠背稿，对吧。
> 演示时系统挂了怎么办？预案准备好：一张昨日成功运行的日志截图兜底。挂了就指着日志讲，处理事故的方式也计分——慌了才扣分，不慌就是第九条证据。带走一句，咱们下一节真上台，对吧。


## 常见懵点

- 「8 分钟讲不完我所有东西怎么办？」→ 答辩考的就是取舍；没讲到的放互评问答里说；
- 「演示时系统挂了怎么办？」→ 预案：准备一张「昨日成功运行」的日志截图兜底——挂了就指着日志讲，这本身就是证据 #9；
- 「紧张忘词？」→ 提纲只写关键词不写逐字稿；三段开头第一句话背下来，其余靠证据现场说。
