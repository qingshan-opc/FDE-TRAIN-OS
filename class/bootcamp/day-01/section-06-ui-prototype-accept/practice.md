# 第 6 节 · 练习

## 知识确认（3′）

1. UI 为什么必须先复述 PRD，不能直接生成页面？
2. UI 原型至少要考虑哪三种非理想状态？
3. 为什么原型完成后要回到产品经理，而不是让 UI 自己验收？

## 实操任务（37′）

### 第 1 次切换 · `@产品经理` → `@UI`

切换到 `@UI`，要求它读取 `PRD.md`，先用五句话复述用户、问题、主要操作、页面范围和验收标准。学员确认理解一致后再继续。

### UI 逐题设计

让 UI 一次只问一个问题，确认设备、首页信息、风格、主色、最常用操作、加载状态、空数据和错误状态。

### 页面方案确认

UI 先展示页面结构和用户操作路径。学员对照 PRD 检查后回复“确认页面方案”。

### UI 正式交付

生成并保存：

- `design-spec.md`；
- `ui-flow.md`；
- `ui-prototype.html`。

直接打开 `ui-prototype.html`，亲手检查主要按钮和筛选是否产生可见反馈。

### 第 2 次切换 · `@UI` → `@产品经理`

让产品经理读取 PRD 和三个 UI 交付物，逐条输出“通过/不通过、PRD 依据、责任岗位”，不得直接修改 UI 文件。

### 第 3 次切换 · 问题闭环

存在不通过项时切回 `@UI` 修改，再回 `@产品经理` 复验。完成后创建 `day1-handoff-log.md`，记录每次岗位、输入、输出、验收结果和修改轮次。

## 完成标志

- UI 先复述需求、后确认设计、再生成原型；
- 三个 UI 交付文件都存在，HTML 可直接打开并能交互；
- 已回到产品经理按 PRD 验收；
- 至少完整演练一次“发现问题 → UI 修改 → 产品经理复验”，没有问题时由导师指定一条模拟缺口；
- `day1-handoff-log.md` 清楚记录完整闭环。
