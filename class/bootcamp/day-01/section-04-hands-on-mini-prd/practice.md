# 第 4 节 · 练习

## 知识确认（3′）

1. 为什么提示词要「整份粘贴、一个字都别改」？改一个字可能带来什么后果？
2. 复述迭代口诀：产出不对时，先改什么、不改什么？为什么不能手改文档？

## 实操任务（22′）

**跑出你的迷你 PRD**：

1. 打开 AI 工具，新开会话，整份粘入 `PM_Agent_Prompt.md`；
2. 输入点子：「我想做一个部门周报助手，帮部门负责人自动汇总一周数据、生成周报」（或你自己的点子）；
3. 认真回答它提出的全部澄清问题（至少 3 个），每个回答写成明确的约束；
4. 让它生成迷你 PRD，保存到你的工作区为 `PRD.md`；
5. 用三要素自检：≥3 条完整句式用户故事 / 每条可衡量验收标准 / 写明目标平台。缺项则在对话中补约束，重新生成；
6. 把最终版 `PRD.md` 落盘，准备第 5 节过闸。

## 一键粘贴提示词

> 整段复制给 Cursor / Claude Code / 平台 Agent / 任意 AI 搭档。尖括号 `〈〉` 换成你的路径或名称。

```text
把 class/resources/prompt-toolkit/PM_Agent_Prompt.md 整份当作你的系统角色（一字不改）。
我的点子：〈部门周报助手 / 或我的点子〉。
按提示词流程：先澄清提问 → 再产出迷你 PRD。
硬性要求：≥3 条「作为…我想要…以便…」用户故事；每条有可衡量验收；写明目标平台。
最终只输出完整 Markdown，我要存为 PRD.md。
```

## 完成标志

- 工作区存在 `PRD.md`，含「用户故事」「验收标准」两节；
- ≥3 条用户故事全部为「作为……我想要……以便……」完整句式；
- 每条故事有可衡量验收标准（含数字或可数判据），且文档写明目标平台；
- 至少经历过一轮「检查 → 补约束 → 重生成」的迭代（在对话记录中可溯源）。
