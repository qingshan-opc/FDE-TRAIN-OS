# 第 4 节 · 本地实操

在 QRAE 中切换到 `@后端`。不要让前端智能体继续修改后端代码。

## 第 1 段 · 检查现有后端

```text
请读取 iteration-prd.md、frontend-handoff.md、原 API_Spec.md、DB_Schema.md、RUNBOOK.md 和现有后端代码。
只复述业务规则、请求合同、相关入口和现有数据结构。
不要修改代码。输出后停止。
```

## 第 2 段 · 接口与数据方案

```text
请生成 day5-replay/iteration-api-spec.md 和 iteration-db-change.md。
数据无需变化时也要写明理由。
列出修改文件、兼容风险和回退方法。
输出后停止，等我回复“确认后端改动”。
```

## 第 3 段 · 实现后端

```text
已确认。请只实现本次接口与业务规则。
保持原接口兼容，不修改无关模块。
不得把真实密钥写入代码或证据文件。
```

## 第 4 段 · 联调与交接

```text
请运行启动、健康、成功请求、错误请求、持久化和前端真实调用检查。
生成 day5-replay/backend-acceptance.md 和 backend-handoff.md。
写明命令、实际结果、证据、已知限制与测试入口。
```

## 学员检查

- 数据变更是否真的必要？
- 原接口是否仍能正常工作？
- 前端是否发出了约定请求？
- 成功、错误和重启后数据是否都有证据？
