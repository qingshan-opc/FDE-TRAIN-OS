> 总时长 100′ · 5 节 · 概念 55′ + 实战 30′ + 验收 15′

## 这一天在解决什么

角色周的第一天给产品经理，不是随机排的。整条产品研发流水线的第一棒就是 PM——他定方向，后面的人才有活干。你这一周要逐日扮演架构师、前端、后端，而他们的输入全部来自你今天产出的 PRD。第一棒打歪，后面四天全是返工。

更现实的原因是：零基础学员用 AI 工具最常见的卡点是「不知道下什么需求」。点子人人都有，但「帮我做个工具」这种话丢给 AI，得到的只能是一堆看着热闹、没法验收的废话。今天就是要补上这一课——把点子翻译成 AI 能执行、你能验收的需求。

好在 AI 时代这件事的门槛大幅降低了。过去 PM 一半的功力在「写文档」，这部分正在贬值到免费；真正升值的是「定方向」和「做验收」——这两件事不考验文笔，考验判断力，而判断力是可以靠一天的高强度训练建立的。

今天的贯穿案例是「部门周报助手」：帮部门负责人自动汇总一周数据、生成周报的小工具。你也可以换成自己的点子，但流程不变——先学读 PM Agent 提示词，再用它跑出迷你 PRD，最后过快测和 PRD 两道闸。这份 PRD 明天会原样交给架构师提示词，所以今天的验收不是形式主义，是在给明天的自己省返工。

## 今日验收（GATE 1）

- 日级快测 6 题 ≥ 4 题合格（考点覆盖五节关键概念，理解题无背诵题）；
- 迷你 PRD 过闸三要素齐全：≥3 条完整句式的用户故事、每条故事配可衡量的验收标准、写明目标平台；
- 工作区存在 `PRD.md` 且含「用户故事」「验收标准」两节（lab rubric 机器校验）；
- PRD 不合格不进入 Day 2——明天的架构师提示词直接消费这份文档。
