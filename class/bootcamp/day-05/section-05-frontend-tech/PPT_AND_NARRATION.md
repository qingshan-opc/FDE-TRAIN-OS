## 01 · open

**PPT**
- BRIDGE · 从「住哪」到「摸哪」
- 服务器、容器解决「长时间跑」；前端解决「用户看得见、点得到」。

**口播**
> 同学们，上节咱们讲了服务器跟云原生——说白了呢，就是程序住在哪、怎么长时间跑。不管今天的软件，还是工厂里的 ERP、CRM，都得有个生存环境：服务器、物理机、电脑或者容器，对吧。这节换一条线：用户摸到的那一层——前端。

## 02 · define

**PPT**
- 前端不只是网页
- 用户直接接触的界面层——凡是摸得到的，都算。

**口播**
> 先把前端这个词撑大一点。有人对前端的理解呢，还停在做个网页——其实不对。操作系统里你点的窗口按钮、Web 页面、手机 App、微信小程序、桌面上双击打开的软件界面——凡是用户直接接触的界面层，都是前端。一句话记住：摸得到的那一层，就是前端。

文稿：`video/scripts/narration/02-define.txt`

## 03 · platforms

**PPT**
- MAP · 前端四大平台
- 选型第一步永远先问：用户在哪儿用你？

**口播**
> 主流分成四个平台，大家可以看屏幕。Web 网页——浏览器地址栏那一类；App——应用商店下载安装；小程序——微信里扫码即用；桌面软件——电脑上双击图标。选型第一步永远先定平台：用户在哪儿用你，你就站哪条线，对吧。

文稿：`video/scripts/narration/03-platforms.txt`

---

## 04 · web

**PPT**
- WEB · 框架选型
- 地基仍是 HTML / CSS / JS。框架是预制装修套件。

**口播**
> 先说 Web。网页从两千年左右的静态店铺页，发展到今天的强交互——你搜一下，后端算一下，再把结果渲染给你看。地基还是三件套：HTML 骨架、CSS 皮肤、JavaScript 肌肉。框架呢，就是预制装修套件。React——人最多、生态最大、AI 最会写，大型项目常用，也推荐大家优先熟悉。Vue——尤雨溪做出来的，中小型、单体应用很合适，企业小系统、大屏都行。Angular——新项目少一些、上手偏重，但大企业存量还在，别人说我们是 Angular你要听得懂。另外还有 Svelte；以及 React 再加服务端渲染的 Next.js——官网、内容站、电商很常见。小页面呢，不用框架完全够用，你们 第三天 的 index.html 就是。

文稿：`video/scripts/narration/04-web.txt`

## 05 · app

**PPT**
- APP · 原生与跨端
- 性能要极致走原生；小团队默认跨端。

**口播**
> 再说 App。苹果原生是 Swift，安卓原生是 Kotlin——性能跟系统能力最全，代价是两套代码、两拨人。小团队要做双端、求体验一致呢，很常看 Flutter。会 React 的团队转 App，可以走 React Native，包一层壳接到原生。若还要顺带出小程序等多端，国内团队常看 uni-app 这条路。

文稿：`video/scripts/narration/05-app.txt`

---

## 06 · mini-desk

**PPT**
- 小程序与桌面
- 国内生意绕不开小程序；桌面多用网页技术包壳。

**口播**
> 小程序这块，做国内生意绕不开。微信原生是 WXML、WXSS、JS，能力最全最稳。要微信、支付宝、抖音再加 H5、App，就看 Taro 或者 uni-app。桌面软件呢，很多用 Electron——VS Code、飞书都是它包的，前端团队零门槛，代价是包大、吃内存。要轻量，看 Tauri 这类路线。

文稿：`video/scripts/narration/06-mini-desk.txt`

---

## 07 · four-q

**PPT**
- METHOD · 两步法 + 四问

**口播**
> 记住两步法。第一步定平台：用户在哪用你？浏览器、应用商店、微信里、还是桌面图标。第二步选框架，四个问题按顺序问：团队会什么？生态大不大？AI 写得好不好？项目有多大？兜底呢——没团队跟生态走，有团队跟团队走。AI 时代还有个隐藏加分：React 这类语料多的技术，生成质量更稳，对吧。

文稿：`video/scripts/narration/07-four-q.txt`
