# 第 1 节 · 从系统到能力（15′ · 概念）

> 开场 30 秒每人一句：「我要封装的事」。然后换档：对象从「页面」变成「可执行能力」。

## 教学目标

- 说清 Week1→周末→本周的链条：业务系统 → 驾驶舱 → 可聊助手位 → Skill；
- 一句话区分 Prompt 与 Skill；
- 理解 Skill 三重价值：可复用、可验收、可交接。

## 讲授要点（15′）

### 正确叙事（请勿再说「Week1 系统 = 驾驶舱」）

```
Week1：业务系统（CRUD，可运行）
周末：同一应用加成驾驶舱首页 + AI 空槽
D6：助手位接上真实 LLM 对话
今天：给它装「可执行能力」= Skill（说明书 + 可被调用）
后面：Loop 会自动选 Skill 干活
```

关键洞察：**系统被使用，能力被执行**。驾驶舱等人来看；Skill 被 AI（或你的 loop）拿去干活。

### Prompt vs Skill

| | Prompt | Skill |
|---|---|---|
| 寿命 | 这次对话 | 长期复用 |
| 结构 | 想到哪写哪 | 输入/步骤/输出/验收 |
| 验收 | 凭感觉 | 有标准 |
| 形态 | 聊天 | `skills/<id>/SKILL.md` + 可 run |

### 反例：不值得封装

低频、每次都变、必须人拍板的决策——先别封装。

## 常见懵点

- 「我做的是管理系统不是驾驶舱」→ 驾驶舱就是你的管理首页看板；
- 「Skill 要写代码吗」→ 说明书必须有；执行可用 LLM 按说明书产出，或挂脚本；今天要 **可被加载调用**。
