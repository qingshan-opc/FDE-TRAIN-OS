# 第 4 节 · 实现「想→做→看→再想」循环（35′ · 实战）

> 🎬 视频位（现阶段：口播稿）
> 把你的 Skill 挂上 Agent 的工具表。从今天起，你派活用自然语言，挑工具的活，Agent 自己干。

## 教学目标

- 给 Skill 写一段「工具描述」（名称 + 何时用 + 输入要求）——Agent 选工具时只读这个；
- 完成 Agent v0.1 闭环：自然语言任务 → Agent 选对并调用 Skill → 产出过验收；
- 实测「什么时候会选错」，并学会用描述修正。

## 流程安排（30′）

| 时段 | 内容 |
|------|------|
| 0–5′ | 讲解：工具描述 = 工具在货架上的标签 |
| 5–12′ | 写工具描述，挂上 Agent（Agent Lab 操作） |
| 12–24′ | 闭环实测：3 个任务（该调的 / 不该调的 / 容易选错的） |
| 24–30′ | 修正描述 + 记录「选错图谱」 |

## 工具描述（货架标签）

```markdown
## 工具描述（给 Agent 看）
- 名称：weekly-report
- 何时用：需要生成本周运营周报/日报时。输入为本周 KPI 与异常工单数据。
- 不用于：写通用文章、做数据以外的创意写作、对外发送任何内容。
- 输入要求：JSON（kpi 数组 + exceptions 数组），缺数据时本工具会拒绝。
```

三要素：**何时用 + 不用于 + 输入要求**。「不用于」最反直觉也最重要——它是防止误选的护栏。

## 闭环实测三任务

```
任务 A（该调）：「用本周数据生成周报」→ 期望：选中并调用 weekly-report
任务 B（不该调）：「帮我写一句朋友圈文案」→ 期望：不调工具，直接答
任务 C（易选错）：「总结一下这周情况」→ 模糊指令，观察它选什么
```

## 🎬 口播稿（约 6 段 · 待审）

> 同学们，这节把你的 Skill 挂上 Agent 的工具表。Agent 选工具的时候读什么？不是说明书全文——是货架标签，叫工具描述。名称、何时用、输入要求，三要素写清楚，对吧。
> 工具描述三要素：何时用——需要生成本周运营周报时，输入为 KPI 与异常工单数据；不用于——写通用文章、创意写作、对外发送任何内容；输入要求——JSON 格式，缺数据时本工具会拒绝。最反直觉的是不用于——它是护栏，防止周报工具被选去写情诗，嘛。
> 挂上去，测三个任务。任务 A 该调：用本周数据生成周报——期望选中 weekly-report。任务 B 不该调：帮我写一句朋友圈文案——期望不调工具，直接答。任务 C 易选错：总结一下这周情况——模糊指令，观察它选什么，对吧。
> 选错了别怪 Agent 笨，怪标签写得宽。改描述，再测。今天结束前交一张选错图谱：我的 Agent 在什么措辞下会误选或漏选，因为什么，我用什么修了描述。这比十次正确都值钱——它告诉你工具描述的边界在哪，对吧。
> 描述写多长？两到四句；长了稀释关键信息，短了护栏不够。平台没有工具表功能？降级玩法：Prompt 里手动提供工具清单加描述，让模型先输出选择再执行。Agent 调用时输入谁准备？今天你在任务里给数据，第九天编排会把拉数据串起来，嘛。
> 收个尾：从今天起你派活用自然语言，挑工具的活 Agent 自己干。选错图谱和 agent-tool-map.md 一起进 Git。下一节第八天验收——Agent v0.1 闭环演示，对吧。


## 常见懵点

- 「描述写多长？」→ 2–4 句；长了稀释关键信息，短了护栏不够；
- 「平台没有工具表功能怎么办？」→ Agent Lab 主路径支持；降级玩法：Prompt 里手动提供「工具清单+描述」，让模型先输出选择再执行；
- 「Agent 调用时输入谁准备？」→ 今天：你在任务里给数据（或 Agent 先调「拉数据」——Day 9 编排把这个串起来）；
