# 第 2 节 · 练习

## 知识确认（3′）

1. 按顺序默写软件旅程六站。
2. 访谈时为什么不能问「你觉得好不好」？应该问什么？食堂「看倒掉什么」对应哪种调研方法？
3. 用一句话区分：运维可以做什么、严格不做什么？再补一句区分瀑布和敏捷。

## 实操任务（8′）

**「一次迷你需求调研」**：找一位同事或家人，访谈 5 分钟，主题是「你每天工作中最烦的一件重复性小事」。要求：
- 只问「上一次……是什么时候、你怎么处理的」，不问「你想不想要某个功能」；
- 记下三行：他的角色、最近一次的具体场景、他现在的凑合办法；
- 最后用一句话写出你发现的问题（格式：「谁在什么场景下被什么问题折磨，现在靠什么凑合」）。

## 完成标志

- 六站顺序能不看笔记背出
- 访谈记录有三行（角色 / 具体场景 / 凑合办法），且包含一个「上一次」式回答
- 问题一句话里不出现解决方案，只有「谁 + 场景 + 痛 + 现状」
