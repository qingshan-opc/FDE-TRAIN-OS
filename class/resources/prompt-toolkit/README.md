## 为什么是这五份

它们来自同一条产品研发流水线：**PM 定方向 → 架构师定骨架 → 设计/前端定脸 → 后端定心脏**。
每份提示词的「关键输入」恰好是上一棒的「关键输出」——这就是第一天到第四天的学习路径，
也是真实 Agent 团队协作的最小闭环。

## 提示词解剖学（四要素 + 两接口）

每份提示词都长一个样，记住这个结构，你就能自己写：

1. **角色定位** —— 它是谁，多少年功力（决定回答的专业水位）；
2. **核心任务** —— 它的职责边界（决定不越界、不缺位）；
3. **关键输入** —— 它从哪里读需求（上游交付物的路径约定）；
4. **关键输出** —— 它交付什么、存到哪（下游能直接接着用）；
5. **协作说明** —— 它和谁交接（两接口：Input Sources / Output Targets）。

## 迭代口诀

- 产出不对，先改**约束**再重生成，不要手改产物；
- 每改一版提示词，记一行迭代日志：改了什么、为什么、效果如何；
- 提示词就是源码——可迭代、可验收、可追溯。
