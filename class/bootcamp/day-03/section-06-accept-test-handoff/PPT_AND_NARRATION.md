## 03 · fix

- P2 · 确认后修复

- 完整更新文件
- 逐项回归

## 05 · six-files

**PPT（屏幕）**
- 测试接收六件套
- PRD
- API 与数据合同
- RUNBOOK
- 验收与交接单

**口播**
> 测试岗位要接收六类材料：需求文件，说明测什么业务；接口合同，说明怎样成功和失败；数据合同，说明记录怎么保存；运行手册，说明怎么启动；验收记录，说明验证过什么；交接单，说明限制和待测重点。材料齐了，切测试。

文稿：`video/scripts/narration/05-six-files.txt`

## 06 · test-receive

**PPT（屏幕）**

- 今天不要执行测试

## 07 · why-wait

**PPT（屏幕）**
- 为什么不提前测试
- Day3 先完成交接
- Day4 再定测试计划
- 岗位边界更清楚

**口播**
> 让测试只接收，不是拖延。第三天的目标是后端完成并可靠交棒，第四天才由测试制定计划、执行用例、提交缺陷。现在提前开测，小白就分不清后端验收和独立测试的边界了。接收确认无误，记日志。

文稿：`video/scripts/narration/07-why-wait.txt`
