# 第 2 节 · 四层架构与前后端分离（15′ · 概念）

> 不管你的应用多简单，它都有四个「器官」。看懂它们，明天做前端、后天做后端你都知道自己在哪一层。

## 教学目标

- 说出四层架构：前端 / 接口 / 数据库 / 模型，并各用一句人话解释；
- 理解前后端分离 = 厨窗分开、只凭菜单交流；
- 说出分层带来的红利：「换内脏不换脸」。

## 讲授要点

### 四层架构（以周报助手为例）

| 层 | 人话 | 周报助手里是什么 |
|----|------|------------------|
| 前端 | 你看到的部分 | 提交周报的表单、周报列表页面 |
| 接口（API） | 前后端怎么对话 | 「提交一条周报」「拉取本周全部周报」 |
| 数据库 | 数据住哪 | 存周报条目的表：谁、哪周、写了什么 |
| 模型 | 谁动脑子 | 把 30 条周报汇总成一段摘要的大模型 |

### 前后端分离：厨窗分开

餐厅里，厨房和前厅是分开的，只凭一样东西交流——**菜单**。服务员不用会炒菜，厨师不用会招呼客人；只要菜单不变，厨房换厨师、前厅换装修，互不干扰。

前后端分离就是这个意思：前端（前厅）和后端（厨房）只通过 API（菜单）交流。中间那份「菜单合同」就是接口约定。

### 分层的红利：换内脏不换脸

- 数据库从 SQLite 换成 PostgreSQL → 前端无感知；
- 模型从 A 换成 B → 只要接口不变，页面一行不改；
- 前端重做皮肤 → 后端一行不改。

「换内脏不换脸」——这就是分层存在的全部理由。

### 模型层是 AI 时代的新器官

传统架构只有前三层。AI 应用多了第四层：模型。它像一个「随叫随到的实习生」——写摘要、做分类、生成文案，但它也会犯错（幻觉），所以架构上要把模型调用和核心业务隔开，出错可降级。

## 🎬 口播稿（约 2 分钟）

【抛问题】
同学们，一个 AI 应用拆开看，里面到底有几个「器官」？今天给你一张图，明天后天你都靠它定位。

【四层】
四层。第一层，「前端」——你眼睛看到的部分，表单、按钮、页面。第二层，「接口」，也叫 API——前后端怎么对话。第三层，「数据库」——数据住哪。第四层，「模型」——谁动脑子。你的周报摘要，就是它写的。

【类比】
前后端什么关系？想想餐厅。「厨房和前厅是分开的，只凭菜单交流。」服务员不用会炒菜，厨师不用会招呼客人。菜单在，谁也不依赖谁。这份菜单，就是接口。

【红利】
为什么要分？为了——「换内脏不换脸」。数据库换了，页面不动；模型换了，页面不动；页面重做皮肤，后端不动。分层不是装专业，是给未来的自己留退路。

【AI 时代】
注意，模型层是 AI 时代的新器官。它像随叫随到的实习生，能干，但会犯错——所以架构上要把它隔开，出错能降级。

【带走的话】
带走一句话——「四层各司其职，接口就是菜单。」

## 常见懵点（导师备用）

- 「接口和前端不都是代码吗，区别在哪？」→ 前端跑在用户的浏览器里，接口跑在服务器上；接口是「服务的窗口」，前端是「用户的脸面」；
- 「模型层和接口层会合并吗？」→ 模型调用通常封装在后端里，但架构图上单独标出，因为它的成本、延迟、错误模式都不一样；
- 「四层是最少的吗？还有别的层吗？」→ 这是最小够用模型；真实系统可能加缓存层、消息队列，但先记住四层，其他都是变种。
