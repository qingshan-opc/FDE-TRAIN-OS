# 第 2 节 · 实战：Skill v1 + 异常注入测试（40′ · 实战）

> 🎬 视频位（现阶段：口播稿）
> 上刑场：故意喂坏输入，看你的 Skill 怎么死。死法符合声明，才算可依赖。

## 教学目标

- 把边界声明合入说明书，升级 Skill v1；
- 执行异常注入测试：≥3 种坏输入，逐一验证「按声明的方式失败」；
- 迭代修声明/修 Skill，直到注入全过 + 乖数据回归仍过。

## 流程安排（40′）

| 时段 | 内容 |
|------|------|
| 0–5′ | 讲解：注入测试法——坏输入清单从哪来 |
| 5–10′ | 合入边界声明 → Skill v1 |
| 10–30′ | 注入测试：逐条喂坏输入，记录「死法」并对照声明 |
| 30–38′ | 迭代修复 + 乖数据回归（v1 不能把好输入也变挑了） |
| 38–40′ | 证据归档 + commit 准备 |

## 坏输入清单（按四类各备至少一条）

```
输入错：空数据 / 缺关键字段 / 字段名变了 / 日期范围超限
环境错：（模拟）接口超时、数据文件打不开
能力限：「顺便翻译成英文」「直接发给客户」
目标歧：「把两周数据合并一下」
```

## 注入记录表

```
| 坏输入 | 期望死法（声明原文）| 实际死法 | 判定 |
| 空数据 | 停止+列出所缺字段 | | ✓/✗ |
| ... | | | |
```

判定只有两种：
- **✓ 按声明的方式失败**（拒绝/重试后报告/列理解请确认）；
- **✗ 失控失败**（编了数据、硬撑着交付、闷头乱选）——必须修。

## 修复的两个方向（别搞反）

- 死法对但声明没写 → **补声明**；
- 死法不对 → **改说明书**（边界段措辞/示例/红线前置），不是骂 AI。

## 🎬 口播稿（约 6 段 · 待审）

> 同学们，这节上刑场。注入测试是软件工程的老手艺：故意喂坏的，看它怎么死。你的 Skill 昨天在乖数据上过关，今天要在坏数据上证明——死法符合声明，才算可依赖，对吧。
> 清单按四类各备至少一条：输入错——空数据、缺关键字段、字段名变了、日期范围超限；环境错——模拟接口超时、文件打不开；能力限——顺便翻译成英文直接发给客户；目标歧——把两周数据合并一下。咱们逐条喂，记录实际死法，嘛。
> 每条坏输入填一张表：期望死法写声明原文，实际死法看 AI 怎么反应，判定只有两种。✓ 按声明的方式失败——拒绝、重试后报告、列理解请确认，好死。✗ 失控失败——编了数据、硬撑着交付、闷头乱选，必须修，对吧。
> 修的时候方向别搞反。死法对但声明没写——补声明，条款缺失补条款。死法不对——改说明书，边界段措辞、示例、红线前置，不是骂 AI。AI 太聪明了，空数据也编一份周报？这正是要抓的失控：红线前置加空数据必须拒绝，再测，对吧。
> 最后一步别省：乖数据回归。边界加完，好输入也得照常过——别把 Skill 修成什么都拒的废人。今天标准：注入测试至少三条、覆盖至少两类，全部 ✓，再加乖数据回归仍过，才算 Skill v1 达标，嘛。
> 证据归档，commit 准备。带走一句：注入测试比十次正确运行都值钱——它告诉你 Skill 在坏输入下会不会失控。下午咱们掀引擎盖，看 Agent 和 Harness 怎么调用你的 Skill，对吧。


## 常见懵点

- 「AI 太聪明了，空数据也给我编了一份周报」→ 这正是要抓的失控：红线前置 + 边界段加「空数据必须拒绝」的明确指令，再测；
- 「注入测试要多少条？」→ 今天 ≥3（覆盖 ≥2 类）；真实项目按风险加；
- 「修声明和改说明书有什么区别？」→ 声明是「合同条款」，说明书是「执行细则」——条款缺失补条款，执行跑偏改细则。

> 拓展（非必修）：模糊测试（fuzzing）、混沌工程 → 公开课 O2/O3。
