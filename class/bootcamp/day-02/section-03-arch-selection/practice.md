# 第 3 节 · 练习

## 知识确认（3′）

1. 用「住法」类比对同伴讲清单体 / 微服务 / Serverless 的区别。
2. 背出选型四问，并说明「团队人数」为什么通常是一票否决项。
3. 「为假想中的规模过度设计」为什么是小团队最常见的死法？

## 实操任务（7′）

为你的周报助手完成一次「选房」推演，写下四问的答案：

| 问题 | 你的答案 |
|------|----------|
| 团队几个人？ | |
| 预期多少人用？峰值并发多少？ | |
| 迭代多快？需求稳定吗？ | |
| 出事谁修？有专职运维吗？ | |

然后做两个判断：

1. **初选**：基于四问，你选哪种架构风格？一句话。
2. **否决**：写出你**不选**的另一种风格 + 一句否决理由。（例：「否决微服务——团队 1 人，维护多个服务的成本远超收益。」）

这两个判断就是第 4 节 ADR-001 的毛坯。

## 一键粘贴提示词

> 整段复制给 Cursor / Claude Code / 平台 Agent / 任意 AI 搭档。尖括号 `〈〉` 换成你的路径或名称。

```text
你是选型教练。给定约束：〈团队规模/上线时间/是否要登录〉（我来填）。
请给出 2 个技术选型决策（例如前端栈、是否上 BFF），每个必须写：选项 A/B、约束、选择、不选理由。
不要空谈「看情况」。
```

## 完成标志

- 四问表格全部填写，数字具体（不写「可能很多人」）；
- 初选与否决各一句，理由引用四问中的具体约束；
- 能说出至少一个「未来重新评估」的演进信号。
