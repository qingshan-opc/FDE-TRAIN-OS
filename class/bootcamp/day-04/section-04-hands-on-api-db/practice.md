# 第 4 节 · 练习

## 知识确认（3′）

1. 后端提示词里哪两样产出是「强制/必备」的？（提示：OpenAPI 格式的 API 文档、带索引建议的数据库设计说明）
2. 为什么不能上来就让 AI「直接生成完整后端设计」，而要先让它问澄清问题？

## 实操任务（27′）

按四步节奏在你的 AI 工具里跑一轮（可在平台 lab 直接进行，lab 已自动带上你前三天的 PRD.md、architecture.md、index.html）：

1. **粘贴提示词**：下载 `Backend_Engineer_Agent_Prompt.md`，整份粘入对话；
2. **喂上下文 + 设规矩**：把 PRD.md 与 architecture.md 内容交给它，并附上这句——「动笔前先问我 3 个澄清问题：核心数据实体、谁调用这些接口、数据量级」；
3. **先清单后展开**：先要 3–5 个接口的一行清单（路径 + 方法 + 一句话用途），确认无误后让它逐个展开为 `API_Spec.md`——每个接口必须含：路径、方法、请求参数、成功响应、至少一个错误响应；
4. **配表**：让它基于接口清单输出 `DB_Schema.md`——2–3 张表，每张表列名列类型列约束，每张表有主键，全库至少一个索引建议并写明理由。

生成中打回重做的两个典型时机：

- 接口没有错误响应 → 「补上每个接口的 400/404 场景」；
- 接口和表对不上 → 「逐个接口标注它读写哪张表的哪几列，对不上的修正设计」。

## 完成标志

- `API_Spec.md` 落盘，含 3–5 个接口且四要素齐全；
- `DB_Schema.md` 落盘，含 2–3 张表，主键、索引建议齐备；
- 随机指一个接口，你能说出它读写哪张表的哪几列。
