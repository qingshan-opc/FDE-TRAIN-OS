# 第 1 节 · 概念：从系统到能力（15′ · 概念）

> 🎬 视频位（现阶段：口播稿）
> 开场 30 秒每人一句：「我要封装的事」（昨晚作业）。然后换档：Week 2 的思维对象变了。

## 教学目标

- 说清 Week 1→2 的换档：从「做系统」到「造能力」；
- 一句话区分 Skill 与 Prompt：Prompt 是一次性对话，Skill 是可复用说明书；
- 理解 Skill 的三重价值：可复用、可验收、可交接。

## 讲授要点（15′）

| 时段 | 内容 |
|------|------|
| 0–5′ | 开场：每人 30 秒讲「我要封装的事」 |
| 5–10′ | 换档讲解：系统 vs 能力；Prompt vs Skill |
| 10–15′ | Skill 的三重价值 + 反例：什么事不值得封装 |

### 系统 vs 能力

```
Week 1：系统 = 驾驶舱（前端+接口+数据库+LLM，跑在那里）
Week 2：能力 = 一件具体的事（生成周报 / 整理线索 / 初审工单）
         能力的载体 = Skill（说明书）+ 执行者（AI）
```

关键洞察：**系统被使用，能力被执行**。驾驶舱等着人来看；Skill 是被 AI 拿去干活的——你从此从「操作者」变成「派活的人」。

### Prompt vs Skill（一句话版）

| | Prompt | Skill |
|---|--------|-------|
| 寿命 | 这次对话 | 长期复用 |
| 结构 | 想到哪写到哪 | 输入/步骤/输出/验收 四部件 |
| 验收 | 凭感觉 | 有标准，可判对错 |
| 交接 | 无法交接 | 同事（人或 AI）照着就能做 |

> 你 Week 1 写的 `prompts/summary.md` 其实已经半个 Skill 了——今天把它升级成完全体。

### 反例：不值得封装的事

- 一年做一次的（封装成本回不来）；
- 每次都不一样的（没有稳定步骤可写）；
- 必须人来判断拍板的（可以封装「准备材料」，不能封装「做决定」）。

## 🎬 口播稿（6 段 · 与 video/scripts/narration 同步）

> 同学们好，我是你们的老师404。第七天换档——第一周做系统，第二周造能力。关键句：**系统被使用，能力被执行**。Prompt 管这次对话，Skill 管长期复用（输入/步骤/输出/验收）。三重价值：可复用、可验收、可交接。反例：低频、不稳定、高风险别碰。详见 `PPT_AND_NARRATION.md`。


## 常见懵点

- 「Skill 是新概念还是新瓶装旧酒？」→ 概念不新（SOP 存在几十年了），新在执行者：说明书第一次能被 AI 直接执行；
- 「我的驾驶舱和 Skill 什么关系？」→ 驾驶舱是 Skill 的数据来源之一：Day 9 你会编排「从驾驶舱拉数据 → 生成周报」；
- 「 Skill 要写成代码吗？」→ 不用：Markdown 说明书即可，AI 读得懂；Week 2 全程如此。
