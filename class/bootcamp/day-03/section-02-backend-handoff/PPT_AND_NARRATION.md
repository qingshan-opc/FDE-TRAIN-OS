## 01 · open

**PPT（屏幕）**
- 第二次开发交接
- @前端 → @后端
- 先接收，后开工

**口播**
> 同学们好，我是你们的老师四零四。现在开始前端到后端的正式交接。很多小白只会说帮我做后端。面对大量代码时又不知所措。今天我们把交接拆成四步。先检查和复述。再逐题澄清。最后展示方案并由你确认。

文稿：`video/scripts/narration/01-open.txt`

## 02 · inputs

**PPT（屏幕）**
- 后端四类输入
- PRD
- 前端数据需求
- 真实文件与验收

**口播**
> 后端首先读取需求文件。它还要读取前端数据需求。真实页面文件会告诉它请求从哪里发生。前端验收记录说明上游通过了哪些检查。缺少任何一项都不要猜测。后端要先指出缺口。学员再回到责任岗位补齐。

文稿：`video/scripts/narration/02-inputs.txt`

---

## 03 · p1

**PPT（屏幕）**
- P1 · 只检查文件
- 不要设计接口
- 不要写代码
- 缺项回责任岗位

**口播**
> 第一段提示词只做文件检查。切换到后端岗位。让它报告五类文件是否存在。现在不要设计接口，也不要写代码。缺少需求就回产品经理。缺少数据需求或调用位置就回前端。输入补齐以后，生成才有可靠起点。

文稿：`video/scripts/narration/03-p1.txt`

## 04 · p2

**PPT（屏幕）**
- P2 · 五项复述
- 规则
- 展示与提交
- 四种状态
- 待确认问题

**口播**
> 文件齐全后发送第二段。让后端复述核心业务规则。页面展示数据和用户提交内容也要说清。还要覆盖四种页面状态和待确认问题。你要对照原文件检查。理解不一致时只做纠正。后端不能擅自修改上游文件。

文稿：`video/scripts/narration/04-p2.txt`

---

## 05 · p3

**PPT（屏幕）**
- P3 · 一次只问一题
- 数据来源
- 核心对象
- 权限与隐私
- Python 环境

**口播**
> 第三段进入逐题澄清。后端一次只能问一个问题。先确认数据来源和核心数据对象。再确认访问权限和隐私限制。最后检查本机运行环境。每题都给一个当前项目的回答示例。你先完成回答。它才能继续下一题。

文稿：`video/scripts/narration/05-p3.txt`

---

## 06 · environment

**PPT（屏幕）**
- 环境只做一件事
- python --version
- 不行再试 py --version
- 不乱装未知工具

**口播**
> 环境检查保持简单。先在工具终端输入 Python 版本检查命令。如果命令不存在，再使用启动器的版本命令。这里只确认 Python 三是否可用。不要下载陌生安装包。也不要提前安装很多框架。出错时保留原始提示。

文稿：`video/scripts/narration/06-environment.txt`

---

## 07 · p4

**PPT（屏幕）**
- P4 · 最小后端方案
- 3—5 个接口
- 2—3 张表
- 运行与健康检查
- 明确不做项

**口播**
> 第四段只展示最小后端方案。第一版采用 Python 标准库和本地轻量数据库。接口数量控制在三个到五个。数据表控制在两张到三张。还要写清运行和健康检查。登录和云部署等未确认功能不要加入。

文稿：`video/scripts/narration/07-p4.txt`

---

## 08 · gate

**PPT（屏幕）**
- 人工确认闸
- 学员检查方案
- 本人回复
- 确认后端方案

**口播**
> 方案出来后，你要逐条检查。接口必须覆盖主要页面动作。数据表只服务当前第一版。运行方式也要适合当前电脑。确认无误以后，由你本人回复确认后端方案。这句话是人工闸门，智能体不能代替你自动通过。

文稿：`video/scripts/narration/08-gate.txt`
