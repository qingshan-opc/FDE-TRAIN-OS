# 四层架构速查卡（M2–M3 手边卡）

> 打印或钉在手边。每天开工前问自己一句：**今天在动哪一层？**

## 一张表

| 层 | 回答的问题 | 本课技术 | 将来可换 | 建设日 |
|---|-----------|---------|---------|--------|
| 前端 · 看 | 人怎么看、怎么用 | 原生 HTML/CSS/JS 单页 | React / Vue / 小程序 | Day 2 |
| 接口 · 传 | 数据怎么规范流动 | FastAPI | Express / Spring | Day 3 |
| 数据库 · 存 | 什么是真的 | SQLite | PostgreSQL / MySQL | Day 4 |
| 模型 · 想 | 数据意味着什么 | 平台模型网关 | 任意 OpenAI 兼容模型 | Day 5 |

## 一次请求的四层之旅（Day 4 后的样子）

```
浏览器 → 前端请求 GET /api/metrics
      → 接口校验参数、查库、组装 JSON
      → 数据库返回真实记录
      → 前端渲染；同时 POST /api/summary
      → 模型读数据、写摘要 → 显示在摘要区
```

## 三态检查（任何取数区块）

- [ ] 加载中：有等待提示（不是白屏）
- [ ] 空数据：有空态文案（不是裸表头）
- [ ] 出错：有友好错误（不暴露 500/null 给用户）

## 常见误判（导师高频纠偏）

- ❌「AI 模型是独立业务层」→ 它是外挂大脑，附着在前三层上，不产生业务数据
- ❌「接口就是网址」→ 接口是请求/返回/出错的约定，网址只是地址
- ❌「数据写死=造假」→ 分日替换策略：壳先成立，假数据逐日换真
- ❌「换框架=换架构」→ 概念层稳定，技术层可换
