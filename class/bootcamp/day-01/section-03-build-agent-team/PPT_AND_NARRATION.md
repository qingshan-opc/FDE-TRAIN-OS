## 01 · open

**PPT（屏幕）**
- 把工程地图装进 TRAE
- 六个智能体 = 六份长期岗位说明书
- 职责清楚，交接才清楚

**口播**
> 同学们好，我是你们的老师404。现在我们要把刚才那张六岗位地图装进 TRAE。先说清楚：我们不是创建六个名字不同、行为一样的聊天机器人，而是在创建六份长期岗位说明书。产品经理只能确认需求和验收，UI 只负责设计与原型，前端、后端、测试、运维也各有边界。边界越清楚，交接越像真实团队。

## 02 · find-entry

**PPT（屏幕）**
- 第一步 · 找到创建入口
- 点击 @Agent
- 滚动到列表底部 → 创建智能体
- 看不到？先确认 Agent 对话模式

**口播**
> 看右侧对话区，第一步点击当前显示的 @Agent。屏幕会展开内置智能体和自定义智能体列表。在列表底部找到“创建智能体”。如果你没看到，不要着急乱点，先确认当前处在 Agent 对话模式，再把列表滚动到底部。今天所有岗位都从这个入口创建。

## 03 · name-role

**PPT（屏幕）**
- 第二步 · 名称统一
- 第一个：产品经理
- 后续提示会用 @岗位 精确切换

**口播**
> 进入创建页面后，最上方是名称。第一个填写“产品经理”。名称必须和课程统一，因为后面提示会明确写“切换到 @产品经理”。如果你写成“小王产品大神”，虽然也能用，但小白跟课时会找不到同名岗位。课程阶段先统一命名，等你掌握流程后再个性化。

文稿：`video/scripts/narration/03-name-role.txt`

## 04 · paste-prompt

**PPT（屏幕）**
- 第三步 · 粘贴岗位提示词
- 01-product-manager.md
- 只复制：提示词正文
- 一个智能体只放一个岗位

**口播**
> 下面最大的输入框是“提示词”。这里不是输入今天临时要做的任务，而是放岗位长期遵守的说明书。请打开课程提供的 01-product-manager 文件，只复制“提示词正文”下面的内容，完整粘贴。里面已经规定了一次只问一个问题、先复述、等待确认、生成哪些文件以及什么时候交给 UI。不要把六个岗位提示词粘在一起，一个智能体只对应一个岗位。

文稿：`video/scripts/narration/04-paste-prompt.txt`

## 05 · disable-calling

**PPT（屏幕）**
- 第四步 · 关闭被其他智能体调用
- 第一周先手动切换每一棒
- 先学会流程，再学习自动编排

**口播**
> 再往下看“可被其他智能体调用”。本课程第一周请把它关闭。有人会问，能自动调用不是更高级吗？技术上看起来更省事，但你会跳过最重要的学习过程：不知道什么时候从产品切到 UI，也不知道两个岗位靠什么交接。我们先让你亲自做项目负责人，手动切换每一棒；第二周学会 Skill 和 Agent 编排后，再讨论怎样自动化。

文稿：`video/scripts/narration/05-disable-calling.txt`

## 06 · tools-create

**PPT（屏幕）**
- 第五步 · 工具按岗位需要设置
- 工具越多，不一定越强
- 确认名称 + 提示词 → 创建

**口播**
> 工具区域先按课程给出的默认要求设置，不要因为看到很多工具就全部打开。工具越多不一定越强，反而可能让岗位越界。产品经理主要读取和生成文档，UI 需要读取需求并生成设计与原型；其他岗位后续课程再实际使用。确认名称和提示词后点击“创建”。

文稿：`video/scripts/narration/06-tools-create.txt`

## 07 · verify-first

**PPT（屏幕）**
- 创建后先验证，不急着发任务
- 自定义智能体 → 产品经理 → 出现对勾
- 再依次创建 UI / 前端 / 后端 / 测试 / 运维

**口播**
> 创建完成会回到对话区。再次点击当前智能体，你应该能在“自定义智能体”下看到产品经理。选择它，列表旁出现对勾，就表示当前会话已经切换到这个岗位。现在先不要讲项目需求，我们只是验证它能被选中。随后按照同样步骤创建 UI、前端、后端、测试和运维。

文稿：`video/scripts/narration/07-verify-first.txt`

## 08 · boundary-check

**PPT（屏幕）**
- 每建一个岗位，问三句
- 它接收什么？
- 它交付什么？
- 它不能做什么？

**口播**
> 六次创建看起来重复，但这是有意义的肌肉记忆。每创建一个岗位，都顺手问自己三句：它接收什么？它交付什么？它不能做什么？产品经理不能替 UI 画最终原型，UI 不能替产品经理增加功能，测试不能偷偷替开发修代码，运维不能未经确认修改产品需求。你越清楚边界，后面越不容易让一个 AI 会话失控。

文稿：`video/scripts/narration/08-boundary-check.txt`

---

## 09 · switch-inspection

**PPT（屏幕）**
- 六岗位切换巡检
- @产品经理 → @UI → @前端 → @后端 → @测试 → @运维
- 最后回到 @产品经理

**口播**
> 六个岗位都建好后，做一次切换巡检。依次选择 @产品经理、@UI、@前端、@后端、@测试、@运维，每次只看名称和对勾，不发送正式任务。最后回到 @产品经理，因为下一阶段要从需求开始。如果某个岗位缺失，就回到创建入口补齐，不要带着缺口继续。

文稿：`video/scripts/narration/09-switch-inspection.txt`

## 10 · close

**PPT（屏幕）**
- 你已经有了一支 AI 开发团队
- @岗位 = 指挥棒
- 工作区文件 = 接力棒
- 下一节：选择一个小而真实的项目

**口播**
> 带走一句话：创建智能体不是装六个插件，而是在搭建一支职责清楚的 AI 开发团队。@岗位 是你手里的指挥棒，工作区文件是岗位之间的接力棒。下一节我们先不急着对话，而是从你的专业领域挑一个足够小、足够真实的项目。同学们，本节先到这里。
