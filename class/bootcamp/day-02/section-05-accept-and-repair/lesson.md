# 第 5 节 · 亲手验收并完成一次修复

## 本节目标

- 区分“文件存在”和“页面可用”；
- 学会检查页面、主要操作、四种状态和控制台；
- 用“位置、操作、实际、预期”描述问题；
- 让责任岗位修复，并执行同样步骤复测。

## 五类人工检查

1. 页面能否打开，有没有空白屏；
2. 主要文字和区块是否齐全；
3. 按钮、筛选或表单是否产生可见反馈；
4. 加载、空数据、成功、错误是否都能进入；
5. 浏览器控制台有没有红色错误。

## 问题不能只说“没反应”

合格问题单必须包含：

- **位置**：在哪个页面或区块；
- **操作**：点击、输入或选择了什么；
- **实际**：页面真实发生了什么；
- **预期**：根据 UI 流程应该发生什么。

例如：“在首页筛选区选择本月并点击查询，列表没有变化；按照 ui-flow.md，列表应只显示本月记录，并在上方显示筛选条件。”

## 谁修，谁验

学员和 UI 可以提出问题，但代码仍由 `@前端` 修复。修复后，验收者必须执行原来完全相同的操作。只听 AI 说“已修复”不能通过。

## 口播稿

同学们好，我是你们的老师404。现在页面已经生成，但不要被文件数量骗了。三个文件都在，不代表用户能用。工程验收必须亲手运行。

先打开页面，看有没有空白屏；再检查主要文字和区块；然后点击最重要的按钮、筛选或表单；接着把四种状态逐一切出来；最后按 F12 看控制台有没有红色错误。

发现问题时，不要对 AI 说“这里不好用”。用四句话描述：问题在哪里、你做了什么、实际出现什么、预期应该什么。描述越具体，前端越容易只改错的地方，不破坏已经通过的部分。

修复仍然交给 @前端。它要告诉你原因、修改了哪个文件、怎样复测。然后你必须重新执行同样操作。AI 说“完成”只是通知，页面真的通过才是证据。今天至少做一次“发现问题、前端修复、亲手复测”的闭环。同学们，本节先到这里。
