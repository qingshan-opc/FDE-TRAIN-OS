# 第 3 节 · 先定 API 与数据合同

## 本节目标

- 理解“先合同后代码”；
- 写全接口六要素；
- 只设计第一版需要的数据表；
- 完成页面、接口、数据表三方对账。

## 接口六要素

每个接口都写清：请求方法、路径、用途、请求参数或请求体、成功状态码与 JSON、错误状态码与触发条件。只写“有一个查询接口”不算合同。

## 最小数据合同

`DB_Schema.md` 只设计第一版真正需要的 2—3 张表。每张表写字段、类型、主键、是否必填和必要关系。所有接口字段都要能追到某个表字段或明确的计算规则。

## 三方对账

```text
页面操作 → API 方法与路径 → 表名.字段名
```

对账时发现字段无来源、表字段无人使用或命名不一致，先只列问题。学员确认后，再完整重生成两份合同。

## 口播稿

同学们好，我是你们的老师404。代码开工前，我们先把两份合同定清楚。API 合同告诉前端怎样请求、成功收到什么、失败收到什么；数据合同告诉后端每一条真实记录怎样保存。先只列三到五个接口菜单，确认后再展开六要素。接着只设计第一版需要的表，每张表必须有主键。最后从页面操作一路对到接口，再对到表字段。合同有错就完整重生成，不让前后端拿着两个版本继续做。同学们，本节先到这里。
