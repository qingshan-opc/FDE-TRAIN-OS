# Week 1 · Day 1 课程包：学员任务提示词（三领域版 · V3）

> 关联文档：`docs/Week1_Course_Outline.md`（V3 结构与验收项）、`docs/Week1_Domain_Packs.md`（领域变量与字段基线）。
>
> **Day 1 主线**：创建智能体团队 → 选题 → @产品经理 出 PRD → @UI 出交互原型 → 项目建档。
> **使用方式**：平台课节 STEP 3 展示对应提示词，学员一键复制 → 粘贴到 Trae → 按标注使用（通用对话 / @产品经理 / @UI）。
> **领域对应**：A = 财务费用管理系统 ｜ B = HR 员工诉求管理系统 ｜ C = 经营问题闭环系统（默认）。

## D1-L1 · 选题：选定你的战场

**使用方式**：本课节不需要 Trae。平台展示三张领域卡（业务场景、核心对象、AI 能力、适合人群），学员选择后在平台提交选题理由（≥50 字），平台生成 `选题确认单`。
**教学要点**：选与自己专业/岗位相关的方向——你做出来的东西，应该是你自己想要的。

**平台自检清单**：
- [ ] 我读完了三张领域卡
- [ ] 我选定了领域并写下了理由
- [ ] 我知道 Day 1 结束前可以换题一次

## D1-L3 · 向 PM 下达第一个需求：从老板一句话到 PRD

**使用方式**：Trae 对话中 **@产品经理**，粘贴对应领域提示词；随后以"老板"身份回答 PM 的澄清提问。
**教学红线**：PM 必须先提问澄清再写 PRD——如果他直接开写，学员要打断他："先向我提问。"

### 领域 A（财务版）

```text
@产品经理

我是这个项目的负责人。老板的原话是："每个月报销一团乱，我不知道钱花哪儿了，给我做个系统管起来。"

项目背景：我要做的是一套「公司财务费用管理系统」——员工在页面提交费用记录，负责人查看处理，数据存入数据库，驾驶舱展示费用统计。计划 5 天做出 V1.0：单应用、本地数据库、跑通真实业务数据链路；详情页预留“AI 分析区｜Week2 接入”，本周不接真实 AI。

请你按你的工作方式执行：
1. 先向我（扮演老板）提问澄清，不超过 8 个关键问题。在我回答之前，不要开始写 PRD。
2. 我回答后，产出本项目的精简版 PRD，保存为 docs/PRD.md，必须包含五章：
   ① 项目目标与背景；② 目标用户与核心场景；③ 至少 3 个核心用户故事（作为…我想要…以便…）；④ MVP 范围（P0 不超过 4 项，并明确列出本期不做什么）；⑤ 费用报销单的数据字段清单（字段名/类型/必填/说明）与每条 P0 功能的验收标准。
3. 规模约束：这是一个 5 天教学项目，范围务必克制；不确定的内容标"待确认"，不要编造。

完成后汇报：你提了什么关键问题被我否决或补充了，为什么。
```

## D1-L4 · 把 PRD 交给 UI：产出可点击的交互原型

**使用方式**：Trae 对话中 **@UI**，只发一句话指令（三领域通用，PRD 里已带领域信息）。
**设计说明（V3.1 修订，按创始人反馈）**：UI 智能体创建时已载入完整岗位职责（输出目录 `design/prototypes/`、Tailwind + FontAwesome、index.html 平铺入口、空/加载/失败三态、平台风格——全都写在他的提示词里）。**标准在岗位职责里，不在每次的指令里**：任务越短，说明团队配置得越好。学员要练的是"下达意图 + 验收纠偏"，不是替 UI 写规格书。

**学员指令（复制这一句话即可）**：

```text
@UI 请阅读当前工作区的 docs/PRD.md，为它产出高保真可交互 HTML 原型。
```

**然后进入本课节真正的训练：验收与纠偏。** 学员对照平台自检清单逐项验收原型，**发现问题就给 UI 下纠偏指令**（从下方指令库选用，或仿照它自己写）：

| 发现的问题 | 纠偏指令示例 |
|---|---|
| 页面缺空态 | "列表页没有数据时应该显示空态提示，请补上。" |
| 字段与 PRD 不一致 | "提交页字段和 docs/PRD.md 的字段清单不一致，请以 PRD 为准逐个核对修改。" |
| AI 区边界不清 | "详情页标题请写'AI 分析区｜Week2 接入'；样例内容必须标'演示数据'，不要写成真实 AI 结果。" |
| 页面缺失 | "还缺详情页，请按 PRD 的用户故事补上。" |
| 打不开/样式错乱 | "index.html 打开后页面错乱，请检查文件路径和样式引用。" |
| 风格不符 | "这是企业后台系统，请用简洁专业的风格，主色用青绿系。" |

**教学红线**：不允许跳过验收直接说"重做"。每条纠偏指令必须写清"**哪里不对、改成什么样**"——这就是验收口径，是学员每天都要用的基本功。

**平台自检清单**：
- [ ] 三个页面都能打开，index.html 能平铺预览
- [ ] 表单字段和 PRD 完全一致（不一致时我先判断：改 PRD 还是纠偏 UI）
- [ ] 我点了提交，列表里出现了新记录
- [ ] AI 分析区块有“Week2 接入”说明，样例有“演示数据”标识
- [ ] 我至少下过一条纠偏指令，并看到它被修好

## D1-L5 · 今日冲刺：项目建档与第一次提交

**使用方式**：Trae **通用对话**（三领域通用）。

```text
你正在协助我完成 FDE 训练 Day 1 · 今日冲刺。

目标：完成项目建档（README + Git 首次提交），为明天开始的开发立好规矩。

请按顺序执行：
1. 检查当前工作区（今天已产出 docs/PRD.md 和 design/prototypes/），创建 README.md 骨架，包含三节：项目简介（一句话说清这是什么系统）、团队角色（列出我在 Trae 里的 6 个智能体及分工）、当前进度（Day 1 已完成：PRD v1 + 交互原型）。
2. 初始化 Git 仓库（如果还没有），创建 .gitignore（排除 node_modules 与系统临时文件）。
3. 完成第一次提交，提交信息写 "day1: PRD v1 + 交互原型 V0.1"。
4. 创建 docs/D1_复盘.md，引导我填写三句话：今天最大的意外是什么；哪个角色的表现超出/低于我的预期；明天前端开发我最担心什么。

边界：不修改任何 PRD 和原型文件；Git 操作遇到报错先向我解释原因再给方案。

验收口径：README 三节齐全；Git 有至少一次提交；复盘文件创建。
```

**平台自检清单**：
- [ ] README 有三节内容
- [ ] Git 里有我的第一次提交
- [ ] 我写下了今天的复盘三句话
- [ ] 我能说明天要干什么（把原型变成真的页面）

## 附二：D1-L3「老板参考答案」（三领域 · 课件与 AI 导师共用）

> **用途**：① 课件示范——数字人在 L3 视频中演示"老板怎么答"；② AI 导师兜底——学员答不上来时按级提示；③ 一致性闸门——**所有答案锚定领域基线字段清单（Week1_Domain_Packs.md），防止学员随口改字段导致 D2/D3 跨天验收连环报错**。
> **教学要求**：参考答案不是照抄——学员至少要**否决或修改 PM 的一个问题**（如拒绝加角色、砍掉一个功能），体验"需求决策权在我"；PM 结课汇报才有素材。

### 领域 A：财务费用管理系统

| PM 可能问 | 建议回答（锚定基线） |
|---|---|
| 用户角色与权限 | 就两个角色：员工提交、财务负责人审核。30 人小公司，不要管理员 |
| 报销审批流程 | 一级审批：提交 → 财务审。状态就三个：待审核 / 已通过 / 已驳回；驳回后员工可修改重交。不要部门经理初审（**否决点**） |
| Week2 的 AI 计划分析什么异常 | 先规划基础版：金额异常高 + 类别与事由明显不符；Week1 只预留接口和演示样例 |
| 报销类型 | 差旅 / 办公采购 / 业务招待 / 培训 / 其他（与基线枚举一致，不增减） |
| 使用平台 | 同意只做 Web 端 |
| 发票/凭证上传 | 不上传，只填金额和说明——写进 PRD"本期不做什么"（**否决点**） |
| 最痛的点 | 数据乱查不到、费用结构看不清 → Week1 MVP 优先“列表可查 + 驾驶舱统计”，异常分析留到 Week2 |

### 领域 B：HR 员工诉求管理系统

| PM 可能问 | 建议回答（锚定基线） |
|---|---|
| 用户角色与权限 | 两个角色：员工提交、HR 负责人处理。不要管理员配置 |
| 要不要匿名提交 | 教学版不匿名，但请在 PRD 里标注"真实产品应考虑匿名选项"作为已知限制（**体现敏感度，是加分项**） |
| 诉求处理流程 | 状态四个：待处理 / 处理中 / 已回复 / 已关闭；不做多级流转 |
| 诉求类别 | 薪酬福利 / 考勤请假 / 办公环境 / 团队协作 / 职业发展 / 其他（与基线枚举一致） |
| 紧急程度怎么定 | Week1 由员工自评：一般 / 较急 / 紧急；Week2 再由 AI 对明显标错的给出提示 |
| Week2 的 AI 做什么 | 分类校验 + 处理建议（含回复措辞参考）；AI 建议必须人工确认，不得用于考核或惩罚 |
| 最痛的点 | 员工有意见憋着不说、走了才知道 → MVP 优先"低门槛提交 + 每条诉求有状态可追" |

### 领域 C：经营问题闭环系统（默认）

| PM 可能问 | 建议回答（锚定基线） |
|---|---|
| 用户角色与权限 | 两个角色：员工提交、经营负责人处理。不要复杂权限 |
| 问题类别 | 客户与市场 / 销售与回款 / 项目与交付 / 成本与费用 / 团队协作 / 其他（与基线枚举一致） |
| 影响程度怎么定 | 提交人自评：高 / 中 / 低；负责人可改 |
| 闭环流程 | 状态四个：待处理 / 处理中 / 已解决 / 已关闭；"已解决"必须由负责人确认，不能提交人自己关（**决策点**） |
| 要不要 @提醒/催办 | 不做消息通知，写进"本期不做什么"（**否决点**） |
| Week2 的 AI 做什么 | 按“结论→依据→风险→建议”结构生成原因分析与行动建议；Week1 只定义接口和展示位置，Week2 接入后仍需人工确认 |
| 最痛的点 | 问题在群里说完就没人管 → MVP 优先"每个问题有状态、有负责人、可追踪" |

### AI 导师 FAQ（D1-L3 配套，写入导师知识库）

1. **学员说"我不知道怎么回答 PM"** → 一级提示："想想你选这个领域的原因，你工作中最烦的那件事是什么"；二级提示：展示本领域参考答案中的"最痛的点"一行。
2. **学员想加字段/改枚举** → 提醒："可以改，但要同步改 PRD 字段清单，并告诉接下来每一天的智能体——改一处字段，后面三天都要跟着变。教学期建议先用基线。"
3. **PM 没提问直接开写 PRD** → 让学员回复 PM："先向我提问，我回答后再写。"（引用教学红线）
4. **学员照抄参考答案一字不改** → 不违规，但导师追问一句："这 7 个回答里，有没有一个你其实想改？改一处，这个项目就更是你的。"
5. **PM 提的问题超过 8 个或反复追问** → 让学员回复："范围收敛，按现有信息产出 PRD，遗留项标'待确认'。"——这也是范围管理的教学点。
