## 本地实操

### P1 · 生成后端

> @后端，请严格根据 API_Spec.md 和 DB_Schema.md 生成 backend/server.py、backend/data 目录、.env.example 和 RUNBOOK.md。使用 Python 3 标准库与 SQLite，不安装第三方依赖，不写真实密钥。先生成完整文件，不要替我启动服务。

### P2 · 审查文件

> 请只审查刚生成的文件：接口路径、字段、状态码和数据表必须与合同一致；必须有 GET /api/health；RUNBOOK 要写明启动、检查、停止和常见错误。只列问题，不修改。

确认后让 `@后端` 完整修正，再由学员打开终端。

### P3 · 启动与健康检查

按 `RUNBOOK.md` 运行：

```text
python backend/server.py
```

如本机使用 Python Launcher，则运行 `py backend/server.py`。保持终端窗口开启，在浏览器访问 `http://127.0.0.1:8000/api/health`。

### P4 · 单独验证接口

> 服务已启动。请根据 API_Spec.md 给我一条查询接口检查命令、一条提交接口检查命令和两条错误场景检查命令。每次只给一条，说明期望状态码和结果，等我粘贴实际结果后再继续。

### P5 · 重启持久化

在服务终端按 `Ctrl+C` 停止，重新启动，再查询刚提交的记录。把实际结果写入 `backend-acceptance.md`。

## 提交验证

- 四类文件存在；
- 健康检查成功；
- 查询、提交和两种错误均符合合同；
- 停止与重启步骤清楚；
- 重启后数据仍可查询。
