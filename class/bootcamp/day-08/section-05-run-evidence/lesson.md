# 第 5 节 · 实战：运行与证据（25′ · 实战）

> 🎬 视频位（现阶段：口播稿）
> AI 拿着你的说明书上岗。你的工作变成：派活 → 收货 → 按标准验收 → 留证据。

## 教学目标

- 完整运行一次 Skill：喂说明书 + 喂输入 → 收货；
- 按说明书验收段逐条验收（不是凭感觉）；
- 留下运行证据三件套：输入快照、产出物、验收结果。

## 流程安排（25′）

| 时段 | 内容 |
|------|------|
| 0–4′ | 讲解：运行 = 说明书 + 输入；证据三件套 |
| 4–14′ | 第一次运行 + 逐条验收 |
| 14–21′ | 迭代：验收不过 → 改说明书 → 重跑（最多 3 轮） |
| 21–25′ | 证据归档 + 迭代日志 |

## 运行方式（本课路径）

```
Agent Lab / 模型对话：
  ① 粘贴 Skill 说明书全文
  ② 粘贴输入数据（驾驶舱 curl 结果 / 数据文件）
  ③ 一句指令：「按这份 Skill 执行」
  ④ 收货
```

## 运行证据三件套（每次运行都留）

```
runs/<日期>-<skill名>/
├── input.md       输入快照（这次喂了什么数据）
├── output.md      产出物原文
└── verdict.md     验收结果：逐条判 ✓/✗ + 总判 + 改进了什么
```

为什么要留证据：**Skill 的信任是攒出来的**——连续 10 次验收通过，你才敢把「每次都看」降级为「抽看」（Day 9 编排时的信任分级就是这么来的）。

## 迭代闭环（和 Week 1 同款）

```
验收不过 → 定位：说明书歧义 or AI 执行偏差
         → 歧义：改说明书（多数情况）
         → 偏差：换表达/加示例/拆步骤
         → 重跑 → 再验收
```

> 关键认知：**验收不过大概率是说明书的锅，不是 AI 的锅**——就像换人测试里读者误解是作者的锅。

## 🎬 口播稿（约 6 段 · 待审）

> 同学们，这节 AI 拿着你的说明书上岗。你的工作变成四步：派活、收货、按标准验收、留证据——不再是自己打字，而是按标准验货。运行就是说明书加输入，一句按这份 Skill 执行，对吧。
> 运行方式很简单：Agent Lab 或模型对话里，先粘贴 Skill 说明书全文，再粘贴输入数据——驾驶舱 curl 结果或数据文件，最后一句按这份 Skill 执行。收货后别看感觉，看你写的验收段：逐条判 ✓ 还是 ✗，对吧。
> 每次运行留证据三件套：runs/日期-skill名/ 目录下，input.md 是输入快照，output.md 是产出物原文，verdict.md 是验收结果——逐条判 ✓/✗，加总判和改进项。Skill 的信任是攒出来的，连续十次通过，你才敢把每次都看降级成抽看，嘛。
> 验收不过怎么办？定位是说明书歧义还是 AI 执行偏差。歧义就改说明书——多数情况是这个；偏差就换表达、加示例、拆步骤，然后重跑。记住：验收不过大概率是说明书的锅，不是 AI 的锅。就像换人测试里读者误解，是作者的锅，对吧。
> AI 没按步骤做、直接跳到生成？在说明书开头加严格按步骤顺序执行，每步完成后简述结果。每次跑结果不一样？正常，模型有概率性；验收标准管的是底线——结构、数字、意图，波动在标准内即可。今天目标：连续两次验收全过，对吧。
> 证据归档，迭代日志写清楚改了什么、重跑了几次。下一节是第七天验收——Skill 三问口试，导师看证据链。带走一句：Skill 的信任是攒出来的，证据三件套就是你的本金，嘛。


## 常见懵点

- 「AI 没按步骤做，直接跳到生成？」→ 在说明书开头加「严格按步骤顺序执行，每步完成后简述结果」；执行轨迹也是证据；
- 「每次跑结果不一样？」→ 正常（概率性）；验收标准管的是底线：结构、数字、意图——波动在标准内即可；
- 「要跑几次才算好？」→ 今天：连续 2 次验收全过即达标；第 6 节验收看证据。
