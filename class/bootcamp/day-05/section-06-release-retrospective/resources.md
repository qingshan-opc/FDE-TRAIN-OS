## 名词解释

| 名词 | 小白解释 |
|---|---|
| 发布证据 | 能证明确定版本已运行并可恢复的真实记录 |
| 业务终验 | 根据最初用户问题和验收标准判断价值是否达成 |
| 复盘 | 根据真实过程总结有效做法、问题和下次改进 |
| 退回条件 | 当前岗位不能继续时，明确回到哪个责任岗位补什么 |

## 六岗位接力地图

| 岗位 | 主要输入 | 主要输出 | 下一棒 | 常见退回 |
|---|---|---|---|---|
| 产品经理 | 用户回答、第一版证据 | PRD 与产品交接 | UI | 用户或验收不清 |
| UI | PRD 与产品交接 | 交互说明与 UI 交接 | 前端 | 需求冲突 |
| 前端 | UI 合同与现有代码 | 页面、前端验收与交接 | 后端 | 状态或合同缺失 |
| 后端 | 产品规则、前端合同、数据合同 | 接口、数据、后端验收与交接 | 测试 | 规则或数据风险 |
| 测试 | 全部交接与运行入口 | 计划、缺陷、报告 | 运维 | 阻塞缺陷或证据缺失 |
| 运维 | 测试通过版本与部署说明 | 发布计划与发布日志 | 产品经理 | 未通过发布闸门 |

## 可迁移六步清单

1. 先问清楚，再冻结范围；
2. 先说明交互，再写页面代码；
3. 先列改动，再让前端执行；
4. 先定接口与数据，再让后端执行；
5. 先定计划，再用证据判断测试；
6. 先定发布与回退，再回产品终验。
