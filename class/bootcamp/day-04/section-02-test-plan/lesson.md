# 第 2 节 · 从需求生成测试计划

## 本节目标

- 检查测试所需的六类输入；
- 把 PRD 验收标准翻译成测试用例；
- 按风险排列执行顺序；
- 亲自把住“确认测试”的人工闸门。

## 测试输入

| 文件 | 测试读取什么 |
|---|---|
| `PRD.md` | 用户、范围、业务规则和验收标准 |
| `API_Spec.md` | 成功和错误请求应返回什么 |
| `DB_Schema.md` | 数据应怎样保存与关联 |
| `RUNBOOK.md` | 怎样启动、停止和排查 |
| `backend-acceptance.md` | 开发岗位已经自检了什么 |
| `backend-handoff.md` | 已知限制、风险和测试重点 |

缺文件时停止，不让测试从页面外观猜标准。

## 从风险决定顺序

先测系统能否启动、核心流程能否走通。再测数据丢失、隐私泄露和错误处理。普通文字或轻微样式问题放在后面。计划还要明确哪些内容本轮不测。

## 测试计划结构

每条用例写编号、优先级、前置条件、操作步骤、预期结果、证据位置和主要责任岗位。计划先展示给学员，确认范围没有漏项后，由学员本人回复“确认测试”。

## 口播稿

同学们好，我是你们的老师404。正式测试前先制定计划。测试要读取需求、接口、数据、运行手册和两份后端交接记录。文件齐全后先复述主流程、业务规则和风险，再列测试目录。高风险内容优先，系统不能启动、数据丢失和隐私泄露都要排在前面。最后把目录展开成 test-plan.md。你核对每条 PRD 验收标准都有用例后，再亲自回复确认测试。同学们，本节先到这里。
