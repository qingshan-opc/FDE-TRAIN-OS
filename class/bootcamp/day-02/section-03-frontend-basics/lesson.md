# 第 3 节 · 用人话看懂前端三件套

## 本节目标

- 用结构、样式、行为理解 HTML、CSS 和 JavaScript；
- 知道浏览器怎样找到三个文件；
- 理解演示数据与真实数据的区别；
- 能识别加载、空数据、成功、错误四种状态。

## 三个文件，三种职责

| 文件 | 人话解释 | 本项目中的例子 |
|---|---|---|
| `index.html` | 页面骨架 | 标题、筛选区、表单、列表、按钮 |
| `styles.css` | 页面衣服 | 颜色、字号、间距、布局、悬停和禁用 |
| `app.js` | 页面动作 | 点击、筛选、校验、状态切换、演示数据 |

HTML 通过 `<link>` 找到 CSS，通过 `<script>` 找到 JavaScript。路径写错时，页面可能有内容但没样式，或者按钮完全没有反应。

## 演示数据不等于真实数据

Day2 可以用虚构或脱敏数据验证页面，但要集中放在 `app.js` 顶部，并明确标记。后端接入时，开发者能快速找到“替换演示数据”的位置。

不要把真实公司数据、个人隐私或密钥写进前端。浏览器里的前端文件最终会被用户看到，不是保存秘密的地方。

## 四种数据状态

| 状态 | 用户看到什么 |
|---|---|
| 加载 | 正在处理，不让用户误以为页面卡死 |
| 空数据 | 没有记录，并告诉用户下一步能做什么 |
| 成功 | 数据或操作结果正常展示 |
| 错误 | 说明失败并提供重试或返回办法 |

## 只学会一个调试动作

按 `F12` 打开浏览器开发者工具，查看“控制台”。出现红色错误时先截图或复制错误，告诉 `@前端`：在哪个页面、做了什么、看到什么、预期什么。小白不需要先读懂每一行错误。

## 口播稿

同学们好，我是你们的老师404。开始生成前端前，我们只用几分钟认识三个文件。不要背代码，把它们想成一个人：HTML 是骨架，决定页面有什么；CSS 是衣服，决定它长什么样；JavaScript 是动作，决定点击以后发生什么。

如果页面有文字但特别丑，通常先检查 CSS 有没有正确连接。如果页面看起来正常但按钮没反应，通常先检查 JavaScript 和浏览器控制台。你不需要立刻会修，只要能把现象说清楚，就能指挥前端智能体处理。

今天的数据仍然是演示数据，不代表后端已经接通。一定把它集中放在 app.js，并且不要放真实隐私和密钥。前端文件在浏览器里运行，用户有机会看到它们。

最后记住四种状态：加载、空数据、成功、错误。只做成功页面，就像只设计晴天开车，不考虑堵车、没油和故障。真实系统一定会等待、会没数据、也会失败。今天先把这些状态做出来，明天后端才能知道每种结果怎样交给页面。同学们，本节先到这里。
