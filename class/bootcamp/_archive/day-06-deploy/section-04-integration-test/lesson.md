# 第 4 节 · 实战：上线前集成测试清单（25′ · 实战）

> 🎬 视频位（现阶段：口播稿）
> 上线不是点「部署」按钮，是先过一张清单。这张清单是你五天来所有验收标准的合集——全绿，才放行。

## 教学目标

- 理解集成测试的定位：测「四层接起来对不对」，不是测单层；
- 用清单在**本地**完成一次全链路体检（先本地绿，再上线）；
- 把清单变成可复用资产：以后每次上线前都跑它。

## 流程安排（25′）

| 时段 | 内容 |
|------|------|
| 0–5′ | 讲解：清单的结构——四层 + 三态 + 降级 + 安全 |
| 5–20′ | 逐项执行清单，记录结果，修复红灯 |
| 20–25′ | 清单入库（`docs/release-checklist.md`），准备部署 |

## 上线前集成测试清单（模板）

```
□ 前端：六区块渲染正常；控制台无红错
□ 接口：curl /api/kpi、/api/exceptions、/api/summary 均 200
□ 数据：UPDATE 一行 → 页面刷新同步（活数据验证）
□ LLM：摘要为 AI 版（source=ai），数字与库一致（抽 2 个数核对）
□ 三态：空态（清空明细）与错误态（停接口）正常出现
□ 降级：断网关 → 摘要降级版 + 标识；恢复 → AI 版回来
□ 安全：git grep 无密钥；.env 已忽略；调试模式已关
□ 配置：平台变量清单就绪（照第 2 节清单）
□ Git：工作区干净，全部已提交
```

执行纪律：**红灯先修再上**——上线后修同一个问题，成本是本地的十倍（改→提交→构建→部署→验证）。

## 🎬 口播稿（约 1 分钟）

> 「上线前最后一道手续：集成测试清单。注意它的定位——不是测单层，是测四层接起来对不对。你五天的验收标准都在这张单子上：六区块、三个接口、活数据、AI 摘要、三态、降级、安全、Git。
> 纪律只有一条：红灯先修再上。上线后修同一个问题，成本是本地十倍。
> 这张单子跑完入库存档，以后每次上线前都跑它——它是你的资产，不是今天的作业。」

## 常见懵点

- 「每天不是都验收过了吗，还要清单？」→ 每天验的是「当天那层」；清单验的是「接起来」——接口改了契约忘同步前端，只有集成测试能抓；
- 「清单要自动化吗？」→ V2 可以（脚本化 curl 检查）；今天手动跑——先知道查什么，再谈自动查；
- 「发现红灯但快下课了，能上吗？」→ 不能。带着红灯上线是本课唯一的「不可」——改天再上，清单等你。
