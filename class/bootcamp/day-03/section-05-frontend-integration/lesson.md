# 第 5 节 · 让前端接入真实接口

## 本节目标

- 把 `API_Spec.md` 和 `RUNBOOK.md` 正式交给 `@前端`；
- 先列演示数据与接口的替换映射；
- 跑通查询、提交、刷新和错误状态；
- 按责任岗位修复联调问题。

## 联调不是“两个程序都能打开”

联调要证明用户在页面上的动作能经过 API 到达后端和数据库，结果再正确回到页面。至少完成一次查询、一次提交、一次刷新后复查，并观察加载、空、成功和错误状态。

## 改动边界

前端先读取接口合同与运行手册，列出“页面动作 → 当前演示数据 → 目标接口 → 页面更新位置”。确认后只修改前端的数据调用，不擅改设计、PRD、API 合同和后端代码。

## 问题归属

| 现象 | 优先切回岗位 |
|---|---|
| 请求方法、路径、字段发错 | `@前端` |
| 后端响应字段、状态码、存储错 | `@后端` |
| 需求本身不清楚 | `@产品经理` |
| 页面反馈不符合设计 | `@UI` |

每次修复后重跑完整主流程，避免修好一个点又破坏另一个点。

## 口播稿

同学们好，我是你们的老师404。后端单独通过后，才进入前后端联调。先切换到 @前端，把接口合同和运行手册交给它，让它列清哪些演示数据要换成哪个接口，确认后再改。你本人同时保持后端服务运行，打开页面完成查询、提交和刷新。出错时不要在当前岗位乱改：请求方法、路径和字段错，回前端；响应、状态码和存储错，回后端。修完必须重跑完整主流程。这样你学到的不是碰运气，而是有责任边界的工程协作。同学们，本节先到这里。
