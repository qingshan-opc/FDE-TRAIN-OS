# Week 1 · Day 3 课程包：学员任务提示词（三领域通用 · V3.1）

> 关联文档：`docs/Week1_Course_Outline.md` Day 3（教学目标与验收项）。
>
> **Day 3 主线**：@后端工程师 建库 → 实现真实业务接口（含看板统计） → 为 Week2 预留 AI 接口 → 业务数据全链路联调（含驾驶舱看板）。**本日为全周难度峰值**，但不接模型网关，学员无需准备任何模型 Key。
> **前置状态**：前端 V0.5（四页面含驾驶舱看板 + mock + 接口契约 `docs/D2-L4_接口契约.md`）。

## D3-L1 · 看懂全栈：六部分与一条数据链路

**使用方式**：Trae **通用对话**。

**学员指令**：

```text
请阅读当前工作区（docs/PRD.md、design/prototypes/、前端代码），为我的项目绘制全栈项目地图，保存为 docs/D3-L1_项目地图.md。内容：六部分（业务需求/前端/后端/数据库/AI预留/测试与部署）各自的证据路径与当前状态；一条完整业务数据链路（从提交、入库、列表、详情到驾驶舱统计更新）；AI 部分明确标“Week2 待接入”。不修改任何代码。
```

**教学要点**：这是本周唯一一节"纯认知课"——但用的是**学员自己的项目**（已有 PRD、原型、前端），比 Day 1 空讲结构有效十倍。记忆句正式登场：**AI 负责加速，你负责方向、判断和验收。**

**平台自检清单**：
- [ ] 项目地图六部分齐全，每部分有真实文件证据
- [ ] 我能指着图说清数据链路：提交 → 前端 → 接口 → 数据库 → 列表/详情 → 看板统计更新
- [ ] AI 部分明确标“Week2 待接入”（诚实标记）
- [ ] 我能说出：AI 编程工具生成页面后，验收责任仍在学员

## D3-L2 · 数据库：把字段清单变成表

**使用方式**：Trae 对话中 **@后端工程师**。

**学员指令**：

```text
@后端工程师 请按 docs/PRD.md 的字段清单为项目建数据库表/模型：字段、类型、必填以 PRD 为准，状态用枚举，加主键和创建/更新时间。建好后把表结构讲给我听，并保存说明到 docs/D3-L2_数据表说明.md。
```

**教学要点**：表结构不是技术决定，是 PRD 的翻译——字段清单（D1）→ 原型（D1）→ 页面（D2）→ 数据表（D3），**同一个东西的四次出现**，学员第四次核对它。

**平台自检清单**：
- [ ] 表字段与 PRD 字段清单逐一对应（对照领域基线）
- [ ] 状态字段是枚举，值与 PRD 一致
- [ ] 有主键和创建/更新时间
- [ ] 我听完讲解后能复述每个字段是干什么的

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| 智能体加了 PRD 没有的字段 | "这个字段 PRD 里没有——要么说服我加进 PRD，要么从表里删掉。" |
| 状态用自由文本 | "状态字段要用枚举，值必须和 PRD 的状态定义一致。" |

## D3-L3 · 实现提交、列表与看板统计接口

**使用方式**：Trae 对话中 **@后端工程师**。

**学员指令**：

```text
@后端工程师 按 docs/D2-L4_接口契约.md 实现"提交""列表"和"看板统计"三个接口，数据真实写入/读出数据库，统计接口按真实数据聚合计算。完成后用实际请求演示：提交一条 → 列表能查到它 → 看板统计的数字跟着变。
```

**教学要点**：业务规则放后端——前端可以美化，但"金额必须大于 0"这种规矩必须在接口层再守一次（呼应 D3-L1 测验题）。

**平台自检清单**：
- [ ] 提交接口按契约返回结构，非法输入被拒绝（参数校验）
- [ ] 提交一条后，列表接口能查到
- [ ] 看板统计接口返回的数字和列表里的真实数据对得上（我抽查过）
- [ ] 我看到了请求/响应的证据（日志或测试工具截图）
- [ ] 接口层也校验了必填规则（不只靠前端）

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| 返回结构和契约不符 | "响应结构和 docs/D2-L4_接口契约.md 不一致，请以契约为准。" |
| 接口不做校验 | "我提交了空标题也成功了——业务规则必须在后端再校验一次。" |
| 报错信息是堆栈 | "接口报错要返回契约约定的错误结构，不要把程序堆栈抛给调用方。" |

## D3-L4 · 为 Week2 预留 AI 分析接口

**使用方式**：Trae 对话中 **@后端工程师**。

**学员指令**：

```text
@后端工程师 按 docs/D2-L4_接口契约.md 为“AI 分析”预留接口。Week1 不调用模型：接口返回明确的 501 AI_NOT_CONNECTED（或等价状态）和“AI 能力将在 Week2 接入”说明；同时在 docs/D3-L4_Week2_AI交接.md 写清未来 Agent 需要读取的字段、返回结构和写回位置。不要返回固定分析文案冒充 AI 结果。
```

**教学要点**：预留接口不是“少做一步”，而是在学习真实项目如何分期。Week1 先把数据和工作流做稳；Week2 再把专业 Skill、分析 Agent 和模型接进同一接口。演示数据、真实业务数据和 AI 结果必须明确区分。

**平台自检清单**：
- [ ] 预留接口明确返回 AI_NOT_CONNECTED，不返回伪造分析
- [ ] 详情页标题为“AI 分析区｜Week2 接入”
- [ ] 样例内容醒目标注“演示数据”
- [ ] Week2 交接文档说明未来输入、输出和写回位置
- [ ] 预留接口结构与契约一致

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| 接口返回固定分析文案 | "Week1 不能用固定文案冒充 AI，请返回 AI_NOT_CONNECTED，并把样例留在前端且标为演示数据。" |
| 页面写成 AI 已生成 | "真实 AI 要到 Week2 才接入，请改为'AI 分析区｜Week2 接入'。" |
| 没有 Week2 交接说明 | "请写清未来 Agent 要读取哪些字段、返回什么结构、结果写回哪里。" |

## D3-L5 · 今日冲刺：全链路联调 + V0.8 演示

**使用方式**：Trae 对话中 **@前端工程师**（切换数据源）+ **通用对话**（冒烟与提交）。

**学员指令①（联调）**：

```text
@前端工程师 把四个页面（含驾驶舱看板）的业务数据源从 Mock 切换到 docs/D2-L4_接口契约.md 的真实接口。AI 分析样例可以保留，但必须标“演示数据”，页面标题保持“AI 分析区｜Week2 接入”。切换后我会完整走一遍业务流程，遇到问题我们按契约定位责任。
```

**学员指令②（冒烟与建档）**：

```text
请帮我完成三件事：
1. 执行一次冒烟测试：启动项目 → 提交一条 → 确认 SQLite 已保存 → 列表看到它 → 打开详情 → 打开驾驶舱看板核对统计数字已更新；同时确认 AI 区显示“Week2 接入”且样例标“演示数据”。把每步结果记到 docs/D3_冒烟记录.md。
2. 把今天发现的已知问题整理成 docs/D3_缺陷清单.md（现象/影响/临时方案，至少 1 条；没有就诚实写"暂无"并说明验证过程）。
3. 提交代码，提交信息 "day3: 全链路打通 V0.8"，更新 README 进度。
```

**教学要点**：联调是两个角色按契约对表，**你是主持人**——出问题先查契约，再定责任。能演示 ≠ 能交付：记录已知缺陷是专业行为，不是丢脸。

**平台自检清单**：
- [ ] 提交 → SQLite → 列表 → 详情 → 看板数字更新，业务数据全流程走通
- [ ] 业务 Mock 已移除或隔离（AI 样例仍可保留，但必须标“演示数据”）
- [ ] AI 区明确“Week2 接入”，预留接口不伪造结果
- [ ] 冒烟记录步骤齐全
- [ ] 缺陷清单含现象/影响/临时方案
- [ ] Git 有当日提交

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| 切真接口后页面全空 | "列表页接真接口后没有数据，请先在接口层验证有数据返回，再排查前端渲染——按契约分段定位。" |
| 跨域/端口报错 | "浏览器报跨域错误，请解释原因并给出前后端任一侧的修复方案。" |
| 学员分不清是谁的错 | "请先直接请求接口确认后端正常，再检查前端请求参数——把验证过程告诉我。" |

## 附：平台侧配置提醒（内容团队）

1. **数据库和业务接口是 D3 的生命线**：开课前巡检 Node、SQLite 驱动、端口和课程初始项目；本周不依赖模型网关。
2. **AI 导师知识库 D3 重点覆盖**：建表字段不一致、接口 500、跨域、业务 Mock 切换遗漏、AI 预留接口误返回固定结果——每类至少 1 条“错误诊断”级提示。
3. **防"囫囵过关"**：D3-L5 冒烟记录要求五步证据，防止学员"智能体说通了就信了"——呼应教学红线：验收权在你。
4. 预估 D3 卡点 Top 3：数据库驱动安装、跨域/端口报错、业务 Mock 切换遗漏——全部预置“错误诊断”级提示。
5. **情绪管理提示（写进当日课件结尾）**：D3 是全周最容易挫败的一天——"今天卡住不代表你不行，代表你在做真正的工程。FDE 的简历上没有'从没报错'的人。"
