## 一、为什么先讲发展史

同学们以后要进入这个行业，必须理解一件事：**今天这个 AI 时代不是凭空来的，它是一波一波技术浪潮推过来的。** 看懂每一波浪「解决了什么问题、淘汰了什么人、成就了什么人」，你就知道自己在哪、下一步往哪走。

## 二、互联网发展的四个时代

### 第 1 波 · 信息化（1990 年代）：电脑进办公室

- 计算机刚普及时还是「大头」CRT 显示器，后来才逐渐变成液晶屏。
- 核心变化：**算盘 → 电脑记账**。以前手工/算盘记账的工作，全部搬进电脑。
- 关键词：替代手工、效率工具。

### 第 2 波 · 网页时代（2000 年代）：生意搬上网

- HTML（超文本标记语言）普及，大家开始做网页。
- 企业通过网页**展示自己的店面**，别人通过邮件等方式联系你、下单，大部分交易仍走线下快递。
- 核心变化：信息从「自己看」变成「给全世界看」。

### 第 3 波 · 云服务时代（2010 年代）：机房消失

- 云的概念很早就有，亚马逊（AWS）是最早把云服务做起来的厂商。
- 以前企业**自建机房**；云时代机房不自建了，全部迁到云厂商。
  - 传统服务器厂商把服务器卖给云厂商；
  - 云厂商把服务器**虚拟化**，把底层的网络、存储包装起来，**按需提供服务**。
- 核心变化：基础设施变成「水电煤」，谁按需取用，谁轻装上阵。

### 第 4 波 · 移动互联网时代（与云同期）：口袋里的办公室

- 智能手机取代翻盖机——本质是**操作系统的进步**衍生的新物种。
- 手机玩游戏、聊天；4G → 5G 基础设施起来后，**办公也搬到了手机上**。
- 标志性应用：微信（沟通）、钉钉（办公，出现更晚）。

## 三、AI 时代的到来

### 大模型的前史

- OpenAI 大约 2015 年开始研发 GPT 系列（早期马斯克参与投资，后退出），之前一直在做**小模型**。
- 2018 年 GPT-1 小火过一次；百度当时做了「All in AI」的决策——**赶了个早场，但没吃上饭**。

### 划时代的一刻：泛化能力

- ChatGPT 出来之后（2022 年底爆发、2023 年全民使用），人类第一次见识到：
  > **模型经过训练学习之后，具备了「泛化」能力——它能做出很多没有被专门训练过的事情，初步有了简单的思考能力。**
- 规律：**模型越大，泛化能力越强，越智能。**
- 落地形态：让 AI 帮你写资料、向 AI 学习——这就是当下时代的基本动作。

### 国产厂商的贡献

- **DeepSeek：第一次把「蒸馏 + 思考（推理）」引入主流开源大模型**，成为后来整个大语言模型的重要底座范式。

## 四、人使用 AI 的四次方式跃迁（本课主线）

> 这一段是全课的核心：同样是「用 AI」，方式已经换了四代。你处在哪一代，决定你的产出上限。

### 第 1 代 · 对话搬运：一句一句喂

- 最早用 GPT 做架构的方式：一句一句把东西喂给它，对话，然后**复制粘贴**出来用。
- 特征：AI 是「聊天窗口里的顾问」，人是搬运工。

### 第 2 代 · 提示词工程接系统：给应用「接入大脑」

- 开始研究怎么把 AI **接进系统**：在提示词里写死要求，让模型返回**固定格式**（API 式文本），程序解析后显示在页面上。
- 这样一个应用就是「接入了大脑的应用」。
- 痛点：一个应用可能要维护**几十套提示词**，而且输出**很不稳定**。

### 第 3 代 · Tool Call 与 Vibe Coding：模型自己动手

- Agent 时代开启：AI 可以**扮演角色**、进行多角色/多轮协作。
- 关键能力——**Tool Call（工具调用）**：把本地工具「丢」给模型，只要你实现了工具接口，模型会**自己思考、自己决定怎么调**，串联完成一整串任务。
- 这就是 **Vibe Coding** 时代：打开编码引擎、开黑窗口（CLI），天天跟 AI「斗智斗勇」——一边骂一边用，含着泪在用。

### 第 4 代 · Agent 原生系统：把一切接起来（讲师提出的概念）

> 「Agent 原生系统」是讲师自己的理解与提法。

- Agent 开始把**所有东西接入起来**，Tool Call 只是其中之一：
  - **记忆机制 / 记忆引擎**
  - **Harness（智能体运行架构）**
  - **RAG 知识库**
  - **企业内部流程性资产**
- 目标：让 Agent **执行非常长串的任务**——这是我们现在所处的时代。

## 五、核心概念卡（术语速查）

| 术语 | 一句话解释 |
| --- | --- |
| 信息化 | 用电脑替代手工（算盘→电脑记账） |
| 虚拟化 | 一台物理服务器切成多份按需分配，云服务的技术底座 |
| 云计算 | 把服务器、网络、存储包装成按需取用的服务 |
| 泛化能力 | 模型做出「没被专门训练过的事」的能力 |
| 蒸馏 | 把大模型的能力压缩「教」给小模型的技术 |
| 推理（思考）模型 | 先想再答、显式推演过程的模型范式（DeepSeek 带火） |
| 提示词工程 | 用写死的提示词约束模型输出格式，供程序解析 |
| API | 程序之间约定好的调用接口/数据格式 |
| Tool Call | 模型自主决定并调用外部工具的能力 |
| Vibe Coding | 以自然语言驱动 AI 写代码的开发方式（CLI 黑窗口时代） |
| Agent | 能扮演角色、自主规划并执行多步任务的 AI 实体 |
| Harness | Agent 的运行架构/宿主环境（工具、记忆、权限的承载层） |
| RAG | 检索增强生成：先查知识库再回答，让模型「开卷考试」 |
| Agent 原生系统 | 把工具、记忆、知识库、流程全部接入 Agent，执行长任务（讲师提法） |

## 七、教学建议（落课参考）

- **对应课程位置**：Day 1 世界观课（可替换/增强现有 1.1「世界观快通」），或作为公开课首节。
- **配图建议**：
  1. 五时代演进时间轴（信息化→网页→云→移动→AI），每代一个标志物（算盘/HTML 页面/机房/翻盖机→智能机/对话气泡）；
  2. 「使用 AI 的四代方式」对比图（复制粘贴 → 提示词管道 → Tool Call 链路 → Agent 原生系统全景：工具+记忆+RAG+流程）；
  3. Agent 原生系统架构示意（中心 Agent，四周挂 Tool Call / 记忆引擎 / Harness / RAG / 企业流程）。
- **知识确认题方向**：
  - 「泛化能力」指的是什么？
  - 云厂商把物理服务器变成按需服务靠的是什么技术？
  - Tool Call 与提示词工程接系统的本质差别？
  - 按讲师的定义，「Agent 原生系统」包含哪些组成？
- **讲师自述待研究点**：Agent 多角色协作部分（口述中「AI 这块可能不太对，你研究一下」），建议补充 multi-agent 协作的准确定义后再入正式讲义。
