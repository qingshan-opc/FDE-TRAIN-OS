## 这一天在解决什么

昨天你是产品经理，交出了一份 PRD.md——「部门周报助手」要做什么、给谁用、怎么算成功，都写清楚了。但 PRD 只回答了「做什么」，没回答「怎么搭」。今天换一个角色：架构师。

架构师不是「最会写代码的人」，而是「最会做取舍的人」。团队几个人、预算多少、预期多少人用、出了事谁半夜爬起来修——这些约束摆上桌，方案几乎是被逼出来的。今天你会反复听到一句话：「没有最好的架构，只有最合适的架构。」

上午的节奏分两段：先用三节概念课把「取舍」「四层架构」「单体/微服务/Serverless 选型」讲透——这是你明天做前端、后天做后端时的地图；然后进实战，解剖 Architect_Agent_Prompt.md，用它为你的周报助手生成一份 architecture.md：架构风格选择 + 否决理由、分层图、3 条 ADR。

ADR（架构决策记录）是今天的灵魂产物。AI 时代，生成一个方案只要十秒，但「为什么选它、放弃了什么」才是团队真正需要的资产。写下 ADR，就是把你和 AI 对话里的取舍固化成可复审的文档。

> 昨天的 PRD.md 已自动带入今天的工作区——「昨天你定义了做什么，今天你决定怎么搭」。
