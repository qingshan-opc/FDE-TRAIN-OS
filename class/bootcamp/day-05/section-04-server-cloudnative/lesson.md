## 讲授要点

### 先认识主角：服务器和个人电脑差在哪

大家平常都用个人电脑干活。那服务器和它有什么区别？

- **严格意义上讲**：没什么本质区别——都是操作系统 + 上面跑着程序；服务器只是让那段程序**一直持续运行**。
- **不严格意义上讲**，差在三处：
  1. **系统不一样**：服务器常见 Linux，早期也有 Windows Server 2003 这类「服务器版」系统；个人电脑多是 Windows / macOS；
  2. **一直开着，不关机**：你的电脑可能关机睡觉；服务器 7×24 醒着——没人知道用户几点来；
  3. **屏幕和机房渐渐消失**：早期服务器还有屏幕，方便现场维护；后来屏幕不要了、机房也不用你自己建了——**通过网络跟它打交道**。

一句话记住：**服务器就是一台一直开着、专门给别人提供服务的电脑。** 你做的部门周报助手，合盖就没了；想让全部门用，就得搬上去——行话叫「部署」或「上云」。下面五站，就是这台电脑的搬家史。

### 第一站：物理机——桌底下那台真电脑

最早：公司自己买一台电脑，塞桌底或小机房，插电 24 小时开着。
- **解决了什么**：总算有个东西能让全公司访问；
- **又带来什么**：顶配机器平时可能只用 5% 力气，95% 白花钱；活动一来又不够——买多了浪费，买少了挨骂。

### 第二站：虚拟机——一台物理机里跑多种系统

很多人听过「双系统」：一台电脑装 Windows 又装 Linux，开机选一个。更方便的做法是装 **VMware** 这类软件，在 Windows 里再跑一个 Linux，甚至跑 Kali 这类专门做安全实验的系统——**不必重启切换**。

这种「在一台物理机上运行多种 / 多个系统」的技术，就叫**虚拟机**。早期常见是软件虚拟化（如 Windows 上的 VMware）；后来主流变成**硬件 / 底层虚拟化**：由系统底层拆分出多台「假电脑」，性能更接近真机——虚拟机一般仍略逊物理机，但已经能到很高水准。

- **解决了什么**：一台物理机的力气被榨干，不浪费；不同系统互不打扰；
- **又带来什么**：每台虚拟机都背一整套操作系统——又胖又慢，搬起来沉。

### 第三站：容器——软件界的「集装箱」（Docker 最出名）

去过宁波港的同学可能见过：码头上一排排大型集装箱。早期没有集装箱时，货直接堆上船，到岸拆不出、分不清——一艘大船要服务很多企业，乱套。后来变成：**一个企业、一个集装箱，运到目的地再卸**——物流标准化了。

软件里也有同构的包装：**容器**（最有名是 Docker，还有别的容器技术）。你把开发好的应用装进一个「箱子」，箱子里只跑你的应用及其依赖；箱子到哪，应用就在哪跑。「在我电脑上能跑，到你那就不行」这句话，从此大幅减少。

可以把它看成虚拟机的**轻量进化版**：不再为每个应用背一整套操作系统，共享底层，所以更轻、更快。
- **解决了什么**：搬家不散架，启动只要几秒；
- **又带来什么**：公司一火，箱子从 3 个变 3000 个——靠人管不过来。

### 第四站：Kubernetes（K8s）——几千个集装箱的自动调度

几千个集装箱怎么管理？靠人站码头记账不行。海运侧会用自动化（识别、搬运机器人）把箱子搬到对应船上；软件侧对应物就是以 **Kubernetes（简称 K8s）** 为代表的**容器编排引擎**。

在 K8s 眼里，容器只是编排最底层的一块砖；对外服务、流量、内部调用、文件存储、设备驱动等，统一由平台管。它干的事包括：自动复制「集装箱」、挂了补新的、流量大了多开、小了关掉。
- **解决了什么**：几千个容器也能自动管好；
- **又带来什么**：这套系统本身很复杂——养懂 K8s 的团队不便宜。小团队几箱货，不必先建深水港。

### 第五站：Serverless——按「服务」计费，不是按「整台机器」

云原生时代还衍生出另一条线：**Serverless**（无服务器）。名字唬人——不是真没服务器，是云厂商全包了；你关心的是「一段服务被调用」，不是「哪台机器」。

你可能已经碰过一种形态：微信小程序里的**云函数**——把具体能力包成一段可调用的服务（常见用 Node.js 一类运行时）。它是**以服务为粒度**，不是以「整个应用 / 整台机」为粒度。

- **解决了什么**：零运维起步、按调用付费，没人用就不花钱；大厂生态里很常见；
- **又带来什么**：冷启动、厂商绑定；传统企业内部系统未必用得上——先听懂概念，选型时再决定要不要碰。

### 「云原生」一句话

把五站连起来：**「云」就是租别人的服务器用（像用电网，不自己发电）；「云原生」就是打娘胎里就按云的方式设计的应用**——一出生就装成集装箱、就接受调度、就能按量扩展，而不是半路从桌底搬上来的老系统。

### 对你的意义

你的部门周报助手，后面就要「上云」。今天不必会操作每一站——只要别人说「容器化了吗」「要不要上 K8s」「其实 Serverless 就够」时，你听得懂他在说哪一站、那一站省的是钱还是心、贵的是人还是机器。

### 部署上线：最小必要（从 Day 6 并入的概念）

你的驾驶舱不能只活在 localhost。部署 = 把应用从「我电脑上的进程」变成「互联网上谁都能访问的服务」。

**管线五步**（托管平台帮你跑，但你要看得懂）：

```
① 代码    Git 仓库是唯一事实源——没进 Git 的东西不存在
② 构建    装依赖、打包——「在我机器上能跑」从这里开始消失
③ 镜像    把应用+环境冻成一个标准包裹（容器的一句话）
④ 运行    云上的机器启动这个包裹，7×24 不关机
⑤ 访问    一个公网 URL，谁的浏览器都能打开
```

**环境与配置分离**：密钥/令牌不进 Git、不进镜像——从环境变量读。上线前三不：密钥不进仓库、真实业务库不上公网、调试模式不上线。

**实战闸口**（验收在 S07/GATE 5）：换设备打开 URL，六区块正常；线上断网关测降级。今天 Lab 先练命令行八句 + 本地 `curl`；公网部署在后续实战日完成，但**概念和检查项今天就要认识**。

### 上手：命令行八句话（今天 Lab 的真功夫）

服务器没屏幕、住机房——你摸不到鼠标，只能通过网络发「文字」过去，这行文字就是命令。
别被黑窗口唬住：命令行只是「用文字和电脑对话」，常用的一只手数得过来：

| 命令 | 干什么 | 什么时候用 |
|------|--------|-----------|
| `pwd` | 我在哪（当前目录） | 刚连上服务器先定位 |
| `ls -l` | 这里有什么 | 看部署的文件在不在 |
| `mkdir -p app/logs` | 建文件夹（父目录一起建） | 给日志安家 |
| `cd app` | 走进文件夹 | 去应用目录干活 |
| `curl localhost:8000/healthz` | 敲服务的门，看应不应 | 验证服务活着没（200 = 活着） |
| `tail -f logs/server.log` | 实时盯着日志看 | 出问题时第一动作（Ctrl+C 退出） |
| `chmod +x deploy.sh` | 给脚本执行权限 | 报 permission denied 时 |
| `docker ps` | 看哪些容器在跑 | 第三站的「集装箱」亲眼版 |

**今天的 Lab 就是终端实验台**：在仿真服务器上把这八句真敲一遍（敲错不会坏任何事），
再把周报助手启动并用 `curl` 验证它活着。规矩一条：不许复制粘贴——命令行是肌肉记忆。卡住查资源区「命令手册」。

三个新人必踩的坑：
1. **大小写敏感**：`Logs` 和 `logs` 是两个文件夹；
2. **空格是分隔符**：路径带空格要加引号；
3. **`tail -f` 不是卡死**：它在「跟着看」，退出按 `Ctrl+C`。

## 常见懵点（导师备用）

- 「云是不是就是别人的电脑？」→ 对，业内大实话（There's no cloud, it's just someone else's computer）——后半句是：别人有专业机房、专业运维、弹性扩容，你的桌底没有；
- 「容器和虚拟机我总分不清」→ 虚拟机是「一套房子隔出几间」，每间全套水电（整份操作系统）；容器是「标准集装箱」，共享船的甲板（同一内核），所以又轻又快；
- 「双系统和虚拟机啥关系？」→ 双系统是开机二选一；虚拟机是主机系统还开着，里面再开一台「假电脑」——可同时用；
- 「我的小工具要不要直接上 K8s？」→ 不要。几个人用的内部工具，一台云主机或 Serverless 往往就够——K8s 是给「几千个容器」准备的，三箱货不必建深水港；
- 「Serverless 是不是最好？」→ 没有最好，只有适不适合。云函数适合事件触发、弹性大的小服务；要长期占着资源、强状态的企业系统，传统部署往往更踏实。
