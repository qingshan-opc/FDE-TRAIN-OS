# 课纲 · 部门AI驾驶舱两周主线（v0.4）

来源：`class/FDE课程设计_核心决策记录.md`（2026-07-24）。**本文件取代 `0.3/curriculum-721.md`。**

核心表达：第一周，用 AI 完成一个全栈项目；第二周，把项目升级成会调用 Skills、能够执行任务的部门 Agent。

## 课程结构原则

1. 每节课 20 分钟：视频 5 + 知识确认 3 + 本地实操 8 + 提交验收 4；
2. 每个训练单元必须有可运行成果或能力证据；
3. 信心通过「做出并修改真实成果」建立；
4. AI 负责生成、解释和加速；学员负责目标、范围、判断和验收；
5. 所有课程围绕同一代码库逐日迭代，不每天重建项目；
6. 70% 统一技术主线 + 30% 部门内容包（财务/HR/销售/运营，默认运营）：
   技术教学一致，只替换指标、字段、模拟数据、AI 任务和验收场景。

## Week 1 · 部门AI驾驶舱（全栈）

接口在前、数据库在后：先用模拟数据理解请求与响应，再用数据库替换模拟数据。

| Day | 主题 | 版本 | 产物 |
|-----|------|------|------|
| 1 | 全局思维（角色/四层/选型/架构）+ 前端 | V0.1 | `index.html` 驾驶舱单页 |
| 2 | 后端接口与前后端连接（模拟数据） | V0.2 | `/api/metrics` 等接口 + 页面改吃接口 |
| 3 | 数据库接入，接口读写持久化 | V0.3 | SQLite 库 + 接口改查库 |
| 4 | 大模型接入：AI 摘要与建议 | V0.4 | AI 摘要区接电 |
| 5 | 集成、测试、部署 | V1.0 | 在线地址 + 测试记录 |

Week1 最终成果：完整前端、后端接口、数据库存储、AI 模型调用、加载/空/错误三态、
Git 版本记录、测试记录、项目说明、在线部署地址。

Week1 明确不做：真实企业敏感数据、复杂经营指标、多角色权限、知识库与 RAG、
多智能体编排、复杂审批、复杂云架构、生产运维。

## Week 2 · Skills 与 Agent（同一项目升级）

部门业务能力封装成 Skill，部门业务流程由 Agent 调度。**先 Skill、后 Agent**——
没有稳定可验收的 Skills，不进入多 Agent 编排。

| Day | 主题 | 产物 |
|-----|------|------|
| 1 | 把一项部门工作封装成第一个 Skill | skill 定义 + 运行证据 |
| 2 | 完善 Skill：输入/步骤/输出/边界/异常/验收 | Skill v1 |
| 3 | 能调用一个 Skill 的部门 Agent | Agent v0.1 |
| 4 | 多 Skill 调度 + 人工确认 + 执行记录 | Agent v0.2 |
| 5 | Agent 接入驾驶舱 | 部门AI驾驶舱 V2.0 |

方向示例：财务→财务分析 Agent（财务摘要/费用异常/应收风险/行动建议）；
HR→招聘协作 Agent；销售→销售跟进 Agent；运营→运营执行 Agent。
