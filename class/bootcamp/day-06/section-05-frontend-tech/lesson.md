## 讲授要点

### 先搭桥：上节是「住哪」，这节是「摸哪」

上节讲服务器与云原生——本质是**程序要长时间跑**，得有个生存环境：物理机、服务器、电脑或容器都行。今天的软件如此，以前工厂里的 ERP、CRM 也一样，都要挂在某个环境里持续运行。

那用户看见、点得到的那一层呢？就是今天的主角——**前端**。

### 先把「前端」这个词撑大

有人对前端的理解还停在「做个网页」。不对。

- 操作系统里你点的那些窗口、按钮——操作层，也是一种界面；
- Web 页面——一种；
- App——一种；
- 微信小程序——一种；
- 桌面上双击打开、看见界面再交互的软件——也是一种。

定义收成一句话：**用户直接接触的界面层，就是前端。**

四个主流平台（选型第一步永远先定平台）：

| 平台 | 用户在哪见到 | 举例 |
|------|-------------|------|
| Web 网页 | 浏览器地址栏 | 公司官网、后台系统、你的周报助手 |
| App | 应用商店下载安装 | 微信、滴滴、Keep |
| 小程序 | 微信/支付宝里扫码即用 | 麦当劳点单、健康码 |
| 桌面软件 | 电脑上双击图标 | VS Code、飞书、剪映专业版 |

### Web 网页：从静态店铺到框架时代

企业里最常碰到的是外部网页 / 内部系统。大约 2000 年前后，很多还是**静态页**：挂个店铺介绍、联系方式，让人在网上看得到。今天已经到框架级：强视觉、动态交互——比如你在百度搜一句，请求打到后端处理，再把结果渲染给你看。

地基仍是三件套：**HTML 骨架、CSS 皮肤、JavaScript 肌肉**。框架是预制装修套件，当下常听到这些：

- **React**——人最多、生态最大、AI 最会写；模块化清晰，大型项目常用。**默认推荐多数新项目从这儿看起**（不是唯一正确答案，是「遇坑有人、AI 写得稳」的安全牌）；
- **Vue**——尤雨溪约 2015 年前后做出来的（基于当时的 JS 生态，含 ES6 一带）。国内文档友好，**单体 / 中小型应用表现好**：企业小系统、数据大屏一类很合适。ES6 是什么？可先当「更现代的 JavaScript」——课表资源区有网页发展简史，可翻一眼；
- **Angular**——全家桶、规矩最全，偏大企业长期巨型项目。新项目热度不如从前、上手偏重，但**存量项目仍多**——别人说「我们是 Angular」你要听得懂；
- **Svelte**——另一路框架，写法更省事，生态相对小；
- **Next.js**——在 React 上再加一层「服务器能力」：服务端渲染（把 V8 引擎能力用到服务端渲染链路里），适合内容站、官网、电商。美国这边官网/内容类很爱用它——一体成型，前后端渲染绑得紧；
- **不用框架**——小页面完全够用（你们 Day 3 的 index.html 就是）。

配套记两个名字：**TypeScript**（带类型的 JS，大项目防呆）、**Vite**（主流构建工具，启动快）。

### App 开发：原生两套，跨端几条路

- **原生 · Swift（iOS）/ Kotlin（Android）**——苹果、谷歌各自官方语言。性能与系统能力最全；代价是两套代码、两拨人；
- **Flutter**——一套代码出 iOS + Android，两端长得齐。**只做双端 App、求体验一致时，很常被推荐**；
- **React Native**——用 React 写 App（仍要「包一层壳」接到原生）。会 React 的团队转 App 最顺；
- **uni-app 等国内打包方案**——若还要顺带出**小程序 + App + H5** 多端，国内团队常走这条（一套代码编排到多家）。

### 小程序：微信里的「轻应用」

不用下载、扫码即用——做国内生意绕不开：

- **微信原生（WXML / WXSS / JS，也可上 TS）**——官方能力最全、最稳；
- **Taro / uni-app**——跨端：一套代码出微信 / 支付宝 / 抖音小程序，甚至再加 H5、App。要打多家小程序就选它们。

### 桌面软件：网页技术包壳

- **Electron**——用网页技术写桌面软件：VS Code、飞书、Discord 都是它包的。前端团队零门槛；代价是包大、吃内存；
- **Tauri**——偏轻量的替代路线（核心侧常用 Rust）：体积小很多，生态更新、要肯碰一点系统侧。

### 两步选型法 + 四问

**第一步定平台**：用户在哪用你？浏览器→Web；应用商店→App；微信里→小程序；桌面图标→桌面。  
**第二步选框架**，四个问题按顺序问：团队会什么？生态大不大？AI 写得好不好？项目有多大？

兜底：没团队跟生态走，有团队跟团队走。AI 时代隐藏加分：React 这类语料多的技术，生成质量更稳。

### 回扣你的 Day 3

周报助手是 Web 单页，「不用框架」当时就是正确答案；哪天要变手机 App：团队会 React → React Native；要双端一致 → Flutter；还要小程序多端 → 看 uni-app / Taro。

## 常见懵点（导师备用）

- 「到底学哪个才不亏？」→ 按目标平台：内部系统学 Web（React/Vue 任一），做 App 看 Flutter 或 React Native，国内生意绕不开小程序——没有一门通吃，但概念相通；
- 「老师口语里说 Angular 比较 low？」→ 指的是新项目热度与上手成本，不是「技术错误」。大企业长期巨型项目、存量接手，Angular 仍然合理——听得懂比追热点重要；
- 「小程序和 App 怎么选？」→ 轻量、用完即走、借微信流量 → 小程序；重度使用、要系统能力 → App；
- 「Next.js 和 React 是不是两套？」→ Next.js 建立在 React 上，多的是服务端渲染与全栈路由那一层；学 React 不会浪费；
- 「Electron 是不是落后？」→ 不是，是用开发效率换性能——内部工具桌面版首选；对体积敏感再看 Tauri。
