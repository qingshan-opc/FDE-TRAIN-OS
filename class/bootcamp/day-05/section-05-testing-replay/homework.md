# 第 5 节 · 提交与验证

## 提交文件

- `day5-replay/iteration-test-plan.md`
- `day5-replay/iteration-defect-log.md`
- `day5-replay/iteration-test-report.md`
- 对应测试证据目录

## 通过条件

- 计划覆盖新能力和受影响原功能；
- 每条结果来自学员真实执行；
- 失败项有责任岗位和证据；
- 修复后由测试复测并回归；
- 测试报告明确建议发布或不建议发布。

## 不通过时回到哪里

- 页面与请求问题：退回 `@前端`；
- 规则、响应与数据问题：退回 `@后端`；
- 验收标准不清：退回 `@产品经理`；
- 测试证据不完整：留在 `@测试` 补齐。
