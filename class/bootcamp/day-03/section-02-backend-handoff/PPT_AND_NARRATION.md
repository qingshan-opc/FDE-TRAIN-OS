## 01 · open

**PPT（屏幕）**
- 第二次开发交接
- @前端 → @后端
- 先接收，后开工

**口播**
> 同学们好，我是你们的老师404。现在开始前端到后端的交接。很多小白只会说“帮我做后端”，等 AI 生成一大堆代码，又不知道怎么办。咱们把交接拆成四步：先检查和复述，再逐题澄清，最后看方案、由你确认。先看后端要读哪些文件。

文稿：`video/scripts/narration/01-open.txt`

## 02 · inputs

**PPT（屏幕）**
- 后端四类输入
- PRD
- 前端数据需求
- 真实文件与验收

**口播**
> 后端先读需求文件，再读前端数据需求。真实页面文件告诉它请求从哪儿发出，前端验收记录告诉它上游通过了哪些检查。缺任何一项，都不要猜——后端先指出缺口，你回到责任岗位补齐。那第一段提示词怎么发？

文稿：`video/scripts/narration/02-inputs.txt`

---

## 03 · p1

**PPT（屏幕）**
- P1 · 只检查文件
- 不要设计接口
- 不要写代码
- 缺项回责任岗位

**口播**
> 第一段只做文件检查。切到 @后端，让它报告五个文件齐不齐：PRD、前端数据需求、index.html、app.js 和验收记录。现在不设计接口，不写代码。缺需求回产品经理，缺数据需求回前端。补齐了，发第二段。

文稿：`video/scripts/narration/03-p1.txt`

---

## 04 · p2

**PPT（屏幕）**
- P2 · 五项复述
- 规则
- 展示与提交
- 四种状态
- 待确认问题

**口播**
> 文件齐全，发第二段。让后端复述核心业务规则，页面展示哪些数据、用户提交什么内容，也要说清，还有四种页面状态和待确认问题。你拿原文件对照。理解不一致，只做纠正——后端不能擅自改上游文件。复述对了，进入逐题澄清。

文稿：`video/scripts/narration/04-p2.txt`

## 05 · p3

**PPT（屏幕）**
- P3 · 一次只问一题
- 数据来源
- 核心对象
- 权限与隐私
- Python 环境

**口播**
> 第三段，逐题澄清。后端一次只能问一个问题：先确认数据来源和核心数据对象，再确认访问权限和隐私限制，最后检查本机运行环境。每题让它给一个当前项目的回答示例。你答完一题，它才能问下一题。环境检查这块，别搞复杂。

文稿：`video/scripts/narration/05-p3.txt`

## 06 · environment

**PPT（屏幕）**
- 环境只做一件事
- python --version
- 不行再试 py --version
- 不乱装未知工具

**口播**
> 环境检查，保持简单。先在工具终端输入 Python 版本检查命令；命令不存在，再用启动器的版本命令。这里只确认 Python 三能用，不要下载陌生安装包，也别提前装一堆框架。出错了，把原始提示原样保留。环境没问题，看方案。

文稿：`video/scripts/narration/06-environment.txt`

## 07 · p4

**PPT（屏幕）**
- P4 · 最小后端方案
- 3—5 个接口
- 2—3 张表
- 运行与健康检查
- 明确不做项

**口播**
> 第四段，只看最小后端方案。第一版用 Python 标准库加本地轻量数据库，接口控制在三个到五个，数据表控制在两张到三张，还要写清运行方式和健康检查。登录、云部署这些没确认的功能，一概不加。方案出来，别急着点头。

文稿：`video/scripts/narration/07-p4.txt`
