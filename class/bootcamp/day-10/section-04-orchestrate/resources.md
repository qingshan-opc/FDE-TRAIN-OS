# 第 4 节 · 资源：编排指令 / 日志模板 / 排障速查

> **分槽说明**：下面「编排指令」是发给**正在跑的 Agent / task_runner** 的运行指令；仓库脚手架与 HITL 实现请用本节 practice 里的 **编码任务** `prompts/05-long-task-hitl.md`。两者不要混成同一段粘贴。

## 1. 编排指令模板（发给正在跑的 Agent，改尖括号即可用）

```text
你现在按以下 workflow 执行，顺序不许变：

1. 调用 Skill A〈你的 Skill 名〉，输出存为 step-a 结果
2. 调用 Skill B〈你的 Skill 名〉，输入使用 step-a 结果；
   产出草稿后，生成确认界面：
   - 草稿全文
   - 关键数字（逐项列出）
   - 风险标红（哪些数据你不确定、哪些内容不可撤回）
3. 停。不要执行任何后续步骤，等我回复。
   - 我回复「发」→ 调用 Skill C〈你的 Skill 名〉执行
   - 我回复「驳回：理由」→ 回到第 2 步重做，草稿版本号 +1，
     再次生成确认界面等我
4. 每执行完一步，向 runs/〈今天日期〉.md 追加一行：
   HH:MM | 步骤 | 结果（成功数量/文件名/等待/批准/驳回）
```

## 2. 编码脚手架（TRAE / 改仓库）

整份粘贴教学包：[`prompts/05-long-task-hitl.md`](../../../teaching/week2-cockpit-agent/prompts/05-long-task-hitl.md)

## 3. 执行日志模板（`runs/YYYYMMDD.md`）

```markdown
# 运行日志 2026-07-24

17:02 | Skill A 拉数据   | ✓ 42 条，3.2s
17:02 | Skill B 生成草稿 | ✓ draft-v1.md
17:03 | ◇ 人工确认       | ⏸ 等待审批
17:15 | ◇ 人工确认       | ✗ 驳回：第 2 段数字不对
17:16 | Skill B 重做草稿 | ✓ draft-v2.md
17:18 | ◇ 人工确认       | ✓ 批准（数字已核）
17:18 | Skill C 发送     | ✓ 已发部门群
```

三要素自查：每一行都能回答——**什么时候、谁/什么干的、干成了什么**。

## 4. 排障速查

| 症状 | 大概率原因 | 修法 |
|------|-----------|------|
| 到闸不停，直接发 | 发送类 Skill 守卫没写第一行 / 编排指令漏了「停」 | 先修 Skill，再修指令，重跑 |
| 确认界面只有「发送吗」 | B 的产出缺「确认界面」设计 | 回第 3 节补 B 的输出部件：草稿 + 关键数字 + 风险标红 |
| 驳回后 Agent 不知道从哪继续 | 编排指令没写驳回回路 | 补「驳回 → 回第 2 步，版本 +1」 |
| 日志断行/缺步 | Agent 跳步执行了 | 指令里把「每步追加日志」放到步骤内，不是最后补 |
| A 的输出 B 读不懂 | 数据流断点 | 用第 3 节对齐三查定位，改上游输出或加转换说明 |
