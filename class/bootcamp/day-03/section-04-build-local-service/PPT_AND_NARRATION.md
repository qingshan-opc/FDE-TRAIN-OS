## 02 · simple-stack

**PPT（屏幕）**
- 第一次后端先降低门槛
- Python 3 标准库
- SQLite
- 不安装第三方依赖

**口播**
> 第一次做后端，咱们用 Python 三标准库，数据存在本地轻量数据库里。这样能少装依赖、少踩环境差异的坑，你能先看懂开发和运行的完整流程。以后换成别的技术框架，这套验证和交接顺序照样成立。好，发第一段。

文稿：`video/scripts/narration/02-simple-stack.txt`

**PPT（屏幕）**

## 04 · review

**PPT（屏幕）**
- P2 · 先审查文件
- 路径与字段
- 状态码
- /api/health

**口播**

## 05 · start

**PPT（屏幕）**
- P3 · 学员亲手启动
- 项目根目录
- python backend/server.py
- 终端保持运行

**口播**
> 文件通过后，打开工具终端。先确认终端在项目根目录，再输入运行手册里的启动命令；电脑用启动器的，就用手册里的备用命令。服务启动后，终端会一直停在那儿——别慌，它是在等请求，不是电脑卡住了。下一步，验健康。

文稿：`video/scripts/narration/05-start.txt`

## 06 · health

**PPT（屏幕）**
- 先做健康检查
- 127.0.0.1:8000
- GET /api/health
- 证明服务能响应

**口播**
> 保持终端窗口开着，在浏览器访问健康检查地址。看到合同规定的结果，说明服务启动并能响应了。健康检查失败，先看终端的原始错误，别上来就改一堆代码。服务没起来，也不要进入前端联调。健康了，再测接口。

文稿：`video/scripts/narration/06-health.txt`

## 07 · api-tests

**PPT（屏幕）**
- P4 · 单独验证
- 一次查询
- 一次提交
- 两种错误
- 实际结果对合同

**口播**

文稿：`video/scripts/narration/07-api-tests.txt`

## 08 · restart

**PPT（屏幕）**
- P5 · 重启持久化
- Ctrl+C 停止
- 重新启动
- 刚提交的数据仍在

**口播**
> 最后，回到服务终端，按控制键加字母西停止服务，再重新启动，查询刚才那条记录。记录还在，说明数据真的存下来了；记录消失，它可能只是待在临时内存里。把每项实际结果写进后端验收记录。好，这一节收个尾。

文稿：`video/scripts/narration/08-restart.txt`
