# 第 1 节 · 业务流程即编排（15′ · 概念）

> 🎬 视频位（现阶段：口播稿）
> 快答开场（昨晚查的）：Human-in-the-loop 是什么意思？然后进入今天的主题：把流程翻译成流水线。

## 教学目标

- 理解编排（orchestration）：把多步业务流程拆成 Skill 的串联，数据在上一步与下一步之间流动；
- 掌握拆分手法：每步判断「是 Skill 还是人」——AI 干执行，人干判断与放行；
- 产出自己流程的 Skill 串联图（第 4 节施工图纸）。

## 讲授要点（15′）

| 时段 | 内容 |
|------|------|
| 0–4′ | 快答 HITL + 破题：一件工具是助手，一条流水线才是团队 |
| 4–10′ | 拆分手法：步骤分类（Skill 执行 / 人判断 / 人放行）+ 数据流怎么画 |
| 10–15′ | 动手：昨晚的流程草稿 → Skill 串联图 |

### 拆分手法（对每一步问三个问题）

```
① 这步是「执行」还是「判断/放行」？
   执行 → 候选 Skill；判断/放行 → 人（确认点）
② 这步的输入从哪来？上一步的产出是什么？
   → 画出数据流：A 的产出 = B 的输入
③ 这步错了能撤回吗？
   能 → 自动连跑；不能 → 前面必须有人工确认闸（第 2 节）
```

### 示例：运营周报流水线

```
[Skill A 拉数据] → 本周 KPI+异常 JSON
       ↓
[Skill B 生成周报] → 周报草稿.md
       ↓
◇ 人工确认（你看一眼草稿）   ← 确认闸
       ↓ 批准
[Skill C 发送] → 发到部门群   ← 不可撤回！
```

> 对照 Day 8 的铁律：这是 **workflow**——步骤你定死，不依赖 Agent 现想。编排 = 你当流程设计师，AI 当流水线工人。

## 🎬 口播稿（约 5 段 · 待审）

> 同学们，先快答一句：Human-in-the-loop 就是关键步骤要人点头，AI 不能自己拍板。今天咱们把业务流程翻译成流水线，这叫编排。一件工具顶多算助手，一条串起来的流水线才算团队，对吧。
> 拆分手法呢，对每一步问三个问题。第一，这步是执行还是判断？执行给 Skill，判断和放行人留着。第二，输入从哪来？A 的产出就是 B 的输入，数据流得画清楚。第三，这步错了能撤回吗？不能撤回的，前面必须装人工确认闸。
> 咱们再强调一遍数据流。上一步吐什么格式，下一步就吃什么格式，中间对不齐，流水线一定卡。又是契约思想，第六次了嘛——编排不是堆 Skill，是让产出和输入咬合，对吧。
> 看这条周报流水线：Skill A 拉 KPI 和异常，Skill B 生成草稿，这两步可以全自动连跑。发送之前呢，一个确认闸——你看一眼草稿，批准才发。为什么？消息发出去了就收不回，这个例子咱们后面还会用到。
> 同学们，注意这是 workflow，步骤你定死，不依赖 Agent 现场瞎想。还记得第八天的铁律吗，能 workflow 别 agent。编排的意思就是：你当流程设计师，AI 当流水线工人。本节带走一句——把流程画成 Skill 串联图，第四节能直接施工，对吧。


## 常见懵点

- 「三步都要 Skill 吗？手动步骤能不能混进来？」→ 能：流水线里允许「人工步骤」（比如「你确认」本身就是一步）——写清楚谁干就行；
- 「数据流格式要对齐吗？」→ 要：A 的输出契约必须满足 B 的输入要求——又是契约思想（第六次）；
- 「编排要写代码吗？」→ 今天不用：Agent Lab 里按顺序调用 + 确认闸即可；自动化引擎（n8n 等）在公开课 O2。
