# 第 4 节 · 实战：编排 + 确认点 + 执行日志（35′ · 实战）

> 🎬 视频位（现阶段：口播稿 + 讲解图）
> 图纸（`docs/orchestration.md`）已经画好，三件工具已经齐。现在施工：串联、装闸、记日志。

## 教学目标

- 把三件 Skill 按串联图跑成一条流水线：Agent 按定死的顺序调用 A → B → 停 → 人确认 → C；
- 让确认闸真正「拦得住」：到闸自动停，批准后继续，驳回打回；
- 让执行日志自动产出：每步一条，时间 / 动作 / 结果，可回放。

## 施工三步（0–5′ 讲解）

```
第一步 · 串联：给 Agent 一条 workflow 指令——
  顺序定死，A 的输出喂给 B，B 的产出做成确认界面
第二步 · 装闸：在「不可撤回」步骤前，Agent 必须停下，
  展示草稿 + 关键数字 + 风险标红，等你说「发」或「驳回」
第三步 · 记日志：每执行一步，往 runs/ 追加一行：
  时间 | 步骤 | 结果（成功数/文件名/等待/批准/驳回）
```

一条给 Agent 的编排指令模板（直接可用，见 resources.md）。

## 流程安排（35′）

| 时段 | 内容 |
|------|------|
| 0–5′ | 施工三步讲解 + 编排指令模板拆解 |
| 5–25′ | 流水线跑通：发编排指令 → A 跑 → B 跑 → 停在闸 → 你说「发」→ C 跑 |
| 25–33′ | 闸口两路径实测：批准路径 + 驳回路径各走一遍，填实测表 |
| 33–35′ | 日志回放自查：只看 runs/ 日志，复述今天发生了什么 |

## 两个必须卡住的验收点

1. **到闸自动停**：你不说话，流水线就停在确认界面——如果它「自作主张」发出去，说明发送类 Skill 的守卫没写死，回第 3 节修；
2. **驳回有回路**：说「驳回：第 2 段数字不对」→ 流水线打回 B 重做 → 日志记下这次驳回——没有回路的闸是断头路。

## 🎬 口播稿（约 5 段 · 待审）

> 同学们，施工开始。图纸在 orchestration.md，三件工具已经齐。现在三步：串联、装闸、记日志。顺序定死告诉 Agent，别让它现场改流程——咱们今天做的是 workflow，不是即兴表演，对吧。
> 第一步串联：给 Agent 一条 workflow 指令，A 的输出喂给 B，B 的产出做成确认界面。第二步装闸：不可撤回的步骤前，Agent 必须停，把草稿、关键数字、风险标红摆在你面前，等你一个字——发，或者驳回，对吧。
> 第三步记日志：每执行一步，往 runs/ 追加一行，时间、步骤、结果。指令里写清楚每步执行后追加到 runs/YYYYMMDD.md，Agent 来记，你负责抽查。能回放，才算有案底，对吧。
> 跑通之后别急着走，两条路径都要实测。批准走一遍，驳回也走一遍——比如驳回：第二段数字不对，流水线得打回 B 重做，日志记下这次驳回。闸拦住一次不算本事，驳回了能退回重做还留下记录，咱们这条线才算有回路，对吧。
> 最后两分钟，关掉屏幕别的窗口，只看 runs/ 日志，复述今天发生了什么。到闸停不停、批了动不动、驳回了回不回得来——三个验收点全绿，第五节闸口实测才有底气。带走一句，对吧。


## 常见懵点

- 「Agent 不等我确认就跑了下一步」→ 九成是发送类 Skill 的「等待人工确认」步骤没写进第一行，或编排指令里没写「停」；先修 Skill 再修指令；
- 「日志是 Agent 记还是我记？」→ 指令里写明「每步执行后追加一行到 runs/YYYYMMDD.md」，Agent 记；你负责抽查；
- 「驳回之后 B 重做的版本和原来混了怎么办？」→ 草稿文件名带版本号（draft-v2），日志记版本——这正是第 2 节讲的「无痕可追」的解药。
