- HTML · CSS · JavaScript

## 02 · html

**PPT（屏幕）**
- HTML 管结构
- 页面有哪些东西
- 标题 · 表格 · 表单 · 按钮 · 内容区

**口播**
> HTML 是页面的骨架。它决定页面有什么：标题放哪儿，有没有筛选区，有没有表单、列表、卡片和按钮。就像一套房子的墙、门和房间位置。HTML 不负责把房子装修得多漂亮，先把该有的空间搭出来。骨架搭好了，谁负责好看？

文稿：`video/scripts/narration/02-html.txt`

---

## 03 · css

**PPT（屏幕）**
- CSS 管样式
- 颜色 · 字号 · 间距 · 布局
- 按钮默认 / 悬停 / 禁用

**口播**
> CSS，页面的衣服和装修。主色是什么，标题多大，卡片之间留多大空，手机上怎么排，按钮正常、鼠标悬停、暂时不能点分别长什么样，都归 CSS 管。页面有内容、但看着像一张没排版的纸，先检查样式文件连上没有。能看了，还得能动。

文稿：`video/scripts/narration/03-css.txt`

---

## 04 · javascript

**PPT（屏幕）**
- JavaScript 管行为
- 点击 · 筛选 · 校验 · 切换状态
- 操作以后必须有可见反馈

**口播**
> JavaScript 管页面动作。点查询以后列表变化，填表单以后检查必填项，切状态以后显示空数据或错误提示，这些都归它。页面看着正常，按钮怎么点都没反应，通常要查 app.js 和浏览器控制台。三个文件各管一摊，但它们不是各过各的。

文稿：`video/scripts/narration/04-javascript.txt`

## 05 · links

**PPT（屏幕）**
- 三个文件怎样连起来
- index.html 引用 styles.css
- index.html 引用 app.js
- 路径错：无样式或无反应

**口播**
> 怎么连起来的？index.html 里会写明去哪儿找 styles.css，也写明去哪儿找 app.js。路径写错，页面可能还能打开、却没样式；也可能样式正常、按钮全失效。所以今天每生成一个阶段，都要立刻运行一次。运行之前，还有一样东西要安顿好——演示数据。

文稿：`video/scripts/narration/05-links.txt`

## 06 · demo-data

**PPT（屏幕）**
- 演示数据 ≠ 真实数据
- 集中放在 app.js 顶部
- 不用隐私，不写密钥

**口播**
> 今天仍然用演示数据，虚构或脱敏的，只为验证页面怎么展示和操作。要求 AI 把演示数据集中放在 app.js 顶部，将来后端接入时，一眼就能找到替换位置。千万别把真实公司数据、个人隐私和 API 密钥放进前端，浏览器里的东西，用户都有可能看到。数据安顿好，再说页面的四种脸。

文稿：`video/scripts/narration/06-demo-data.txt`

## 07 · four-states

**PPT（屏幕）**
- 真实页面要面对四种状态
- loading · 正在等待
- empty · 没有数据
- success · 正常结果
- error · 失败与重试

**口播**
> 页面不能只画一张顺利结果。加载状态，告诉用户系统正在处理；空数据状态，告诉用户没记录、下一步能干嘛；成功状态，展示正常结果；错误状态，说明失败、给重试办法。只做成功状态，就像只为晴天设计道路，真用起来一定出问题。最后，学一个看报错的动作。

文稿：`video/scripts/narration/07-four-states.txt`

## 08 · close

**PPT（屏幕）**
- 只学会一个调试动作
- F12 → 控制台
- 看见红错，记录现象
- 下一节：四段生成

**口播**
> 今天只学一个调试动作：按 F12 打开开发者工具，找到控制台。看到红色错误，不要求你立刻读懂，记下四样：在哪个页面、做了什么、实际看到什么、预期什么，然后交给 @前端。再记一遍：HTML 是结构，CSS 是样式，JavaScript 是行为。下一节开始四段生成。同学们，本节先到这里。

文稿：`video/scripts/narration/08-close.txt`
