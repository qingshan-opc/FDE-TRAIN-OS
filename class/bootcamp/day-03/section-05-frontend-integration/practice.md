# 第 5 节 · 练习

## 知识确认

1. 联调至少要跑通哪些用户动作？
2. 请求字段发错和响应字段发错分别由谁修？
3. 为什么修复后必须重跑主流程？

## 本地实操

### P1 · 交接合同

> @前端，请读取 API_Spec.md、RUNBOOK.md、frontend/app.js 和 frontend-api-needs.md。现在不要修改。请列出“页面动作 → 当前演示数据位置 → 目标接口 → 成功后更新位置 → 失败提示”。输出后停止。

### P2 · 确认改动范围

> 映射已确认。请只修改 frontend/app.js 的数据请求与状态处理；保留现有设计、交互和加载/空/成功/错误状态，不修改 PRD、API_Spec.md 和后端文件。修改完成后列出改动点和人工检查步骤。

### P3 · 查询流程

保持后端运行，打开前端页面，执行一次查询。记录页面结果、浏览器 Network 请求和后端终端日志。

### P4 · 提交与刷新

提交一条容易识别的新记录，刷新页面并重新查询，确认记录仍存在。

### P5 · 错误与归责

制造一个安全的错误输入，确认页面出现友好提示。让当前岗位只定位证据，不越权修改；再切换到责任岗位修复。

### P6 · 回归

> 修复完成。请给我按顺序执行的回归清单：启动服务、健康检查、打开页面、查询、提交、刷新复查、错误输入和四种状态。一次只引导一项。

## 提交验证

- 前端读取了真实合同；
- 不再依赖关键演示数据；
- 查询、提交和刷新通过；
- 错误有用户可理解的反馈；
- 修复由责任岗位完成；
- 回归主流程通过。
