# 第 2 节 · 练习

## 知识确认

1. 六类测试输入分别解决什么问题？
2. 为什么测试计划要按风险排序？
3. 谁可以回复“确认测试”？

## 本地实操

### P1 · 检查输入

> @测试，请读取 PRD.md、API_Spec.md、DB_Schema.md、RUNBOOK.md、backend-acceptance.md 和 backend-handoff.md。现在不要执行测试。缺少文件时只说明缺什么、应回到哪个岗位补齐。

等待检查完成。

### P2 · 复述范围和风险

> 文件齐全后，请复述目标用户、核心主流程、关键业务规则、接口成功与错误、数据持久化、权限隐私和已知限制。再列出前三项发布风险。输出后停止。

### P3 · 只列测试目录

> 请只列测试目录，包含启动与健康检查、页面主流程、接口成功与错误、数据保存与重启、四种页面状态、权限隐私和 PRD 验收标准。每类写一句通过条件。现在不要展开用例。

### P4 · 生成计划

> 目录已确认。请生成 test-plan.md。每条用例写编号、优先级、前置条件、操作步骤、预期结果、证据位置和主要责任岗位。标出冒烟测试和回归范围。保存后停止。

学员逐条核对后回复：`确认测试。`

## 提交验证

- 六类输入齐全；
- 每条 PRD 验收标准至少有一条用例；
- 高风险用例优先；
- 每条用例能记录实际证据；
- 确认前没有执行测试。
