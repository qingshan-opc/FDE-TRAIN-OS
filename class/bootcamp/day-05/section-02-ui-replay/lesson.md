# 第 2 节 · UI 重跑交互原型

> 一句话节引言：UI 这一棒不追求重新设计整站，只把确认后的微迭代变成前端能实现的交互合同。

## 教学目标

- 用 `@UI` 读取产品交付物并复述范围；
- 找到本次真正需要变化的页面区域；
- 补齐输入、显示字段、动作、反馈和四种页面状态；
- 让每条设计回到产品验收标准；
- 输出 UI 说明与前端交接，并完成“确认原型”。

## UI 这一棒

```text
输入：iteration-prd.md、pm-handoff.md、现有页面
工作：翻译需求、设计流程、补齐状态、控制一致性
输出：iteration-ui-spec.md、ui-handoff.md
下一棒：@前端
退回条件：需求冲突、状态不清或验收标准不可判断
```

## 传统职能与 AI 时代

传统 UI 设计师需要反复画线框和整理标注。AI 可以快速生成布局草案和状态清单。人的责任是判断交互是否符合真实工作习惯，并确保所有状态都能被前端实现和测试。

## 原型必须覆盖什么

- 用户从哪里进入改进后的流程；
- 用户需要输入或选择什么；
- 系统显示哪些字段；
- 点击后发生什么；
- 加载、空数据、成功和错误时分别显示什么；
- 每个结果对应哪条产品验收标准。

## 本节人工闸门

学员检查交互是否能完成用户目标，四种状态是否齐全。确认以后回复“确认原型”，再切换到 `@前端`。
