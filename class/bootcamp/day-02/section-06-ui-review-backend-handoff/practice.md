# 第 6 节 · 本地实操与提交

## P1 · 切换 UI 复验

> 请读取 design-spec.md、ui-flow.md 和 frontend 目录中的三个文件。只验收，不直接修改。逐项输出“通过/不通过、文件依据、可量化差距、责任岗位”。

## P2 · 回前端修复，再回 UI

> 请只处理 UI 的问题清单，说明修改文件和复测方法。完成后我会再次切回 UI。

修复后重新 `@UI` 复验。

## P3 · 生成后端数据需求

> 请根据已通过的页面生成 frontend-api-needs.md。按页面或功能列出：展示所需字段、字段含义、用户提交内容、期待后端返回内容、加载/空数据/错误的展示方式。不要编造接口地址，不要写密钥。

## P4 · 后端接收

> 请先读取 PRD.md 和 frontend-api-needs.md，只复述你收到的业务规则、页面数据需求和需要确认的问题。现在不要开发接口，等我确认 Day3 开工。

## P5 · 记录完整岗位链

创建 `day2-handoff-log.md`，记录：

```text
UI → 前端 → UI → 前端 → 后端
```

每次写清输入、输出、验收结果和修改轮次。

## 完成标志

- UI 最终复验通过
- `frontend-api-needs.md` 没有虚构接口或密钥
- 后端完成接收复述但没有提前生成代码
- `day2-handoff-log.md` 可还原完整交接过程
