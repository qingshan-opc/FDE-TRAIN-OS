# 第 4 节 · 生成并跑通本地后端

## 本节目标

- 让 `@后端` 严格按合同生成代码；
- 用 Python 标准库和 SQLite 降低第一次运行门槛；
- 学会启动、健康检查、接口检查和停止；
- 证明重启后数据仍然存在。

## 第一版文件

```text
backend/
  server.py
  data/app.db
.env.example
RUNBOOK.md
```

`server.py` 提供接口和业务规则，`app.db` 保存数据，`.env.example` 只给变量名与示例占位值，`RUNBOOK.md` 用小白能执行的步骤说明启动、检查、停止和常见故障。

## 为什么先用标准库

Day3 的目标是理解后端流程，不是学习依赖管理。Python 标准库加 SQLite 无需安装第三方框架，能减少环境差异。以后换成其他框架，合同、运行、验证和交接的顺序不变。

## 先单测，后联调

启动后先访问 `GET /api/health`。再单独完成一次查询、一次提交和至少两种错误请求。停止服务、重新启动，再查询刚提交的数据；仍然存在才证明写入了数据库，而不是只放在内存里。
