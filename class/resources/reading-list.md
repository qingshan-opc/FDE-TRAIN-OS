# 技术演进与生态 · 阅读清单（M0–M5 全程课后延伸）

> 全部可选。标注 ⏱ 为大致耗时，按兴趣取阅，不影响验收。
> 原则：读「为什么」，不读「怎么操作」——操作课里都有。
> 选读方式见公开课 O5「按你的下一站选」。

## 技术演进（对应 Day 1 第 1 节）

| 资源 | 为什么读 | ⏱ |
|------|---------|---|
| Marc Andreessen《Why Software Is Eating the World》(2011) | 上一次浪潮的宣言；对照今天读，体会「浪潮叙事」 | 15′ |
| a16z《AI Will Save, Not Destroy, Software》或同类 2024–25 评论 | 本次浪潮的宣言；注意两次宣言的同与不同 | 15′ |
| 任一篇「SaaS is dead / long live SaaS」辩论 | 理解「AI 原生 vs 传统 SaaS」之争的两边 | 10′ |

## LLM 本体（对应 Day 1 第 2 节）

| 资源 | 为什么读 | ⏱ |
|------|---------|---|
| 3Blue1Brown《But what is a GPT?》 | 目前最好的直觉化解释，动画讲清「预测下一个词」 | 25′ |
| Andrej Karpathy《Intro to Large Language Models》(talk) | 一小时建立 LLM 全局观；看前 30 分钟即可 | 30′ |
| 《Why LLMs hallucinate》任一篇科普 | 幻觉的机制解释，Day 5 验收摘要时会感谢这篇 | 10′ |

## 生态地图（对应 Day 1 第 3 节）

| 资源 | 为什么读 | ⏱ |
|------|---------|---|
| Hugging Face Open LLM Leaderboard | 开源权重视角的实时座次 | 10′ |

## 信息架构与 API 设计（对应 Day 2–3）

| 资源 | 为什么读 | ⏱ |
|------|---------|---|
| 《Don't Make Me Think》(Steve Krug) 任一章节 | 页面必须回答用户问题的经典，信息架构的直觉来源 | 30′ |
| Stripe API 文档随手翻 10 分钟 | 行业标杆的契约长什么样：命名、错误码、分页 | 10′ |
| 《REST API Design Rulebook》或同类速览 | 路径、方法、状态码的设计惯例，Day 3 定契约更稳 | 20′ |
