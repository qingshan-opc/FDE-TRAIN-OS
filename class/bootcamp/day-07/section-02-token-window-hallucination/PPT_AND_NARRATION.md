## 02 · token-unit

**PPT（屏幕）**
- 眉题：02 TOKEN · 不是一个汉字
- 模型读写的最小切块
- 英文约一词一块 · 中文常半字到一字
- 不同模型切法可不同

**口播**
> 先说 Token。同学们啊，千万别把它理解成「一个汉字」或「一个英文单词」——在模型眼里，文本会被切成一块一块的最小读写单位，那一块才叫 Token。英文常常一个词大约一块；中文常常是半个字到一个字不等；不同模型切法还可能不一样。所以啊，你数「多少字」跟账单上的 Token，对不齐很正常。有同学可能会问：那我怎么知道用了多少？看返回里的 usage，或者用官方的计数器估一下。听见了吗？Token 是模型的尺子，不是你的字数统计。来，心里用一句话回答：Token 是字数吗？——不是，是模型咬字的一口大小；同一句话，不同模型咬出来的口数可能不一样。下一页看这把尺子怎么变成钱，对吧。

## 03 · token-cost

**PPT（屏幕）**
- 眉题：03 TOKEN · 钱与注意力
- 计费：输入 + 输出一起算
- Cursor 里贴整个代码仓库 = 烧 Token
- 省：清废话 · 清重复 · 格式写清

**口播**
> Token 为什么重要？两件事：钱，和注意力。API 一般按输入加输出一起计费——你问得多、它答得长，都花钱。你往 Cursor 里贴整个代码仓库、整份 PRD，表面是「让它看全」，实质是在烧 Token，还可能把关键约束淹没在垃圾堆里。打个比方：Token 像手机流量，不是你数了多少字，是套餐按块扣的。所以啊，写 Prompt 省钱不是抠门，是工程习惯：废话清掉、同一段别贴三遍、格式写清。有同学可能会说：贵就贵一点呗。训练营可以；企业里对话一长、并发一高，账单会咬人——一百人同时问，账单是乘上去的。听见了吗？省 Token 是基本功。作业一句：下次贴材料前，先问「这段是不是非看不可」。下一页讲「流量」之外还有「套餐总上限」——窗口，对吧。

文稿：`video/scripts/narration/03-token-cost.txt`

## 04 · window

**PPT（屏幕）**
- 眉题：04 WINDOW · 上下文窗口
- 讲解图：context-assembly.svg
- 一次调用能同时看见的硬顶
- 宣传数字大 · 真材料一塞就满

**口播**
> 第二个词，上下文窗口。用人话说：一次调用里，模型能同时「看见」的 Token 总量上限。宣传册上 Claude 常见二十万量级、GPT 一类一百二十八 K，听着很大，对吧。可你把 PRD、架构说明、接口契约、三天聊天记录一股脑塞进去，很快就顶。有同学可能会问：满了是不是模型变笨了？不是变笨，是装不下了——课桌就这么大，书掉地上它就看不见。所以啊，FDE 要练的不是「窗口越大越好」，而是「有限桌面上放最有用的纸」。记住：窗口数字是上限，不是建议你每次塞满。来，看屏幕这张装填图，下一页讲满了怎么办——三条出路，对吧。

## 05 · window-full

**PPT（屏幕）**
- 眉题：05 FULL · 窗口满了怎么办
- 三卡：截断最早对话 · 摘要压缩再喂 · RAG 只取相关
- 预告：RAG 下节细讲

**口播**
> 窗口满了，常见三条出路。第一条，截断：丢掉最早的对话，简单，但可能丢掉关键上下文。第二条，摘要压缩：先让模型把历史收成短段，再喂回去——省地方，但摘要本身可能丢细节。第三条，RAG：别整库塞进去，只检索跟当前问题相关的几段——下一节细讲。有同学可能会说：那我买更大窗口的模型不就完了？更大有帮助，但材料垃圾仍是垃圾；桌面再大，堆满废纸一样找不到那张关键的纸。听见了吗？窗口是硬顶，装填是手艺。三条路可以组合：先摘要，再检索，实在不行才截断，嘛。

文稿：`video/scripts/narration/05-window-full.txt`

## 06 · hallucination

**PPT（屏幕）**
- 眉题：06 HALLUCINATION · 幻觉
- 最像真的 ≠ 核实过
- 会编 DOI · 错字段 · 假数据
- 铁律：可溯源 + 验收

**口播**
> 第三个，幻觉。上一节成语接龙还在：这儿钉死定义——模型给的是「最像真的」答案，不是「核实过的」答案。你问一篇根本不存在的论文，它也能编个像模像样的 DOI、作者、年份；你问公司内部从没喂过它的字段名，它也可能一本正经写错。这不是偶发 bug，是机制：训练目标是接龙顺、像人话，不是去档案室核对。所以啊，FDE 铁律只有一句：关键事实得可溯源——RAG 或数据库喂真材料，输出还得你按标准验收。有同学可能会说：那我每次都人工看，累不累？关键路径累一点是应该的；盲信模型，在驾驶舱里就是事故。听见了吗？通顺的假话，比明显的报错更危险——因为它看起来像对的。下一页把三个词收成一张能力边界表，嘛。

## 07 · boundary

**PPT（屏幕）**
- 眉题：07 BOUNDARY · 擅长与不擅长
- 擅长：生成 · 归纳 · 结构化输出
- 不擅长：实时 · 精确大数 · 未训私有事实
- 第五天摘要：必须对照 Rubric

**口播**
> 把三个词落到能力边界。擅长啥？模式匹配、语言生成、结构化输出——摘要、改写、问答、按格式吐 JSON，这些又快又稳。不擅长啥？实时股价、没工具辅助的精确大数、你们公司从没出现在训练或检索里的私有事实——硬让它「凭记忆」答，就容易翻车。回想第五天摘要接口：写得通顺不等于过关，你得对照 Rubric——字段在不在、有没有编人名。有同学可能会问：边界表要背吗？不用。记住判断句：它是在「续写像真的话」，还是在「查得到的事实」？前者要验收，后者要工具或数据库。边界不是贬低模型，是帮你选对工具：该算的用计算器，该查的用数据库，对吧。
