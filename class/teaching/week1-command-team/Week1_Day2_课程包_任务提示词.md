## D2-L1 · 从原型到代码：前端工程结构

**使用方式**：Trae 对话中 **@前端工程师**。

**学员指令**：

```text
@前端工程师 请阅读 docs/PRD.md 和 design/prototypes/ 里的原型，为这个项目搭建前端工程骨架并运行起来。页面先放空壳占位，我确认结构后再逐页实现。
```

**教学要点（视频讲解）**：为什么要先搭骨架再填页面——目录结构就是工程的地图；组件拆分思维（页面 = 布局 + 组件）。技术栈课程统一为 **Next.js + Tailwind**（与平台同栈，智能体提示词默认一致）。

**平台自检清单**：
- [ ] 项目能启动，浏览器能打开
- [ ] 我能说出 `components/` 和 `app/`（或 `pages/`）各放什么
- [ ] 四个页面的空壳路由都能访问（提交 / 列表 / 详情 / 驾驶舱看板）
- [ ] README 更新了运行方法

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| 启动报错（依赖没装） | "启动报错提示缺少依赖，请告诉我该怎么处理，先解释原因。" |
| 没有用课程指定技术栈 | "请使用 Next.js + Tailwind 搭建，和团队规范保持一致。" |
| 一口气把页面全写了 | "先停下来——今天按页面逐个实现，请先回到骨架状态，只做空壳路由。" |

## D2-L2 · 提交页：表单与校验

**使用方式**：Trae 对话中 **@前端工程师**。

**学员指令**：

```text
@前端工程师 按 design/prototypes/ 的提交页原型实现真实的提交页面：表单字段、必填规则和字数限制以 docs/PRD.md 的字段清单为准，校验失败时用业务语言给出中文提示。
```

**教学要点**：错误提示是产品语言不是技术语言——"金额必须大于 0" vs "Error: invalid input"。

**平台自检清单**：
- [ ] 页面字段和 PRD 字段清单完全一致（对照领域基线）
- [ ] 留空必填项点提交，看到中文友好提示
- [ ] 数字/日期/字数限制都生效（按选题：金额>0 或 详情≥20字）
- [ ] 提示语不是技术黑话

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| 字段和 PRD 不符 | "表单字段和 docs/PRD.md 字段清单不一致，请逐个核对，以 PRD 为准。" |
| 提示是英文/技术语 | "错误提示要给普通员工看，请改成业务语言，例如'费用事由不能为空'。" |
| 校验可以绕过 | "我把金额填成 -100 也提交成功了，请补上校验规则。" |

## D2-L3 · 列表页与 Mock 数据

**使用方式**：Trae 对话中 **@前端工程师**。

**学员指令**：

```text
@前端工程师 实现列表页：先接 mock 数据（至少 5 条，符合 PRD 的字段和状态枚举），含空态；并让提交页新提交的记录能出现在列表里。
```

**教学要点**：后端还没好，前端怎么干活？mock 是按约定造假数据，不是瞎编——字段、枚举必须和 PRD 一致，否则 D3 换真接口时全是坑。

**平台自检清单**：
- [ ] 列表正确渲染 mock 数据（字段、状态枚举与 PRD 一致）
- [ ] 能看到空态（清空数据时有提示）
- [ ] 我在提交页提交一条，列表里立刻出现
- [ ] 三条页面之间能互相跳转

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| mock 数据字段乱编 | "mock 数据的字段和状态枚举必须和 docs/PRD.md 一致，请逐字段核对。" |
| 提交后列表不更新 | "提交页提交成功后，列表页应该能看到新记录，请打通这个联动。" |
| 没有空态 | "把 mock 清空后页面是白屏，请按原型补上空态提示。" |

## D2-L4 · 详情页 + 前后端的合同：接口契约

**使用方式**：Trae 对话中先 **@前端工程师**，再 **@后端工程师**（两段指令）。

**学员指令①（详情页）**：

```text
@前端工程师 实现详情页：展示单据完整信息 + AI 分析区块。标题固定为“AI 分析区｜Week2 接入”，可以保留采纳/忽略按钮位；如展示分析样例，必须醒目标注“演示数据”，本周不接真实 AI 逻辑。
```

**学员指令②（接口契约）**：

```text
@后端工程师 我和前端工程师要为明天做准备。请阅读 docs/PRD.md 和当前前端代码，和我三方对齐接口契约：提交、列表、详情、看板统计四个 Week1 真实接口，以及一个 Week2 预留 AI 分析接口，输出到 docs/D2-L4_接口契约.md。每个接口含方法、路径、请求字段、响应结构、错误响应和版本号 v0.1；预留 AI 接口本周返回 AI_NOT_CONNECTED，不得伪造分析结果。
```

**教学要点**：接口是前端和后端的合同，也是 Week1 向 Week2 的交接资产。今天先约好 AI 能力未来怎么接，但不把演示数据说成 AI 输出。

**平台自检清单**：
- [ ] 详情页字段与 PRD 一致
- [ ] AI 区块有“Week2 接入”说明，样例标“演示数据”
- [ ] 契约 5 个接口齐全（含看板统计），含错误响应约定
- [ ] 我通读契约，至少问了智能体一个问题（如"列表分页怎么办"）

**纠偏指令库**：

| 问题 | 指令示例 |
|---|---|
| AI 区块边界不清 | "本周尚未接入 AI，请把标题改成'AI 分析区｜Week2 接入'；样例加'演示数据'标识。" |
| 契约缺错误响应 | "契约里只有成功的情况，请补上参数错误、记录不存在等错误响应约定。" |
| 前后端字段对不上 | "前端表单字段和契约请求字段不一致，请以 PRD 为准统一。" |

## D2-L5 · 今日冲刺：驾驶舱看板 + 前端 V0.5 走查

**使用方式**：Trae 对话中 **@前端工程师** + 通用对话（Git）。

**学员指令①（驾驶舱看板页）**：

```text
@前端工程师 实现驾驶舱看板页：按 docs/PRD.md 和 design/prototypes/ 的原型，用 mock 统计数据渲染看板——顶部统计卡片 + 类别分布图表（用轻量方式实现，不引入重型图表库）。看板指标以 docs/PRD.md 为准，mock 数据的结构必须与 docs/D2-L4_接口契约.md 的看板统计接口响应一致，方便明天一键切换真接口。
```

**教学要点**：驾驶舱是管理者的一屏全局——老板打开系统第一眼看到的是看板，不是表单。看板的每个数字都必须能"钻"到列表里的真实记录，所以 mock 结构服从契约，不是随手编几个好看的数。

**学员指令②（走查）**：本步不给标准指令——**学员自己按走查清单检查，把发现的问题写成修复单**：

```text
@前端工程师 走查发现以下问题，请逐项修复：
1. 【页面】问题描述 → 改成什么样
2. 【页面】问题描述 → 改成什么样
（至少 2 条，每条都要写清"哪里不对、改成什么样"）
```

**学员指令③（提交）**：

```text
请帮我提交今天的代码，提交信息写 "day2: 前端三页面 V0.5 + 接口契约"，并更新 README 的当前进度。
```

**走查清单（平台展示）**：三态（空/加载/失败）、四页面互跳（含看板）、字段与 PRD 一致、错误提示为业务语言、AI 区显示“Week2 接入”且样例标“演示数据”、看板指标与领域基线一致、控制台无报错。

**平台自检清单**：
- [ ] 看板页渲染出统计卡片与分布图表，指标和我的选题领域匹配
- [ ] 看板 mock 数据结构与契约的统计接口一致
- [ ] 走查清单七项我全部亲自点过
- [ ] 修复单 ≥2 条，每条含"哪里不对、改成什么样"
- [ ] 修复后我重新验证过
- [ ] Git 有当日提交，README 进度已更新
