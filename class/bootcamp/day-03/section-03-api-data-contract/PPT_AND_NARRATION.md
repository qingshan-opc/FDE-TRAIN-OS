## 01 · open

**PPT（屏幕）**
- 先合同，后代码
- API_Spec.md
- DB_Schema.md
- 避免各写一套

**口播**
> 同学们好，我是你们的老师四零四。后端方案已经确认。现在仍然不急着生成服务。我们先定接口合同和数据合同。接口合同规定前后端怎样对话。数据合同规定每条记录怎样保存。两份合同先一致，后面才不会各写一套字段。

文稿：`video/scripts/narration/01-open.txt`

---

## 02 · api-six

**PPT（屏幕）**
- 接口六要素
- 方法 · 路径 · 用途
- 请求
- 成功
- 错误

**口播**
> 一个完整接口要写清六件事。它们是请求方法和路径。还要写用途和请求内容。成功结果必须有状态码和返回示例。错误结果也要写触发场景。只写一个地址并不够。前端要知道传什么。失败后的提示也要明确。

文稿：`video/scripts/narration/02-api-six.txt`

---

## 03 · menu

**PPT（屏幕）**
- P1 · 先列接口菜单
- 只要 3—5 行
- 对应页面操作
- 确认后再展开

**口播**
> 第一段只让后端列接口菜单。每行写方法和路径。再写一句用途和对应的页面操作。接口数量控制在三个到五个。这里先不展开参数和响应。你要检查查询和提交有没有遗漏。确认后再回复确认接口清单。

文稿：`video/scripts/narration/03-menu.txt`

---

## 04 · api-doc

**PPT（屏幕）**
- P2 · 生成 API 合同
- 每个接口写全
- 真实 JSON 示例
- 错误必须可触发

**口播**
> 第二段才生成接口合同。每个接口都要写全六个要素。成功响应要给出数据示例。错误响应要说明触发条件。这里要注意，错误不能全部写成五百。输入不合格通常返回四百。目标不存在通常返回四零四。

文稿：`video/scripts/narration/04-api-doc.txt`

---

## 05 · db

**PPT（屏幕）**
- P3 · 最小数据合同
- 2—3 张表
- 字段与类型
- 每张表有主键

**口播**
> 第三段生成数据合同。第一版只设计两张到三张表。每张表写明字段和类型。还要写明主键和必填规则。必要的数据关系也要说清。主键像每条记录的唯一身份证。没有主键，就很难准确查找和修改某条数据。

文稿：`video/scripts/narration/05-db.txt`

---

## 06 · map

**PPT（屏幕）**
- P4 · 三方对账
- 页面操作
- 接口
- 表名.字段名
- 只列问题

**口播**
> 第四段只对账，不做修改。后端要列出每个接口读取或写入的表字段。再把接口对应到页面操作。字段没有来源就标为不通过。表字段无人使用也标为不通过。相同含义出现不同名称，也要先列出来等你确认。

文稿：`video/scripts/narration/06-map.txt`

---

## 07 · regenerate

**PPT（屏幕）**
- P5 · 完整重生成
- 不留半份旧合同
- 页面 → API → 数据表
- 一个最新版

**口播**
> 你确认修正方向后，再发送第五段。要求后端完整重生成两份合同。不要只提供几行补丁。最后输出页面操作到接口的链路。再从接口追到数据表。两份合同必须保留一个清晰的最新版，避免后续岗位拿错文件。

文稿：`video/scripts/narration/07-regenerate.txt`

---

## 08 · example

**PPT（屏幕）**
- 例：提交记录
- POST /api/records
- 201 创建成功
- records.id 与内容字段

**口播**
> 比如页面点击提交。它对应一个创建记录的接口。请求内容必须包含合同规定的字段。创建成功会返回二零一和新记录编号。缺少必填内容会返回四百。后端再把记录写入数据表。这样就形成一条完整链路。整条链路都可以检查。

文稿：`video/scripts/narration/08-example.txt`

## 09 · close

**PPT（屏幕）**
- 合同是共同语言
- 字段可追溯
- 错误可预期
- 下一节生成服务

**口播**
> 这一节最重要的不是记住多少术语。你要养成先定共同语言的习惯。每个页面动作都有对应接口。每个接口字段都有明确来源。每种错误也有确定结果。合同通过后，我们下一节才生成本地后端。同学们，本节先到这里。
