## 02 · history

**PPT（屏幕）**
- 眉题：02 HISTORY · 大模型从哪来
- 文献语料 → 神经网络 → Transformer → ChatGPT
- 课上讲来历 · 预训练/LoRA 可课后问 AI

**口播**
> 前五天呢，咱们其实一直在用 AI，也在做传统软件——PRD、接口、业务系统，都摸过。但「大模型」这三个字，很多人还停在「很神奇」。咱们先把来历捋顺。人类历史上攒了海量文献资料，那是后来训练的原材料。上世纪九十年代，人们搞出神经网络，人工智能从此热一阵、冷一阵。直到二零一五年，谷歌提出 Transformer 架构，局面才真正拧过来。刚开始呢，它也没有一下子改变全世界；真正把普通人叫醒的，是二零二三年前后 ChatGPT 这类产品爆出来。来，我复述一下：不是忽然天上掉下智能，是「语料 + 架构 + 算力」叠到一个临界点。有同学想钻预训练、LoRA，可以课后去问 AI 深挖；课上咱们只钉一件事——它是怎么来的，还有它跟以前那些「模型」到底差在哪，嘛。

## 03 · small-model

**PPT（屏幕）**

- 红外测温 + 摄像头人脸 = 传感器 + 专用小模型
- 语音 · OCR · 图像识别 · 视频理解

**口播**
> 在大模型普及之前，人工智能其实早就有了，只是形态不一样。同学们想一下疫情期间：有些地铁口，红外线先扫体温，摄像头再认人脸——那时候 ChatGPT 还没刷屏呢。本质是什么？接了一个物理传感器，扫出温度；再通过摄像头做人脸检测、识别。它很厉害，但干的是一件写死的事。语音识别、OCR 认字、图像分类、视频理解——以前老板嘴里说的「上了个模型」，多半是这类。有同学可能会说：那不也是 AI 吗？对，说得真好，它就是 AI，但咱们今天要叫它「小模型」或者「专用模型」——输入输出边界清楚，任务单一，不像聊天那样啥都能接。听见了吗？先记住这一层对比，下一页咱们再看大模型「大」在哪，对吧。

## 04 · generalization

**PPT（屏幕）**
- 眉题：04 GENERALIZATION · 泛化
- 早期：小语料 · 有点本事但不泛化
- 临界：海量文本 · 千亿参数 · 很多显卡
- 泛化＝没见过的题也能接一下

**口播**
> 那 LLM 大模型跟这些小模型，区别到底是什么？同学们先别背定义，听我说人话：它足够大。早期大家用很小一块语料去训文本模型，也能写出几句像样的话，但还没真正长出一种能力，叫「泛化」。泛化是什么？就是训练时没见过一模一样的题，它也能顺着给你接一下、答一下。二零二三年前后的实验把这件事钉死了：在海量文本加持下，参数往往到几千亿这个量级，还得很多张显卡才能训出来；训完之后，它有那么一点泛化。有同学可能会说：那不就是更聪明吗？不完全是——更准确的说法是：它学会了「在语言空间里往下接」，所以显得啥都会。来，对照屏幕：小模型＝干一件事；大模型＝够大之后，开始「啥题都敢接」。这一步听懂了，幻觉才听得懂，嘛。

## 05 · idiom-chain

**PPT（屏幕）**
- 眉题：05 成语接龙 · 核心机制
- 你说一段 → 向量里检索 → 接下一个最像的
- 流畅 ≠ 核实过 · 幻觉同源
- 认字快的实习生，不是事实库

**口播**
> 泛化落到日常体验上，就是：你丢给它几乎任何问题，它都能给你「编」一段。这也是大模型幻觉的核心逻辑——不是它故意骗人，是它的工作方式就是这样。不知道有没有同学玩过成语接龙？大模型跟成语接龙非常像：你说一段话，它在自己的向量空间里检索，琢磨「接下来哪个词最像、最顺」，然后一个一个接给你。接得漂亮，不等于它去档案室核对过。所以啊，同学们钉死一句：LLM 是认字特别快的实习生，不是查过档的事实库；具体干活的结果，还得人负责验收。有同学可能会问：那我还用它干啥？用啊——用它快、用它会写、用它会归纳；但关键数字、关键承诺、关键对外发出去的话，得你来判。听见了吗？机制听懂了，后面的 Token、窗口、幻觉细拆才站得住，对吧。

## 07 · orchestration

**PPT（屏幕）**
- 眉题：07 YOU ARE HERE · 应用 + 编排
- 应用：用户看得见的产品
- 编排：控制模型怎么干活的软件适配
- 提示词 · RAG · MCP · Harness…

**口播**
> 那问题来了：你在哪一层？同学们记好——咱们这门课，主要围着最上面两层转：应用，和编排。应用好理解：产品长什么样、用户点哪里、验收过不过。编排呢？有同学一听就懵。我用人话说：编排就是「控制大模型去做事情」的那一层——你得给大模型做一套完整的软件适配，让它别自由发挥。包括提示词怎么写、RAG 怎么外挂资料、MCP 怎么接工具、Harness 怎么管循环和重试，还有一堆新冒出来的概念，其实不止这些。听见了吗？模型再强，没有编排，它就是个能聊天的黑盒；有了编排，它才变成你业务里可调度的同事。第二周往后你们动手的地方，全在应用加编排这两层——模型层、基建层知道名字和权衡就行，不要求你们自己去训千亿模型，对吧。

## 08 · access

**PPT（屏幕）**
- 眉题：08 ACCESS · 怎么接到模型
- 主路：云端 HTTP API · 按量付费
- 自部署：显卡与运维 · 往往更贵更难
- 建议：DeepSeek 等开源模型的云 API

**口播**
> 再往下一层，讲怎么「接到」大模型。同学们日常用的 ChatGPT、国内助手，背后都是你发一句话、它回一句话——开发者侧呢，主路是调云端 API：你的程序发 HTTP 请求，把提示词和参数送过去，把生成结果接回来。自己部署也行，把权重下到自己机器上跑，但显卡、电费、运维都得扛。国内开源模型的云 API 现在很便宜，咱们课里建议优先走这条——比如 DeepSeek。有同学可能会纠结开源还是闭源：先问两件事——数据能不能出公司门？你有没有人养集群？训练营场景，调云 API 就够了。听见了吗？先钉「走 API」，下一页钉「怎么收流」，嘛。

## 09 · sse

**PPT（屏幕）**
- 眉题：09 SSE · 一次性响应 vs 流式
- 一次性：等整包 JSON 再渲染
- SSE：text/event-stream · 边收边显示
- 助手位建议 SSE · Key 不进前端

**口播**
> 很多同学会问：API 和 SSE 啥关系？别对立——SSE 不是另一家供应商，是 API 的一种返回方式。一次性响应：你发出去，干等，整包 JSON 回来再渲染——像寄信，等回信全文。SSE，Server-Sent Events：服务端按 Token 一段段推，浏览器边收边显示——像打电话，对方一句句说。ChatGPT 那种「字一个个蹦出来」，多半就是流式加 SSE。应用里的助手位、对话面板、摘要预览，本课建议 SSE：体感快、能显示生成中、断了能重试。WebSocket 是双向长连，聊天流多数用不上，先别绕。有同学可能会说：那我把 Key 写进网页？绝不——密钥放后端或环境变量。来，对照屏幕：API 负责「打到哪」；SSE 负责「怎么流回来」。本节练习会丢给你教学包 prompts/02：整份粘贴到 Cursor 等编程 AI，在你自己的仓库里接入 DeepSeek，优先 SSE——让它帮你改到跑通，对吧。

- 多模态：图 · 声 · 画图 · 视频

**口播**
> 最后再点一个词：多模态。传统最多是文本模型——你打字进去，它打字出来。多模态还能理解图、声音，甚至画图、做视频。有同学可能会说：那我把截图丢给助手位行不行？本课边界先钉死：应用内对话先只用文本能力——摘要、问答、多轮聊；并且文本链路优先用 SSE 跑通。不是多模态不重要，是你得先把「接电 + 流式 + 验收」跑熟。听见了吗？边界清晰，比功能堆满更像 FDE，对吧。
