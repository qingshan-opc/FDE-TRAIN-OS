# 第 3 节 · 概念：云原生最小概念——容器与镜像（15′ · 概念）

> 🎬 视频位（现阶段：口播稿）
> 「在我机器上是好的」——这句名言是怎么被消灭的？这是云原生给你上的第一课。

## 教学目标

- 一句话说清镜像与容器：镜像是冻好的包裹，容器是跑起来的包裹；
- 理解容器解决的核心问题：环境一致性——「在我机器上能跑」从此消失；
- 知道「云原生」这个词在说什么：应用生来就为云设计（打包成镜像、配置走环境、无状态）。

### 「在我机器上能跑」的三个病根

| 病根 | 容器怎么治 |
|------|-----------|
| 操作系统不同（Mac/Windows/Linux） | 镜像里自带一个标准 Linux 环境 |
| 依赖版本不同（你装 2.0 他装 1.0） | 镜像构建时锁定依赖，冻在一起 |
| 配置不同 | 第 2 节已治：环境变量注入 |

### 镜像与容器（一个比喻管终身）

```
镜像（Image）= 冻好的饺子：统一规格，哪里都能煮
容器（Container）= 下锅煮着的饺子：跑起来的实例，可以煮好几锅
```

- **Dockerfile** = 冻饺子的配方：「基于什么底、装什么料、怎么启动」——托管平台今天帮你自动生成，知道存在即可；
- 云平台做的事：拿到你的镜像 → 在它们的机器上「煮」成容器 → 分配 URL。

### 云原生三特征（你的项目对照）

| 特征 | 你的项目 |
|------|---------|
| 打包成镜像 | ✅ 平台构建时自动完成 |
| 配置走环境变量 | ✅ 第 2 节刚做完 |
| 无状态（状态在外部） | ⚠️ SQLite 文件在容器里——教学期可接受，知道这是「有状态」即可 |

## 🎬 口播稿（约 1.5 分钟）

> 「『在我机器上是好的』——程序员名言。病根三个：系统不同、依赖版本不同、配置不同。
> 容器的治法釜底抽薪：把你的应用连同一个标准 Linux 环境、锁定版本的依赖，一起冻成一个包裹——这叫镜像。云上的机器拿到镜像，煮开了跑——那叫容器。你的电脑和云跑的是同一个包裹，『在我机器上能跑』从此消失。
> 配置昨天已经分家，环境变量注入。加上打包成镜像、状态外置，这三条就叫『云原生』——应用生来为云设计。
> 注意第三条你的项目其实不满足：SQLite 文件在容器里，是有状态的。教学期没问题，但你要知道这个『⚠』在哪——Day 4 的换库三信号，将来就在这里响。」

## 常见懵点

- 「容器和虚拟机什么区别？」→ 虚拟机连操作系统整套模拟（重）；容器共享宿主机内核只打包应用环境（轻，秒级启动）；
- 「我要学 Docker 命令吗？」→ 本课不用：托管平台代劳；想深入看公开课 O3；
- 「镜像和 Git 仓库重复吗？」→ 不重复：仓库存源码（会变），镜像存「某一版本代码+环境」的冻品（不变）——部署到任何地方都一致。
