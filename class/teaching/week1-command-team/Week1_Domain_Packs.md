# Week 1 项目选题制 · 首期 3 个选题《领域包规格》

> 关联文档：`docs/Week1_Course_Outline.md` §0.1（选题机制）、§5（配套生产清单）。
>
> **本文件用途**：内容团队的直接生产输入。每个选题（领域皮肤）包含三件可执行资产：① 基线字段清单（D2 教学锚点 + 跨天验收基准）；② D1-L1 信心时刻 Prompt（全周最重要的一段 Prompt）；③ 领域化任务上下文变量表（全周 25 份 Prompt 的统一替换变量）。
>
> **通用约定**：
> - 工程骨架统一：**驾驶舱看板** + 表单提交 → 列表 → 详情 → AI 分析/建议 → 数据库（SQLite 起步，验收不要求真实部署）。看板为系统首页：顶部统计卡片 + 类别分布图表，指标取自各领域包的 `{看板指标}`。
> - 验收规则领域无关：结构类校验引用本文档变量；语义类仅用于个人解释题。
> - 变量书写约定：`{核心对象}` `{对象字段列表}` 等占位符在 Prompt 模板中出现时，按对应选题的变量表替换。

## 领域包 A：公司财务费用管理系统

**适合学员**：财务、会计、审计专业大学生；财务/行政岗位在职人员。
**一句话场景**：员工提交费用报销单，财务负责人查看处理状态，AI 分析费用异常并给出合规建议。
**真实业务参照**：Enterprise AI OS 财务看板（收入/支出/应收/逾期回款/异常费用识别、费用超历史均值 130% 预警规则）。

### A-1 基线字段清单（费用报销单）

| 字段 | 类型 | 必填 | 说明 | 数据责任 |
|---|---|---|---|---|
| expense_id | 字符串（主键，自动生成） | 系统 | 报销单号，规则 FIN-YYYYMMDD-序号 | 系统 |
| title | 字符串 | 是 | 费用事由（≤50 字） | 提交人 |
| category | 枚举 | 是 | 差旅 / 办公采购 / 业务招待 / 培训 / 其他 | 提交人 |
| amount | 数值（元，两位小数） | 是 | 报销金额，>0 | 提交人 |
| occurred_at | 日期 | 是 | 费用发生日期，不得晚于提交日 | 提交人 |
| submitter | 字符串 | 是 | 提交人姓名/工号 | 提交人 |
| department | 字符串 | 是 | 所属部门 | 提交人 |
| description | 文本 | 否 | 费用明细说明 | 提交人 |
| status | 枚举 | 系统 | 待审核 / 已通过 / 已驳回 | 财务负责人 |
| ai_analysis | 文本 | 系统 | Week2 接入后的异常分析与合规建议；Week1 仅预留 | Week1 演示数据 / Week2 AI |
| created_at / updated_at | 时间戳 | 系统 | 创建与更新时间 | 系统 |

**数据质量风险示例（D2-L4 教学用）**：报销金额与发票金额不一致；类别乱选（把招待费报成办公采购）；月末集中提交导致统计失真。

### A-2 D1-L1 信心时刻 Prompt（财务版）

```text
你正在协助一位零代码基础的学员完成 FDE 训练 Day 1 的第一课。

请用当前项目技术栈创建一个可直接运行的网页：「公司财务费用管理 - 费用报销提交页」。

功能要求（只做这一个页面，不做后端、不接数据库）：
1. 页面顶部有产品名称「公司财务费用管理系统」和一句副标题「让每一笔费用都清楚可查」。
2. 一个报销提交表单，包含字段：费用事由（文本）、费用类别（下拉：差旅/办公采购/业务招待/培训/其他）、报销金额（数字）、费用发生日期（日期）、提交人（文本）、所属部门（文本）、费用明细说明（多行文本，可选）。
3. 表单校验：费用事由、类别、金额、日期、提交人为必填；金额必须大于 0；日期不得晚于今天。校验不通过时在字段下方用中文给出友好提示。
4. 提交成功后：在页面下方「我的报销单」列表中新增一条记录，显示事由、类别、金额、日期、状态（默认"待审核"）。数据保存在浏览器内存即可，刷新可丢失。
5. 列表为空时显示空态提示「还没有报销单，提交第一笔吧」。
6. 视觉要求：简洁专业的后台系统风格，主色使用青绿色系，圆角卡片布局，移动端基本可读。

完成后请启动本地服务并告诉我访问地址。不要创建除本页面以外的其他页面。
```

## 领域包 B：HR 招聘与员工诉求管理系统

**适合学员**：人力资源、行政管理、心理学专业大学生；HR/行政岗位在职人员。
**一句话场景**：员工提交诉求（请假异议、福利建议、职场问题），HR 负责人查看处理状态，AI 对诉求分类并给出处理建议。
**真实业务参照**：Enterprise AI OS 组织与人事实践（部门负责人看板、任务延期与负载预警）；FDE 白皮书"一线用户是否被监控、是否影响岗位"的采用风险视角。

| ai_analysis | 文本 | 系统 | Week2 接入后的分类校验与处理建议；Week1 仅预留 | Week1 演示数据 / Week2 AI |

**数据质量风险示例（D2-L4 教学用）**：诉求描述情绪化、事实不清；类别与内容不匹配；同一问题多人重复提交。**伦理提示（写进课件）**：员工诉求属敏感数据（对应白皮书数据分级 L3），教学全程使用虚构数据，AI 分析不得用于惩罚性用途。

## 领域包 C：经营问题闭环系统（默认）

**适合学员**：专业不限、跨专业学生；非财务/HR 岗位或暂不确定方向的学员。
**一句话场景**：员工提交经营问题（回款异常、客户流失迹象、项目延期），负责人查看处理状态，驾驶舱展示问题分布；Week2 再由 AI 生成原因分析与行动建议。
**真实业务参照**：Enterprise AI OS 风险预警中心（回款逾期 / 项目延期 / 客户未跟进 / 费用异常 / 数据缺失五类规则）与 AI 决策助手（"结论→数据依据→问题→风险→建议→关注对象"固定结构）。

### C-1 基线字段清单（经营问题单）

| 字段 | 类型 | 必填 | 说明 | 数据责任 |
|---|---|---|---|---|
| issue_id | 字符串（主键，自动生成） | 系统 | 问题单号，规则 BIZ-YYYYMMDD-序号 | 系统 |
| title | 字符串 | 是 | 问题标题（≤50 字） | 提交人 |
| category | 枚举 | 是 | 客户与市场 / 销售与回款 / 项目与交付 / 成本与费用 / 团队协作 / 其他 | 提交人 |
| impact | 枚举 | 是 | 影响程度：高 / 中 / 低 | 提交人 |
| submitter | 字符串 | 是 | 提交人姓名 | 提交人 |
| department | 字符串 | 是 | 所属部门 | 提交人 |
| description | 文本 | 是 | 问题描述（现状、影响、发生频率，≥20 字） | 提交人 |
| related_target | 字符串 | 否 | 关联客户/项目/订单名称 | 提交人 |
| status | 枚举 | 系统 | 待处理 / 处理中 / 已解决 / 已关闭 | 负责人 |
| ai_analysis | 文本 | 系统 | Week2 接入后的原因分析与行动建议；Week1 仅预留 | Week1 演示数据 / Week2 AI |
| created_at / updated_at | 时间戳 | 系统 | 创建与更新时间 | 系统 |

**数据质量风险示例（D2-L4 教学用）**：问题描述只有情绪没有事实；影响程度凭感觉填；同一问题换说法重复提交。
