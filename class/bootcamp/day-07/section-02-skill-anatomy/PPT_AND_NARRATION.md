## 01 · open

**PPT（屏幕）**
- 眉题：01 OPEN · 解剖一只 Skill
- 讲解图：skill-anatomy.svg
- 输入 · 步骤 · 输出 · 验收
- 缺一个都转不动

**口播**
> 同学们好，我是你们的老师404。这节咱们解剖一只 Skill。一份能被 AI 执行的说明书长什么样？四个部件：输入、步骤、输出、验收。缺一个都转不动——输入没写清楚，AI 不知道吃什么料；步骤没写清楚，它不知道先干啥后干啥；输出没写清楚，你不知道该收什么货；验收没写清楚，你不知道货好不好。有同学可能会说：我写 Prompt 时也写过要求啊？对，但 Prompt 往往缺步骤和可判验收，写完就散。今天咱们把四部件钉死，后面写、选、跑都围着它转。来，先看屏幕解剖图，对吧。

## 02 · four-parts-map

**PPT（屏幕）**
- 眉题：02 FOUR PARTS · 四部件地图
- 讲解图：skill-anatomy.svg
- 输入 → 步骤 → 输出
- 验收 · 横切全流程

**口播**
> 来，看屏幕这张解剖图。输入是入口：做这件事吃什么料。步骤是流水线：从料到货怎么一步步走。输出是交付物：交什么格式、多长、什么红线。验收是尺子：好坏怎么判，每条能不能打 ✓ 或 ✗。打个比方：输入像备菜清单，步骤像后厨工序，输出像摆盘标准，验收像质检表——四张纸缺一张，厨房就乱。有同学问：验收放最后写行不行？可以，但脑子里得先有这把尺子；没有尺子，步骤容易写飞。听见了吗？四部件不是四个标题，是四道硬约束，缺一道后面全得返工，嘛。

## 03 · input

**PPT（屏幕）**
- 眉题：03 INPUT · 输入要具体
- 数据来源 · 周期 · 读者
- 禁用 · 相关数据
- 概念卡 · 来源 + 范围

**口播**
> 先讲输入。输入管做这件事吃什么料，要具体到来源和范围。比如周报 Skill：驾驶舱 /api/kpi 和 /api/exceptions，近七天，读者是部门总监——这三行，AI 和人都能对上号。不能写「相关数据」——哪相关呢？有同学可能会说：我手头就是一堆文件。行，那就写清路径、文件名、时间范围。输入写得虚，后面步骤再漂亮也是盲做。判据就一句：换一个同事只看输入段，能不能准确去拉同一批料？不能，就回去改输入。输入是 Skill 的「原材料标签」，对吧。

文稿：`video/scripts/narration/03-input.txt`

## 04 · steps

**PPT（屏幕）**
- 眉题：04 STEPS · 步骤要可执行
- 拉取 · 找出 · 对比 · 生成
- 禁用 · 分析一下
- 细到不换理解

**口播**
> 步骤管怎么做，必须细到 AI 能一步步执行。还是周报例子：拉取本周 KPI 与异常清单；找出环比变化最大的两个指标；找出逾期最久的三张工单；按输出格式生成周报——四条，每条都是动作，不是愿望。不能写「分析一下」——怎么分析嘛？有同学问：步骤要写多细？细到换一个人或 AI 照着做，不会做出第二种理解。写不到这个程度，先别急着填输出，回去拆步骤。就像第五天教结构化输出：先定工序，再谈成品。步骤里的模糊词，是后面验收不过的头号元凶，呢。

文稿：`video/scripts/narration/04-steps.txt`

## 05 · output

**PPT（屏幕）**
- 眉题：05 OUTPUT · 输出要有格式
- Markdown 四段 · ≤300 字
- 数字 · 只用来源里真实的
- 禁用 · 写个周报

**口播**
> 输出管交出什么货。继续周报 Skill：格式 Markdown 四段——头条、数据、风险、建议；长度三百字以内；数字只用数据来源里真实存在的，不许编。不能写「写个周报」——什么样的周报？四段还是一段？谁看？多长？有同学可能会说：示例算不算输出的一部分？算，输出段贴一个好示例，是最划算的消歧方式——第五天 few-shot 手法直接搬过来。输出定死了，验收才有靶子；步骤才知道最后一步「生成」长什么样。听见了吗？输出不是「大概差不多」，是「交卷格式」，对吧。

文稿：`video/scripts/narration/05-output.txt`

## 06 · accept

**PPT（屏幕）**
- 眉题：06 ACCEPT · 验收要可判
- 结构 · 四段齐全
- 数字 · 能溯源
- 建议 · 主语是人且可执行

**口播**
> 验收管好坏怎么判。周报 Skill 三条：结构——四段齐全；数字——每个数字能在来源中找到出处；建议——主语是人、可执行，不能是「系统应优化」。每条都能判 ✓ 还是 ✗，不能写「写得好」——谁判？怎么判？有同学问：验收谁来做？三层：AI 自检、你抽检、同事或导师复核——但标准得写在你的说明书里，不能只在脑子里。验收是 Skill 和普通 Prompt 的分水岭：有验收，才叫可交付；没验收，只能靠感觉。这一步听懂了，后面运行节才知道逐条打勾，嘛。

文稿：`video/scripts/narration/06-accept.txt`

## 08 · defects-day5

**PPT（屏幕）**
- 眉题：08 DEFECTS · 模糊词与回扣
- 相关数据 · 分析一下 · 写个周报 · 写得好
- 输出+验收 = 第五天结构化输出
- 三条军规 · 各自有格子

**口播**
> 常见缺陷记四个词：相关数据、分析一下、写个周报、写得好——屏幕上出现这些词，说明书就还没写完。它们像四个报警器，一响就说明某部件缺硬约束。修法也简单：相关数据改具体来源；分析一下改成拉取、找出、对比；写个周报改成格式加长度；写得好改成可判条目。眼熟吗？输出加验收，就是你们第五天学的结构化输出加三条军规——格式、数字、意图，在 Skill 里各归各位。第一周的每个概念，在第二周说明书里都有自己的格子。有同学可能会说：原来不是新概念，是新容器。对，容器换了，标准更严了——因为执行者从人换成了 AI，嘛。

文稿：`video/scripts/narration/08-defects-day5.txt`
