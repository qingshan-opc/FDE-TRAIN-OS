**口播**
> 同学们好，我是你们的老师404。先问一句：Human-in-the-loop，昨晚查过的同学，用你自己的话答——关键步骤要人点头，AI 不能自己拍板。想三秒。有同学可能会说：404老师，这和编排有啥关系？关系大了。今天咱们把业务流程翻译成流水线，专业词就叫编排。一件工具顶多算助手，一条串起来的流水线才算团队；你昨晚画的流程草稿，今天要变成能施工的 Skill 串联图。来，看屏幕这张 workflow 对比图：左边一件工具，右边一条串起来的线，差别就在数据会不会流动。咱们就从「怎么拆步骤」讲起，一步步来。

## 02 · hitl-anchor

**PPT（屏幕）**
- 眉题：02 HITL · 人该在哪一步
- 讲解图：orchestration-confirm.svg
- 执行给 Skill · 判断给人
- 不可撤回 → 前面装闸

**口播**
> 编排的第一条规矩：AI 干执行，人干判断和放行。有同学一听就懵——是不是每一步都得我盯着？不是。能撤回的步骤，Skill 可以自动连跑；一旦错了收不回来，前面必须留一道人工确认闸。比如发消息、改生产数据、对外通知——这些动作出去就难撤回。听见了吗？编排不是把活全丢给 Agent 现想，而是你先画好：哪几步机器跑，哪几步必须等人点头。来，对照屏幕这张确认闸图，拿你的周报流程想三秒：最该装闸的是哪一格？通常是发送前那一格，别装错位置。这个分界画清楚了，后面装闸才有地方装。现在就把这一格在你的草稿上标出来，别留到施工再返工，对吧。

文稿：`video/scripts/narration/02-hitl-anchor.txt`

## 03 · split-three

**PPT（屏幕）**
- 眉题：03 SPLIT · 拆一步问三问
- 讲解图：orchestration-confirm.svg
- 执行还是判断？
- 输入从哪来？错了能撤吗？

**口播**
> 拆一步，问三个问题。第一，这步是执行还是判断？执行，候选 Skill；判断和放行，归人。第二，输入从哪来？上一步吐什么，下一步就吃什么，数据流得画清楚。第三，这步错了能撤回吗？能撤回就自动连跑；不能撤回，前面必须装确认闸。有同学可能会说：手动步骤能不能混进来？能——「你确认」本身就是一步，写清楚谁干就行。来，对照屏幕三问卡片，拿你昨晚的流程草稿试拆第一步：它是 Skill 还是人？输入从谁那儿来？错了能不能撤？这三句答不上来，这步先别写进图。拆完第一步再拆第二步，别一口气画满整张图，嘛。

文稿：`video/scripts/narration/03-split-three.txt`

## 04 · dataflow-contract

**PPT（屏幕）**
- 眉题：04 DATAFLOW · 产出咬合输入
- 讲解图：workflow-vs-agent.svg
- A 的产出 = B 的输入
- 格式对不齐 · 流水线必卡

**口播**
> 咱们再强调一遍数据流。编排不是堆三件 Skill，是让产出和输入咬合——上一步 JSON 里缺字段，下一步就接不住，流水线一定卡。又是契约思想：A 写清楚输出格式，B 写清楚输入要求，中间别留「一些数据」这种模糊话。有同学可能会问：格式要对齐到多细？至少字段名、类型、必填项要说死；细到文件名、版本号更好。听见了吗？图画得漂亮，不如咬合点钉死。第四节施工，就是照这个咬合点接线。你现在能在纸上标出 A 吐啥、B 吃啥吗？标不出来先别往下走——接口糊了，Agent 再聪明也接不上。来，把 A 的输出、B 的输入各写一行，对齐了再画下一格，对吧。

文稿：`video/scripts/narration/04-dataflow-contract.txt`

## 05 · weekly-pipeline

**PPT（屏幕）**
- 眉题：05 EXAMPLE · 运营周报流水线
- 讲解图：orchestration-confirm.svg
- A 拉数 → B 草稿 → 确认闸 → C 发送
- 发送不可撤回

**口播**
> 看这条周报流水线示例。Skill A 拉本周 KPI 和异常，吐 JSON；Skill B 吃 JSON 生成周报草稿——这两步可以全自动连跑。发送之前呢，一道确认闸：草稿、关键数字、风险标红摆在你面前，你批准才发。为什么？消息发出去了就收不回。Skill C 负责发送，必须等闸通过。有同学可能会说：草稿我信 B 不行吗？信可以，但对外动作不能赌——闸是最后一道工程保险。这个例子后面几节还会反复用，先记成模板：拉数、写稿、人看、再发，四格别乱。来，你画自己的流程，也按这四格套一遍——套不上的地方，就是你今晚要补的格。

文稿：`video/scripts/narration/05-weekly-pipeline.txt`

## 06 · manual-step

**PPT（屏幕）**
- 眉题：06 MANUAL · 人工也是一步
- 讲解图：workflow-vs-agent.svg
- 确认本身占一格
- 谁干 · 看什么 · 批还是驳

**口播**
> 常见懵点：三步都要 Skill 吗？不一定。流水线里允许人工步骤——「你看一眼草稿并批准」就是独立一格，不是省略。画串联图时，确认闸用菱形或停顿符号标出来：谁来看、看什么、批还是驳，写进 orchestration 图纸。有同学可能会说：那 Agent 会不会跳过？不会——只要你按 workflow 写死顺序，并在发送类 Skill 里把「等待确认」钉在第一行。人工步骤写清楚，编排才不是口头约定。听见了吗？「你确认」和 Skill A 一样，都是图上的一个框；框里写清决策信息，别画成虚线。现在检查你的图：闸那格写没写「看什么」？没写就补上，对吧。

## 07 · workflow-designer

**PPT（屏幕）**
- 眉题：07 WORKFLOW · 你设计 · AI 执行
- 讲解图：workflow-vs-agent.svg
- 步骤定死 · 不靠 Agent 现想
- 能 workflow 别 agent

**口播**
> 同学们注意：这是 workflow，步骤你定死，不依赖 Agent 现场瞎想。前面讲过的铁律还记得吗——能 workflow 别 agent。编排的意思就是：你当流程设计师，AI 当流水线工人；图纸画在 orchestration.md，施工按顺序调用。有同学可能会问：编排要不要写代码？今天不用——今天只画图；第四节在你自己仓库里按图调用 Skill，加确认闸就够。不靠别人家的编排产品。自动化引擎是后面公开课的事。听见了吗？先把串联图画出来，第四节能直接施工；别急着让 Agent「自由发挥」，自由发挥是事故温床。本节带走一句：流程画成 Skill 串联图——图纸清了，工人才不会乱。

文稿：`video/scripts/narration/07-workflow-designer.txt`
